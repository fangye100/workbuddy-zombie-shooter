## 🔴 重大发现：MCP parseGlb 会做 XZ 重定心（影响所有绑定测量）
- `dist/domain.mjs parseGlb`：`cx=(minX+maxX)/2, cz=(minZ+maxZ)/2`，归一后 `x'=(x-cx)*s, z'=(z-cz)*s`（y 只压脚底不重定心）。
- H-01 的 baked glb Z 中心 raw=-0.0241 → **MCP 空间比「直接缩放」的测量空间前移 4.77cm**。此前所有 z 都偏后 4.8cm。

- **教训：任何给 MCP 的坐标必须先加 +cz*s；测量脚本必须复刻 parseGlb 的重定心。** 已修（joints_fixed.json）。

## 🔴 导出形变根因：「摆放方向 ≠ 模板标准朝向」→ unpose 把网格整体挪走（已修）
- 症状：首版 `export_glb` 出来 `heightAfter 2.187 ≠ heightBefore 2.05`（probe 门禁 `<1e-3` 不过）、`maxPoseAngleDeg 43.34`、7 根 offAxis；逐顶点位移**中位 9.6cm / max 29.6cm**，脚底沉到 y=−0.145、踝高切片 X 从 ±0.283 塌到 ±0.074。
- 根因（两处，都在 `fitSkeleton` 的语义里）：
  1. **模板 `Hips→UpLeg` 标准朝向是 45° 斜下外 `(±0.707,−0.707,0)`**，而摆放是近水平 `(−0.150,−0.010,+0.040)` → 43.3°。T-pose 重建按标准朝向从 Hips 往下推，于是整条腿比真实低 0.10~0.14m（踝重建到 y=−0.003）。
  2. 模板所有中轴骨/手臂链的 z 分量恒为 0 → 摆放时脊柱 z 从 −0.042 漂到 +0.068、手臂 z 从 0.028 漂到 0.098，反解全被拉回 Hips 的 z → 手尖位移 0.14m。
- **关键判据（省掉大量试错）：落差 `|tpose 重建 − placed|` 只跟「骨的方向」有关，跟骨长无关**（骨长是从摆放里采纳的）。⇒ 只要每根骨摆放方向 == 模板标准朝向，落差 = 0，unpose 就是恒等变换。
- 修法（v2 摆放 `.workbuddy/tmp/joints_v2.json`）：**Hips y 1.000 → 1.155**（使 Hips→UpLeg 正好 45°、|UpLeg.x|=0.165）；脊柱/腿严格竖直、z 统一 −0.010；**手臂保留贴模型的前扫+下垂**（保权重质量），只让反解把手臂摆正。
- 结果：`heightBefore == heightAfter == 2.05`、`maxPoseAngleDeg 43.34→11.14`、`offAxisBones` 清空、零权重/tip 权重 0；真实形变**中位 0.0000 / max 0.1361**，仅 21.7% 顶点移动且全在 |x|>0.25 的臂区，腿/躯干/头切片逐行不变。落差 2.606 → 0.479（全在臂）。
- 🔴 **Mixamo/HumanIK 的 Hips 本来就在髋臼上方**：Hips ≈ 0.55H、髋关节 ≈ 0.48H，两者差 0.07H ≈ 0.14m 的斜下外。所以「Hips 抬到 1.155（0.556H）」「髋关节 0.99（0.483H）」是标准人形骨架约定，不是畸形。
- 顺带结论：**不用改引擎**。`rotWorld[name]=rotWorld[parent]·poseRotations[name]` 会把整体旋转沿链累积（指尖 4θ），但改成「ΔR 相对父骨实际朝向」只把 max 从 0.139 降到 0.117，收益太小，不值得动 `fitSkeleton`（会波及 E-01 等既有导出）。
