### 工具：`assets/characters/_tools/gen3d_from_image.py`
**坑 1（致命）**：官方 `buddy-cloud.py` 的 `--image-base64` 是**命令行参数**。
本地 PNG 转 base64 约 2.1 MB，远超 Windows 命令行长度上限（~32K 字符），**直接传必失败**。
解法：把 buddy-cloud.py 当模块 import（`importlib.util.spec_from_file_location`，
文件名含连字符不能普通 import），复用它的 `_call_api` / `_poll_job` / `_build_3d_body`，
base64 从文件读入。Token 走 `--token-stdin` 管道，不进命令行/进程列表。
依赖：managed python 需 `requests`（脚本会自动装，首次约 10s）。

**坑 2**：返回字段是 **`ResultFile3Ds`**，且是**大写** `Type` / `Url` / `PreviewImageUrl`，
不是 `ResultFiles` / 小写 snake_case。解析错会**静默拿到空数组**（任务明明 DONE）。
另：`Type=OBJ` 的产物实际是 **.zip 包**，要解压（内含 obj / mtl / 4 张 PBR 贴图）。
因此脚本加了 `--job-id`：只查询下载、**不重新提交**，避免重复烧额度（本次白烧了一轮）。

### 硬坑（都是非显而易见的）
- **pymeshlab 的 GLB 导入器会丢 UV**（`has_vertex_tex_coord()=False`），但模型 UV 其实是好的；
  而且它对这套 GLB 的 PBR 材质也解析不出来。**必须自己解析 GLB 二进制**取 verts/faces/uv/贴图，
  再转 OBJ 喂给 pymeshlab。trimesh 5.0 也对这套材质解析失败（`PBRMaterial` 的 `baseColorTexture` 是 None）。
- **减面到不了目标面数的原因**：`preserveboundary=True` 会护住 UV 接缝边界，压到 29064 就停了。
  必须 `preserveboundary=False`（目标 1600 时）才能到 1599；`preservenormal=True` 要**保留**，
  否则盾板/护甲硬边会塌成软面。
- **pymeshlab 不能导出 glb**（`Unknown format for save: glb`）。导出 ply/obj，再用 **trimesh 转 GLB**。
- **trimesh 转出的 GLB 没有 materials 字段** → 部分渲染器不启用顶点色，会显示成白模。
  脚本内置 `ensure_material()` 注入一个哑光 PBR 材质；渲染器检测到 `COLOR_0` 会自动开 vertexColors。
- GLB 解析两个细节：indices 是 SCALAR accessor，要 `.reshape(-1,3)` 折成面；
  `normalTexture`/`occlusionTexture` 挂在 **material 根**上，不在 `pbrMetallicRoughness` 里。
- 重新打包 GLB 时：JSON chunk 用 `0x20` 补齐、BIN chunk 用 `0x00` 补齐（glTF 2.0 规范）。

### 设计决策：为什么烘顶点色而不是重展 UV
压到 2% 面数后 UV 必然严重拉伸，重展 UV + 烘焙 normal/AO 工序重。
本项目是 god view 下几十像素的小怪，把高模 baseColor 按 UV 采样成**顶点色**就够用，
还能省一张贴图。真要做近景 Boss 时再走完整烘焙流程。

### 关键坑
- **pymeshlab 的自动 UV 全军覆没**：`generate_voronoi_atlas_parametrization` / LSCM /

### ⚠ 三个只有真跑浏览器才会暴露的坑（tsc / vite build 都查不出）

1. **`minUniformBufferOffsetAlignment`(256) 对静态 offset 同样生效**。
   我原先以为只有 dynamic offset 才要对齐 —— 错。
   报错：`Offset (128) of [Buffer "objects"] does not satisfy the minimum ... alignment (256)`。
   修法：拆成 `materialBuf` / `transformBuf` 两个 buffer，各自 256 字节 stride，
   绑定 offset = `base`（base 本身 256 对齐）。

2. **描边 vertex stage 读到的 uniform 必须声明 `VERTEX | FRAGMENT` 可见性**。
   `vs_outline` 要读 `mat.flags.y`（描边倍率），但 binding 3 只写了 FRAGMENT。
   报错：`Entry point's stage (ShaderStage::Vertex) is not in the binding visibility`
   `... @group(0) @binding(3) ... vs_outline`。

3. **`fwidth()` 等导数函数必须在 uniform control flow 里**。
   两条违规：函数内两个 early `return` 之后才调 `fwidth`；调用点又在
   `if (!exempt)` 里而 `exempt` 来自纹理内容（non-uniform）。
   修法：把 `fwidth` 提到函数开头无条件求值，调用点也无条件求值，
   最后用 `* select(1.0, 0.0, exempt)` 掩码。
