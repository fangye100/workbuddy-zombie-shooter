# 2026-09-10

## Motion Match（重定向后的动画匹配）—— 设计已定，未实现

产出 `docs/16-MotionMatch动画匹配设计.md`（新文件）。用户诉求：同一套 mocap 对不同比例
角色，按角色比例传递 IK/FK 部分，不滑步、不幅度失真（照 Maya HumanIK / MotionBuilder
的 Match 做）。

### 核心诊断（这次最重要的结论）

现有 `retarget.ts` 是**纯 FK 旋转重定向**，只守住一条：
`Q_tgt_i·d_tgt_i = Q_src_i·d_src_i`（世界**骨向**守恒）。
**它完全没守末端效应器的世界位置** —— 而 HumanIK Match 守的正是后者。

旋转相同 + 骨长不同 ⟹ 末端位移 ΣL·sinθ 必然不同 ⟹ 幅度失真 + 滑步。
根位移按全局腿长比缩放、脚落点由「目标骨长 × 源旋转」FK 算出，两条路径只在
「目标是源的等比缩放」时相等；现实比例分布不同，必然对不上。

### 分层（MVP = L1+L2+L3）
- L0 FK 骨向对齐（已有，不动）
- L1 骨架比例归一化：**按链**算长度比（腿/臂/脊柱），非全局 scale
- L2 两骨 IK 解析解（余弦定理，非迭代）+ 极向量取源姿态 + **swing–twist 分解保留 twist**
- L3 接触帧脚锁定 + **根回退**（防过伸）
- L4 地面 clamp + Hips 高度对齐（本轮不做）

### 已定决策
- **手臂不走 IK**（用户确认）：射击游戏大量持枪姿态，手臂 IK 与瞄准打架，且手部无地面
  约束、收益低。手臂完全不进 motion match，保持 L0 FK 结果。L2 是链无关的，日后加配置即可。
- 中轴（Hips/Spine*/Neck/Head）走 **FK**，保 mocap 的重心起伏与躯干节奏；只有双腿走 IK。

### 🔴 两个易混的量（写代码时必须分开）
- `hipToAnkleY = Hips.y − Foot.y = 0.97`（T-pose 模板）→ **根位移缩放**，沿用 L0 现值，
  改了会破坏 retarget.test.ts 的 40+ 条断言。
- `legLen = |UpLeg→Leg| + |Leg→Foot| = 0.42 + 0.45 = 0.87` → **IK 链长比与可达半径**。
两者差 11%，混用会让腿系统性地够不到地。

### 测试判据里最重要的两条
- **T1 等比退化恒等**：目标骨架 = 源 ⟹ 输出 == 输入（防把本来就对的情形搞坏）
- **T2 缩放退化**：目标 = 源 × k ⟹ 旋转不变、根位移 × k
这两条是 L1 用「各向同性缩放」而非分轴缩放的原因（分轴会破坏退化性质）。

### 性能定性
motion match 是**离线烘焙**，输出仍是 RetargetClip → 烘进 GLB animations[]。
500 僵尸运行时只播 AnimClip + instancing，与它无关。**别做成 runtime IK**。
