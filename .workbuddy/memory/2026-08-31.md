## 目录改名：为什么在 WorkBuddy 里做不到（重要结论，别再重复踩）
- **根因不是"其他会话未结束"**。WorkBuddy 会为每个工作区维持一个 CLI 进程，其 CWD 钉在工作区目录上。
  Windows 不允许重命名任何进程的当前目录。实测：杀掉 26592 → 1 秒内自动重建 22048（同样 CWD）。
  → **只要 WorkBuddy 开着这个工作区，改名必然失败，杀进程无用，抢不过重建速度。**
- Windows 报错形态：Git Bash `mv` = `Device or resource busy`；PowerShell `Rename-Item` =
  `it is in use` / `being used by another process`。两者都不告诉你是谁占的。
- **定位手法（可复用）**：读目标进程 PEB 的 CurrentDirectory 枚举所有进程 CWD，比猜快得多。
  脚本已固化在 `C:\Users\fangy\findlock.ps1`（C# `NtQueryInformationProcess` + `ReadProcessMemory`，
  64 位偏移 PEB+0x20 → ProcessParameters，+0x38 → CurrentDirectory；32 位为 +0x10 / +0x24）。
- **最终方案**：改名必须在 WorkBuddy 关闭后执行。已交付给用户一个可执行程序：
  - `C:\Users\fangy\rename-workspace\rename_workspace.py`（UTF-8，含全部中文字符串；支持 `--dry-run` / `--no-wait`）
  - `C:\Users\fangy\Desktop\RenameWorkspace.bat`（**纯 ASCII**，只负责调 python + `chcp 65001`）
  - 编码铁律：中文绝不写进 .bat/.ps1，只放进 UTF-8 的 .py，否则 Windows 控制台会乱码。
- 脚本做的四件事：等待 WorkBuddy 退出 → 重命名工作区目录 → 重命名 `projects/c-Users-fangy-WorkBuddy-<旧名>`
  → 重写全部路径引用（自动备份 `app/sessions.json`）。
