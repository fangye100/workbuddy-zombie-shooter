## LOD1 花脸真根因定论 + 修复成功（E-01）

用户质询「LOD1 贴图还是花的，能修么」→ 挖到两层真根因，全部修掉。

### 根因 1：几何（花脸的主因，非 UV 算法）
- 空间网格聚类减面（v1 无屏障 / v2 加 UV chart 屏障）产出的三角形**横跨模型不同部位**
  （胸口顶点连到后背），这种三角形采任何贴图都是花的。证据：v2 加了接缝屏障花脸依旧，
  且面积保持率掉到 56%（v1 报 80% 是假象）。
- 🔴 混元高模**几何本体是完美封闭流形**：按位置焊点后 V=39854 / E=119616(=1.5F) /
  边界边 0 / 非流形 0。表面上那 20% 「边界边」全是 UV 切分造成的假象
  （atlas 被切成 1338 个 chart，中位仅 10 顶点）。
- 正解：**先焊点（mesh 保留逐面角 wedge UV）+ pymeshlab `meshing_decimation_quadric_edge_collapse_with_texture`**。
  实测 E-01：79744 → 3000 面 / 1482 顶点 / 面积保持 **92.8%** / 边界 0 / 非流形 0。
  （对比：聚类 v2 3000 面档面积保持仅 56%。）
- 另注：`preserveboundary=True` + 那批假边界边会让 QEM 卡在 26236 面不动（两个不同 target 同结果）。

### 根因 2：glTF 的 UV 是逐顶点，不是逐面角（颜色整体错位）
- OBJ 的 vt 是 wedge（E-01 低模 4209 vt vs 1482 顶点）。**直接把 vt 表塞进 glTF**
  会得到 4209 个 UV 但 1482 个 POSITION，indices 只能引 POSITION 下标
  ⇒ 前 1482 个 UV 被错配到不相干顶点，采样整体偏移（表现为「全身偏绿/色相偏」）。
- 修法：`split_wedges()` —— 每个唯一 (v, vt) 对生成一个新 glTF 顶点，
  POSITION/TEXCOORD_0/NORMAL 同步复制。输出 4209 顶点，UV 正确对齐。

### 附带修掉的两个 glb 容器坑
- JSON chunk 填充必须用 **空格 0x20**（`JSON.parse` 不认 `\x00` 是空白
  → "Unexpected non-whitespace character after JSON"）。BIN chunk 才用 `\x00`。
- `buffers[0].byteLength` 必须随追加贴图同步扩，两个 chunk 都要 4 字节对齐。
