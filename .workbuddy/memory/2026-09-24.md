## E-01 绑定审核（hy4 质量标准）

用户切换到 hy4-preview 后要求「用混元4 的质量水准，用 MCP 图，对 E01 绑定结果再做一次审核」。
前序 session 由 GLM5.3 → Kimi K3 → 混元3 接力修过肘部，本次为独立复审。

### 🔴 关键突破：hy4 能直接读 PNG
前面几个模型看 `Read` 图片一律返回「current model does not support images」，
被迫走像素标定数值路线。**hy4 能真看图** → 审核改为「视觉判读为主 + 数值佐证」。
以后审核绑定/渲染问题优先确认当前模型是否支持读图，支持就别绕。

### 建立的审核方法（可复用，已存 skill `binding-geometry-audit`）
1. `dom.session.getMesh()` 拿 `{vertices, indices, vertexFloats}`；`dom.session.positions` 拿关节。
2. **复现 `render.ts` 的 auto-fit 投影**（points ∪ markers(±0.02) 的联合包围盒 → scale/cu/cv/sx/sy），
   与渲染器实际画出的绿点比对：**误差 < 0.7px**（scale 471.8 px/m @760×1000）。
   → 像素↔世界坐标双向精确换算，不用再靠肉眼估像素。
3. 渲染用 **mesh-only toon**（`showSkeleton:false, showCylinders:false`）——
   骨架线画在 mesh 之上会把 tan 剪影割断，污染 run 判定。
4. 逐行扫描非白 run → 世界坐标区间；**从末端向上追踪**四肢中心线（合并处自动断链）。
5. **判定铁证 = run 归属**：关节投影是否落在某个 run 内。悬空 = 铁证错误。
6. 出「红虚线=现状 / 绿实线=建议」对比图，一眼判读。

### 审核结论（E-01 Shambler）
- 🔴 **手臂链下半段整体错位，6 关节中 5 个悬空**：
  LeftForeArm(+8.8cm) / LeftHand(**+16.9cm，落在左大腿上**) / LeftHandTip / RightForeArm / RightHand / RightHandTip 全不在网格上。
- 根因：手臂 x 按「贴身」假设填（0.27→0.33→0.30 **递减**），而网格手臂实际**外张**（0.284→0.418→0.469 **递增**）。
  用户之前抱怨的「肘贴着肚子」= 肘偏内 8.8cm 正好贴躯干前缘。
- 🟠 LeftFoot 偏内 7.5cm；LeftHandTip 比左手网格尖端低 4.5cm。
- ✅ 上臂两侧、右腿全部、中轴 7 骨、**z 方向全部合格**（z 精度 ±5cm，受肢体厚度限制）。
- 🔴 **网格本身左右不对称**：手臂 1.5–3.5cm，**小腿 8cm** → `mirror L2R` 必然引入 1.5–8cm 误差，
  左右肢体应**分别对位**，不要一步镜像。
