### 🔴 关键突破：hy4 能直接读 PNG
前面几个模型看 `Read` 图片一律返回「current model does not support images」，
被迫走像素标定数值路线。**hy4 能真看图** → 审核改为「视觉判读为主 + 数值佐证」。
以后审核绑定/渲染问题优先确认当前模型是否支持读图，支持就别绕。

### 建立的审核方法（可复用，已存 skill `binding-geometry-audit`）
1. `dom.session.getMesh()` 拿 `{vertices, indices, vertexFloats}`；`dom.session.positions` 拿关节。
2. **复现 `render.ts` 的 auto-fit 投影**（points ∪ markers(±0.02) 的联合包围盒 → scale/cu/cv/sx/sy），
   与渲染器实际画出的绿点比对：**误差 < 0.7px**（scale 471.8 px/m @760×1000）。
   → 像素↔世界坐标双向精确换算，不用再靠肉眼估像素。
3. 渲染用 **mesh-only toon**（`showSkeleton:false, showCylinders:false`）——
   骨架线画在 mesh 之上会把 tan 剪影割断，污染 run 判定。
4. 逐行扫描非白 run → 世界坐标区间；**从末端向上追踪**四肢中心线（合并处自动断链）。
5. **判定铁证 = run 归属**：关节投影是否落在某个 run 内。悬空 = 铁证错误。
6. 出「红虚线=现状 / 绿实线=建议」对比图，一眼判读。

### 方法论沉淀（可复用）
- **法线-径向对齐扫描找横向褶皱**（`crease.py`）：平滑管 `dot(normal, radial)≈1`，横向折痕处骤降。
  **已验证有效**：y=1.40–1.43 探到的折痕 = **袖口**（已知真值）✓；E-01 另有折痕带 1.10–1.165 与 0.90–0.92（腕褶）。
- **2D 设定图是判肘的好参照**：`assets/characters/images/E-01/front/E-01_front.png`（1024×1536，角色占 y 39–1493）。
  逐行取最外 run = 手臂；宽度最小 = 腕（y≈860/900px），宽度局部最大 = 臂最粗（≈660–700px）。
  E-04 另有 `front/E-04_front-landmarks.png`（带标尺虚线）可参考惯例。
- **高模 4K 贴图渲染**是判布料/皮肤/褶皱唯一可用的底图：1K 烘焙 baseColor 的亮度直方图被 128 灰主导，
  分不出袖子和皮肤（`colhist.py` 结论），必须回退到 `obj_*/texture_pbr_*.png` + 79k 面高模。
- 🔴 **MCP render 的 width/height 被 `tools.ts` 夹到 64..1024** —— 要 1400×1900 会静默返回 1024×1024。
- 顶点 stride=15：POSITION 0..2 / NORMAL 3..5 / **UV 9..10**（不是 3..4）。
- 会话空间 = 文件空间 ×1.9 + (0.02375, 0.0019, −0.09405)。

### 教训
- **关节位置不适合纯数值推断**：臂近直时没有肘部拐点，只有解剖比例；让用户**看图点线**一次收敛，
  此前几轮全是自证空转。遇到信号互相矛盾时，出「候选线对照图 + 单选」比继续量更快。
- 用户的「外形结构」判读与解剖比例可能冲突（1.25 会让上臂比手短）→ **照做 + 立刻量化副作用上报**，
  用户随即同意提肩，两步收敛。

### 🔴 关键发现 1：offset 是主要病灶（不是半径）
`bindingEditor.cylinders` 里 11 根圆柱带**乱拖的 offset**（上个 session 拖去追破布）：
`LeftLeg [0,-0.130,0.200]`（侧移 13cm/前后 20cm！）、`LeftHand [0,-0.100,0.140]`、
`LeftFoot [-0.100,-0.050,0]`、`LeftUpLeg/Hips/ForeArm` 同款。位置被拖离腿/手。
**清零 offset → unwrappedVerts 2160(51.3%) → 1178(28.0%)**。
另外 **22 根全是 `manual:true`** → `autoFitCylinders()` 直接 `continue` 且返回 `changed=[]`，
**静默空操作**（`skin-proxy.ts:153`）。以为跑过 autoFit = 最容易踩的坑。

### 🔴 关键发现 2：p90 会给「破布」定半径
用「未包裹顶点的 dr p90」反推半径 → 得 127(3.0%)，但四肢半径变成可见肉身的 1.9–2.8×，
且 `Spine2.top=0.300` 抢颈/三角肌、`LeftHand.top=0.132` 咬膝盖。
**根因：p90 在包破布/描边壳，而破布按设计就该在圆柱外。**
改回「**密度峰值**」法（包内 dr 直方图 bin 5mm 取峰，破布成尾部不动峰）→ 腿 0.095/0.158/0.106、
臂 0.147/0.078 —— 与**原手工值**（腿 0.10、臂 0.09）和审核员看图值（0.08/0.115/0.105）三者一致。
**结论：僵尸类破损模型不能用分位数反推半径，要用密度峰值（肉的主表面）或解剖经验值。**

### 🔴 关键发现 3：出图投影必须含圆柱（否则十字错位 17cm）
`render.ts:170-174` 的 auto-fit 把 capsules 端点 **± 半径** 纳入包围盒。
我出图脚本的变换只算 mesh 顶点（scale 485.9）而渲染图含圆柱（scale 442.7）
→ **十字/标签整体错位 17cm**，肉眼可见（HD 标签浮在头顶上方）。
独立审核员用关节 marker 圆点反解出图形层真实变换并用 rms 0.36px 验证，抓出此 bug。
**修法**：`tfFull()` 复刻 auto-fit（points+segments+capsules±r+markers 0.02）。
**关节阶段的图不受影响**（那时 showCylinders:false），wrapper 阶段必须修。
