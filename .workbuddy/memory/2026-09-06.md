**用户症状**：「模型每个 joint 上应显示圆柱形状的皮肤权重包裹器，在视图里完全看不到」。

**排查结论（重要，别再踩）**：
- 圆柱体**早就实现了**，但只有两处，且都不是主 3D 视口：
  1. 数据/权重：`services/binding/skin-proxy.ts`（`SkinCylinder` / `defaultSkinCylinders` / `computeCylinderWeights` / `mirrorCylinders`）。
  2. 绘制：`binding-panel.ts` 的 `drawSkin()`（line ~1092）——只在面板的 front/side **2D canvas** 里用
     `lineCap:'round'` 的粗描边画示意，**不是 3D 几何**；且要 `editMode==='skin'` 才画（默认 `'skeleton'`），
     `cylinders` 由 `ensureCylinders()` 惰性初始化。

## 绑定面板正/侧视换 3D 正交视图（commit 0e12cde）

**用户原话**：「把面板正/侧视也换成 3D（复用主视口那套圆柱体几何，正/侧视
变成 3D 正交相机视角，能真正看出包裹器体积和穿插）」。

### 路径
1. **引擎层加正交投影**：`packages/core/src/math.ts` 新增 `ortho()`
   （WebGPU 深度 [0,1]，返回 out[5]=1/halfHeight 语义对齐
   perspective 的 projScaleY）。`packages/render/src/renderer-core.ts`
   的 `RenderFrameParams` 加必填 `orthoHalfHeight: number | null`
   （null = 透视，非 null = 正交），drawFrame 按它选 ortho/perspective。
   正交下 near/far = `max(0.01, distance - ORTHO_DEPTH=500)`
   /`distance + 500`，足够覆盖角色包围盒。
2. **面板每视图独占 RendererCore**：新文件
   `apps/editor/src/services/binding/binding-view3d.ts`（模型层
   BindingView3D，独占画布 + GPU 上下文），与 asset-preview 平级。
   画网格实体（带深度）+ 半透明 X-ray 圆柱体。joint 圆点 / 骨连线 /
   选中高亮 / 文字标签仍在 2D 画布上画（透明叠在 3D 层之上）。
3. **两套投影严格对齐**：`setFit(scale, targetY)` 把面板的
   `project()` 映射 `ox + x·s`、`oy - y·s` 等价翻译为正交
   `halfHeight = (h/2)/scale`、`targetY = 0.42·h/scale`，
   保证网格与 2D 骨架不错位。
4. **cylinder-overlay 抽出共享核心**：原 `buildCylinderOverlay`
   （实时关节矩阵 → 主视口）保留；新增 `buildCylinderOverlayFromSegments`
   （骨段 → 面板），与 `computeLbsWeights` 共享 `boneSegments(positions)`，
   面板里看到的体积 = 算权重用的体积（单一真源）。两条路径各占一块
   scratch 缓冲防同帧互踩。
5. **GPU 不可用降级**：`gpu===null` 时不创建 BindingView3D，drawView 退回
   原 2D 画家算法，drawSkin 用旧粗描边——功能不丢。
6. **DOM 改造**：`apps/editor/index.html` 加 `.bd-stage { position:relative; ... }`
   包裹两个 canvas：3D 层 `.bd-gl` 在下，2D 层 `.bd-canvas` 在上且透明，
   无 border（border 移到 stage 上）。

### 坑点
- `RenderFrameParams` 加**必填**字段会逼着主视图 + asset-preview 一并改，
  不能漏。typecheck 一次过——只 2 处调用点。
- `binding-view3d.ts` 用 `m4.mat4()` 单位阵作为 transform，写一次而非
  每帧重算。
- 蒙皮槽位**必须绑**：哪怕面板网格是静止姿态，也得给一个恒等 skin 顶点

## 面板 3D 视图「过曝一片白 + 包裹器看不见」修复（commit 14aeaf2）

**用户反馈**：「panel 里面人物过曝一片白色 然后还是没看到3D 包裹器」。

### 根因（两条，都被像素采样证实）
1. **过曝**：`VIEW_PARAMS` 直接继承 `defaultParams()`，而它 `exposure = 1.5`
   是给主视口那套卡通渲染调的；配上 `VIEW_MATERIAL.albedo = '#8E96A8'`，
   三点光叠满后模型直接顶到 1.0。像素采样 `white=7.6% / maxL=250`，
   模型区域几乎全是纯白。
2. **包裹器看不见**：**不是没画**（几何 5280 顶点早就送进管线、零报错），
   是半透明彩色圆柱叠在纯白模型上被冲淡成淡色；而且原实现只在
   `editMode === 'skin'` 时画，默认 skeleton 模式下压根不画。

### 修复
- `VIEW_PARAMS` 显式 `p.exposure = 1.05`；`VIEW_MATERIAL.albedo`
  `#8E96A8` → `#79818F`（暗冷灰，linear ≈ 0.19）。
- 包裹器**两个模式都画**：关节模式默认半径 alpha 0.22，蒙皮模式半径表
  alpha 0.42。`BindingView3D` 新增 `setAlpha()`。
- 采样结果：white 7.6% → **0**，maxL 250 → 231，中亮档 21.4%，dark=0。

### 🔴 采样方法的坑（已同步进 skill webgpu-headless-validate）
- **不能 `ctx.drawImage(webgpuCanvas)`**：present 之后 drawing buffer 已丢弃，
  headless 采出来是**全 0**，会把「真黑」和「取不到像素」混为一谈（我第一次
  就误判成渲染失败）。
- 正确链路：`Page.captureScreenshot`（带 clip）→ base64 回传页面 →
  `createImageBitmap` 解码 → 2D canvas → `getImageData`（Node 没 PNG 解码器）。
  `Runtime.evaluate` 要带 `awaitPromise: true`。
- **看不了图时用 PIL 转字符图**：亮度映射 ` .:-=+*#%@` + `sat>0.22` 输出 R/G/B。
  ⚠️ 深蓝背景 (0.09,0.10,0.13) 饱和度就有 0.31，满屏 `B` 可能只是背景——
  **先看四角当基准**。

## Skin Wrapper 半径调不动（2026-09-07）

用户报「视图里调 skin wrapper 半径没反应」。排查结论分两层：

### ① 先把它变成可复跑的判据（不然只能猜）
- 顶点数看不出半径变化（改半径不增不减顶点）→ 新增**几何指纹**
  `sum` = 顶点坐标绝对值之和 + bbox。
- `renderer.debugCylinderStats()` / `BindingView3D.cylinderSum`。
- 冒烟新增 L2e（几何，带「写入同值」对照组量刷新副作用）+ L2f（主视口像素）。
  结论：主视口 / 面板 3D / 2D 降级**三条路径都通**
  （主视口 bbox x −2.72→−3.12，画面 avg 31.5→47.6）。

### ② 真正的原因
蒙皮模式的 `pointerdown` **只做点选，拖动没有任何行为** ——
在视图里拖圆柱体本来就没实现，只有那三个滑块能改半径。
→ 补上「半径 = 指针到骨轴的垂距」，按下即拖，只改点中的那一段。
- 垂距必须用**直线**不是线段（线段版靠近骨两端会被端点距离撑大）。
- 合成 PointerEvent 没有真实 pointer，`setPointerCapture` 会抛 → try/catch。
- 自动化钩子 `wrappers.pick(axis,x,y)` 与鼠标共用 `pickCylinderAt`。

### ⚠️ 冒烟环境坑
`editor:smoke` 默认复用 5100 上**已在跑的编辑器**；5100 不在时它会自己起
vite，但 readiness 探测在新端口上会失败/卡住（这次卡了 1h39m，
只能 TaskStop）。跑之前先 `curl -sk https://localhost:5100/` 确认。
