# 绑定（Bind Skin）流程与 UI 面板 · 技术美术评审

> 评审范围：`apps/editor/src/services/binding/*`（binding-panel / binding-math / skin-proxy /
> binding-export / cylinder-overlay / binding-view3d / humanik-template）+ `main.ts` 接入段。
> 评审视角：技美 —— 蒙皮质量、权重算法、美术可用性、工具反馈闭环、性能预算。
> 日期：2026-09-08

---

## 0. 结论先行

整体架构是**对的**：「骨长采纳 / 姿态旋转 ΔR 不进骨架 / 网格反解回 T-pose」这套数学很干净，
T-pose 反解 + 法线同步逆转置也做得标准，比多数自研小工具扎实。tip 骨「保留槽位 + 权重置零」
的处理（避免 glTF joint index 错位）是正确且专业的决定。

但有 **3 个 P0 会直接反映到画面上**，且都不是「以后再优化」的级别：

| # | 问题 | 后果 | 证据 |
|---|---|---|---|
| P0-1 | 权重平滑（`smoothSkinWeights`）按**槽位 k** 而非**骨 id** 做邻域平均 | 把权重灌到语义无关的骨上，实测无关骨凭空拿到 **18.8%** | 见 §1.1 实测 |
| P0-2 | 两套权重算法，UI **无切换、无提示**；实际永远走圆柱体路径，`computeLbsWeights` 在 UI 上是死代码 | 美术不知道自己在用哪套；距离衰减参数（falloff/eps/maxInfluences）是**死参数** | 见 §1.2 |
| P0-3 | **没有权重可视化，没有变形预览** | 调半径 / 调骨位全靠猜，「优化皮肤权重」开关的实际效果不可验证 | 见 §1.3 |

## 1. P0 缺陷

### 1.1 权重平滑按槽位平均 → 权重跑到无关骨上（已实测）

`binding-math.ts:335 smoothSkinWeights()` 的核心循环：

```ts
for (let k = 0; k < 4; k++) {
  const self = cur[i * 4 + k]!;
  let sum = 0;
  for (const j of nb) sum += cur[j * 4 + k]!;   // ← 邻居的「第 k 个槽位」
  next[i * 4 + k] = (1 - lambda) * self + lambda * (sum / nb.length);
}
```

而 `const joints = new Uint16Array(skin.joints)` —— **影响骨数组原样拷贝，不参与平滑**。

问题在于：顶点 i 的第 k 个槽位与邻居 j 的第 k 个槽位**不保证是同一根骨**。
排序是按该顶点自己的权重降序排的，骨骼交界处相邻顶点的骨集合顺序天然不同。

**实测（一次性探针，真实代码，已删除探针文件）**：
构造 v0=[骨A 100%]，v1=[骨A 60% + 骨B 40%]，v2=[骨B 80% + 骨A 20%（槽位顺序相反）]，
三者互为邻居，跑 `smoothSkinWeights(2, 0.5)`：

```
v0: 骨0=0.813  骨5=0.188   ← 骨5 与 v0 毫无几何关系，凭空拿到 18.8%
v1: 骨0=0.788  骨1=0.213
v2: 骨1=0.800  骨0=0.200
```

**为什么这在本项目里特别致命**：圆柱体权重（`computeCylinderWeights`）是**二值**的
（包住 / 没包住），实测真实骨架下典型顶点输出是 `LeftUpLeg=100.0%` 这种纯硬权重。
这些顶点的槽位 1/2/3 权重为 0，且插入排序在 w 相等时保持稳定 → 填入的是
**索引最小的骨 = Hips / Spine / Spine1**。
一旦它的邻居位于骨交界处（有 2 根真实骨），邻居槽位 1 的 40% 就会被灌进
本顶点的 Hips 槽位 → **关节周围一圈顶点把权重交给脊柱**，弯腰时四肢/躯干被 Hips 拽走。

**修复方向**（不增加复杂度）：平滑前把 4 槽位展开成 `Map<jointId, w>` 累加，
按 **joint id** 聚合邻域权重，最后取 top-4 重新打包并归一化。
伪码：

```ts
// 每个顶点：acc = Map<number, number>
for (const j of [i, ...nb]) for (let k = 0; k < 4; k++) {
  const b = joints[j * 4 + k]; const w = cur[j * 4 + k];
  if (w > 0) acc.set(b, (acc.get(b) ?? 0) + w * (j === i ? (1 - lambda) : lambda / nb.length));
}
```

### 1.2 两套权重算法，UI 无切换无提示，其中一套是死代码

导出路径 `binding-export.ts:186`：

```ts
if (input.cylinders !== undefined)  skin = computeCylinderWeights(...)
else                                skin = computeLbsWeights(...)   // ← 什么时候会走到？
```

`main.ts:1139` 传的是 `binding?.getCylinders() ?? undefined`，
而 `getCylinders()` 直接返回 `this.cylinders`（`binding-panel.ts:1693`）——
`this.cylinders` 在 `setModel()` 里就通过 `ensureCylinders()` **载入即建**
（`binding-panel.ts:532`，注释明确说是为了修「关节模式下包裹器自己变大变小」）。

**结论：只要载入了模型，`cylinders` 就非 null → 每一次 Bind Skin 都走圆柱体路径。**
`computeLbsWeights` 在 UI 路径上永远不会被调用（只有面板 `syncDisplay` 预览用到了它）。
连带后果：`BindExportInput.falloff / eps / maxInfluences` 三个参数
（`binding-export.ts:76-78`）**没有任何调用方传入**，永远是默认值 —— 死参数。

美术侧的可感知问题：
- 面板上「选择 Skeleton / 选择 Skin Wrapper」看起来是**编辑模式**切换，
  但实际还隐含了**权重算法**的语义，而 UI 从不告诉用户当前会用哪套。
- 距离衰减权重（业界默认、过渡自然）在编辑器里根本用不到，除非改代码。

**修复方向**：面板加一个显式的「权重算法」下拉（包裹体 / 距离衰减 / 混合），
默认项写进 `.meta.json`；同时把 `falloff / eps / maxInfluences` 提到 UI 或至少提到
`.meta.json`，让它们从死参数变成可调参数。

### 1.3 没有权重可视化，也没有变形预览

当前可视化只有：圆柱体线框（`cylinder-overlay.ts`）+ 正视/侧视网格剪影 + 三半径滑块。
`cylinder-overlay.ts` 全文没有任何权重着色（grep「权重/weight」只命中注释）。

这意味着美术在调蒙皮时**看不到权重分布**，只能：
调半径 → Bind Skin → 导出 GLB → 换工具/回引擎摆姿势 → 发现塌陷 → 回来重调。
反馈闭环断在最贵的一环上。

**技美标配的三件套，目前一个都没有**：

| 能力 | 现状 | 建议 |
|---|---|---|
| 权重热力图（选中骨 → 顶点按权重着色） | ❌ | 必做，见下 |
| 姿势变形测试（拖关节旋转看蒙皮） | ❌（只有 T/A 重姿态预览，**不是蒙皮变形预览**） | 必做 |
| 数值诊断（影响顶点数 / 零权重顶点 / >4 影响 / 错骨） | ❌（面板只有顶点数、面数） | 必做 |

权重热力图实现成本不高：`computeCylinderWeights` 已经算出每顶点 4 权重，
加一个「选中骨 → 顶点色 = 该骨权重」的叠加通道即可（复用现有 `bd-gl` 正交层或 2D 画家算法）。

## 2. P1 缺陷（算法与流程）

### 2.1 包裹体外顶点：硬权重 1.0 兜底，是撕裂高发区

`skin-proxy.ts:259`：

```ts
if (sum <= 1e-12) { joints[base] = nearestBone; weights[base] = 1; }
```

没被任何 wrapper 包住的顶点 → 单一骨 100% 硬权重。
对本项目的题材（僵尸：腐肉、外露骨骼、破布、绷带、背负物；美漫描边：外扩描边壳）
这类「长在包裹体之外」的几何**会大量存在**，且它们紧邻平滑区 → **硬边接缝**。

建议：兜底改为按 `gap`（到最近 wrapper 表面的距离）做软衰减，而不是硬 1.0：
`w = 1 / (1 + (gap / r_falloff)^2)`，让包裹体外有一段自然过渡带。

### 2.2 `PEN_SCALE = 8.0` 是绝对米制 → 粗骨碾压细骨、尺度不不变

`skin-proxy.ts:209-210`：

```ts
const BASE = 1.0;
const PEN_SCALE = 8.0;
w[b] = BASE + (-gap) * PEN_SCALE;   // -gap = 穿透深度（米）
```

穿透深度是**米**，最大 ≈ 半径上限 0.22 → 权重 1.0 ~ 2.76。后果：
- **粗骨碾压细骨**：上臂（r=0.08）深埋顶点 w≈1.64，下臂（r=0.06）边缘顶点 w≈1.0，
  共享区被粗骨主导 —— 与「包住即所属」的语义矛盾。
- **不尺度不变**：1.6 m 的瘦僵尸与 2.4 m 的暴君，同样几何比例的顶点会得到不同权重，
  换模型就要重调。

建议改成**归一化穿透深度**：`w = BASE + PEN_SCALE * (r - dr) / r`，
或者干脆用 `1 + PEN_SCALE * clamp((r - dr) / r, 0, 1)`，让权重只依赖相对深度。

### 2.3 距离衰减权重实际已退化为「最近骨硬分配」

对照实测（真实骨架，胶囊距离权重，默认 falloff=3.0 / eps=0.02）：

```
左大腿中: LeftUpLeg=97.9% + LeftLeg=1.0% + RightUpLeg=0.8% + RightLeg=0.3%
头顶:     Head=98.9%  + Neck=1.1% + Spine2=0.0% + LeftShoulder=0.0%
```

`1/(d+eps)^3` 在 d 小时爆炸式增长，最近骨压倒性胜出，top-4 里后三个基本是噪声；
而且**对侧骨（RightUpLeg）抢到 0.8%** —— 这是距离衰减的经典缺陷，是大跨步时
裆部/腋下穿插（糖纸效应）的成因之一。

建议：换 `exp(-d / σ)`（σ 与骨半径挂钩）或加距离上限截断；
并对「解剖上不该影响」的骨做排除（左右腿互不影响，可用 `mirrorOf` 侧别 + 最小距离阈值）。

### 2.4 平滑只 2 次迭代 λ=0.5，扩散半径不够

注释说「迭代 2 次、λ=0.5 已是肉眼可见的改善」。理论上 2 次 Jacobi 只能扩散 ~2 环顶点。
而圆柱体权重是**阶跃**的（包住=1 / 不包=0），2 环扩散对几千顶点的低模够用，
但对本项目 15k 面级别的角色，关节处仍会看到折角。

建议：迭代次数与 λ 提到 UI（或 `.meta.json`），默认提到 4~6 次，
并考虑**按测地距离加权**而非纯平均（避免跨薄壁扩散，比如胸腔两侧互相污染）。

### 2.5 平滑邻接靠三角面索引 → 描边模型的硬边会切断扩散

`smoothSkinWeights` 的邻接由 `indices` 构建。若模型带 **split normal / 硬边拆点**
（美漫描边风格模型的常态），裂缝两侧是**不同顶点索引**，邻接图在此断开 →
描边硬边处的蒙皮平滑断裂，出现「裂缝两侧各跟各的骨」。

建议：邻接构建时按**坐标量化（如 1e-4 m）合并**顶点位置，让位置重合但索引不同的顶点
互为邻居。项目里 `mirrorSkinWeights` 已经在用坐标量化配对（`skin-proxy.ts:304`），
同一套思路可以直接复用。

### 2.6 没有 Undo / Redo

grep `undo|redo` 在 binding 模块**零命中**。绑定是高度试错的工作
（拖 27 个关节、调 66 个半径），没有 Ctrl+Z 意味着一次误拖可能要重来。
「重置」按钮还会整体清空（虽然有确认，但确认不是撤销）。

建议：至少做一个 `positions` + `cylinders` 的状态快照栈（JSON 深拷贝即可，
27 关节 + 22 圆柱体，单帧快照 < 10 KB，存 50 步完全无压力），Ctrl+Z / Ctrl+Shift+Z。

### 2.7 没有任何「预算 / 质量数字」

技美的铁律是**艺术家用数字工作**。当前面板只有「顶点 / 面 / KB / 最大姿态偏移 / 身高」，
`BindExportStats` 里其实**已经算好了** `zeroWeightVerts / tipWeightSum / offAxisBones`，
但那些只进了 console.log 和导出后的一行文本，**编辑期完全看不到**。

建议在面板常驻一个诊断条：

```
影响骨数 22 · 零权重顶点 0 · >4 影响 0 · 未被包裹顶点 312 (⚠ 硬权重兜底)
选中 LeftUpLeg: 影响 1843 顶点 · 平均权重 0.71 · 最大 1.00
```

「未被包裹顶点数」这个数字一出来，2.1 的问题就从隐形变成可见。

## 3. P1 缺陷（UI 面板）

### 3.1 头部 12 个控件平铺，无分组无层次

`.bd-head` 一行里塞了：2 个模式按钮 + 「显示」下拉 + 镜像 L→R + 镜像 R→L +
重置 + 保存绑定 + Bind Skin + Detach Skin + 载入 BVH + 导出动画 GLB + ✕。
`flex-wrap: wrap` 意味着窄屏下会折成两行甚至三行，且**破坏性操作（重置 / Detach）
与常用操作（镜像）视觉权重接近**（只有颜色差异）。

建议：按「编辑 / 镜像 / 姿态 / 产出 / 持久化」分 4~5 组，组间加竖分隔线；
`重置` 与 `Detach Skin` 加二次确认并降级为次要样式。

### 3.2 半径滑块无数值输入、无键盘微调

```html
<input type="range" min="0.01" max="0.6" step="0.005" data-bd="r-top">
```

- 只有滑块，**没有数字输入框** —— 想精确设 0.085 只能拖；
- **没有键盘微调**，而骨骼编辑有 `NUDGE_STEP / NUDGE_STEP_FINE`（方向键 2cm / Shift 5mm）；
- `max="0.6"` 对 2 m 高角色过大（半径 0.6 m = 直径 1.2 m），浪费 2/3 行程。

建议：滑块旁加数字框（可输入 + 方向键步进 0.005/0.001），
max 按模型身高自适应（如 0.35 × 骨长 × 3）。

### 3.3 「镜像此圆柱 → 对侧」默认 disabled，无原因说明

```html
<button class="bd-btn" data-bd="cyl-mirror" disabled>镜像此圆柱 → 对侧</button>
```

新用户不知道是「选中圆柱后可用」还是「功能未实现」。
建议：disabled 时给 `title` 说明触发条件（如「先选中一个非中轴骨的包裹器」）。

### 3.4 「在 3D 视图显示包裹器」是全局显示项，却埋在 Skin 子面板底部

它控制的是**主 3D 视口**的叠加层（全局），却放在局部属性区最后。
建议移到头部「显示」下拉旁边，与「显示（全部/仅中轴/隐藏左右）」归为一组。

### 3.5 帮助文本 8 行纯文字堆砌

`.bd-tip` 里塞了 8 行操作说明（拖拽 / Shift / 方向键 / 骨长 / 偏移 / Bind / Detach / Bind 预览），
且**始终显示**、占掉侧栏大量垂直空间。
建议：折叠为「?」帮助入口，或改成按当前模式显示 2~3 条的**情景化提示**。

### 3.6 缺少「结果未落盘」的持久提示

按项目约定（`.meta.rig` 只存装配方，绑定结果随导出 GLB 落盘），
存在「面板里看着绑好了、其实没导出」的状态。UI 上没有对应的常驻提示。
建议在未导出时，`Bind Skin` 按钮旁显示一个「● 未导出」标记，导出后转绿。

## 4. P2 / 流程层建议

1. **骨架现状确认**：当前是 **27 骨 = 22 骨干 + 5 tip**（`HeadTip` / `LeftHandTip` /
   `RightHandTip` / `LeftToeTip` / `RightToeTip`）。注意 tip 数量已从 4 增加到 5
   （新增 `HeadTip`）。22 根影响骨 × 4 权重 / 顶点，对移动端 skin 矩阵预算是健康的，
   但**面板上没显示骨骼预算**，建议补上。
2. **无 LOD 环节**：技美铁律是 hero mesh 必须有 LOD 链。蒙皮阶段不做 LOD 可以理解，
   但建议在绑定产出后自动跑一次「LOD 权重重采样」检查（LOD 减面后 4 影响会退化）。
3. **命名与校验规范**：建议加一条导入期校验（骨骼命名 / 单位 / 朝上轴 / 顶点焊接状态），
   在**导入时**拦住，而不是等到蒙皮出问题才发现 —— 与项目「门禁前置」的思路一致。
4. **绑定参数应进 `.meta.json` 并进版本控制**：目前 `falloff / eps / smoothIters /
   smoothLambda / 半径系数 0.35` 全是代码常量。改一次代码，历史资产全部不可复现。
   建议随 `bindingEditor` 一起存一份 `bindParams`。

## 5. 建议的修复顺序

| 顺序 | 项 | 成本 | 收益 |
|---|---|---|---|
| 1 | 修 `smoothSkinWeights` 按 joint id 聚合（P0-1） | 小（~30 行） | 消除错骨权重，立竿见影 |
| 2 | 权重算法显式化 + 参数外置（P0-2） | 小 | 消除死代码与隐式行为 |
| 3 | 权重热力图（P0-3） | 中 | 让所有后续调参变得可验证 |
| 4 | 诊断数字条（§2.7） | 小 | 把隐形问题变成可见数字 |
| 5 | 包裹体外软衰减 + 归一化穿透深度（§2.1 / §2.2） | 小 | 消除硬边接缝 |
| 6 | Undo/Redo（§2.6） | 中 | 试错成本大幅下降 |
| 7 | 变形预览 / 姿势测试（§1.3） | 中 | 蒙皮质量的最终判据 |
| 8 | UI 分组、数字输入、键盘微调（§3） | 中 | 手感与效率 |
