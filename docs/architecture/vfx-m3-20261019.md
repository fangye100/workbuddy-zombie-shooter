# M3 持续与动作 VFX：作者流程、验证及 M4 决策

日期：2026-10-19。开发基线 `7e211a01a00f28bddc21b1502d051b2e057eda65`，本轮生产/资产开发验证快照 `b863c1e4f42c011eb6939d69c932040dcb34ed3e`。本指南记录 Worker 开发结果，独立 Audit 与 Final Reviewer 尚待 Main 调度；不等于独立验收批准。历史 [M1](vfx-m1-20261019.md)、[M2](vfx-m2-20261019.md) 结论保留原提交与时间；分期依据为 [原 proposal](vfx-system-proposal-20261019.md)。

## 真源与职责

[scene/vfx.ts](../../packages/scene/src/vfx.ts) 定义资源 v3：通用 emission（rate/maxParticles/speed/spreadDeg）和归一化 size/color/alpha 曲线，每条2–8点、t严格递增且首尾0/1。数值有范围和有限性检查，坏曲线拒绝；颜色曲线在线性空间插值并乘资源全局 tint。v1/v2 显式兼容读取，编辑值迁移到 v3，raw 磁盘对象仍独立作 CAS 基准，只有保存才升级。正式 M1/M2 资源盘上仍为 v1/v2，编辑器/Play/门禁有兼容提示，未来版本拒绝。

scene v17 新增通用 `VfxEmitter`（enabled/playing、带GUID的资源、effectKey、uint32 seed、本地方向）；16→17 迁移不补造组件，原19个场景只升版本。发射位置/方向来自节点世界变换，surface 朝向来自作者节点本地上轴的世界变换。Framework 不认识 flame/charge/burn 等游戏含义。组件引用进入场景门禁、typed path 遍历和重命名安全边界；未知/缺失 effect key、坏资源有可定位诊断。

[runtime/vfx-emitter.ts](../../packages/runtime/src/vfx-emitter.ts) 负责固定tick、种子和有界装饰发射。每manager最多32个handle，资源单发射器上限1–128粒子、rate最高120/s；游戏与作者发射器共享原256实例池、原16纹理预算。单次catchup最多处理240tick并计tickOverflow；无新tick不发射。stop只停止新生粒子，尾粒子自然到期；同key重启复用handle并分配新的单调epoch，idle淘汰后重建同key也不会与池seen/尾粒子键碰撞。handleOverflow/dropped/started/stopped/restarted可观察，历史有界。

[WeaponVfxFrames](../../packages/zombie-game/src/weapon-vfx-frames.ts) 在模拟tick末捕获只读火焰锚点/真实攻击方向、燃烧actor身份代次/位置，队列2048上限。它与可见武器共同使用 [weapon-marker.ts](../../packages/zombie-game/src/weapon-marker.ts)，没有用高度差或新增固定偏移修枪口。没有相关状态时不复制全体actor视图。WeaponCombat 的不可变完整效果队列记录 flame/slash 等实际效果，避免只读已过期 mutable effects；EnemyAttacks为charge逐tick记录实际move快照。所有伤害、轨迹和攻击时序仍由原模拟持有。

[ContinuousVfxPlanner](../../packages/zombie-game/src/presentation/continuous-vfx-planner.ts) 解释游戏 opaque tags：weapon.flame、actor.smoke、combat.spark、enemy.charge.trail、combat.melee。火焰按原 AreaWeapon 的有效效果开始/结束，handle种子固定；燃烧烟读取匹配generation的快照，死亡/槽复用不会贴到新actor。冲锋粒子按每个真实move点发射，近战弧线按实际from/to/radius定向；enemy melee快照的hit=false不当作真实命中证明，挥空也可有弧线。真实手枪trace接触触发spark，使用接触点和法线，不用HUD星花代替。

[PlayVfx](../../apps/editor/src/services/play-vfx.ts) 与 [AuthoredVfx](../../apps/editor/src/services/authored-vfx.ts) 仅装配，复用同一 VfxPass/PlaySession资源账目及旧run异步generation防护。render通用层只采样velocity、朝向及曲线，不计算游戏规则。Alpha按动画后实际位置远到近排序，继续只合批连续兼容实例，depth test/write、premul/sRGB/aux衰减沿用M1/M2。缺资源/纹理/预算时不宣称GPU替换成功，Canvas保底和真实危险轮廓保留。

## 正式内容和产品操作

[comic-motion.vfx.json](../../assets/vfx/comic-motion.vfx.json) 及五张三帧原创透明SVG（flame/smoke/spark/dust/arc）是本轮最小正式资源，帧形变不同；没有启用旧隔离图集或使用未跟踪素材。现有程序武器/胶囊与HUD不算新VFX美术交付。

固定HTTPS5100的已登记场景：`assets/scenes/sandbox/vfx-m3-flame.scene.json`、`vfx-m3-charge.scene.json`、`vfx-m3-melee.scene.json`、`vfx-m3-author.scene.json`。前三者分别选择原prototype flame、真实E-04、原chainsaw+真实E-01；数值复制既有武器/敌人真源，不添加玩法公式。均保留interact未清关条件以观察尾部。作者场景有5个组件发射节点且无干扰NPC。地面Collider不加入移动战斗fixture，避免现有导航将整块地面投影为XZ障碍；作者预览只用起点下小接收面，战斗弧线的地平面法线来自模拟，不能误报Collider接收者。

1. Inspector「场景」→「作者 VFX · 持续发射器」：选稳定发射节点、正式资源→读取、effect key、seed、本地方向、进入Play时发射；Apply/Undo/Redo、移除及保存发射场景。配置只存组件，整页reload从盘恢复。Play中锁定作者表单，停止后编辑playing决定下次Play是否发射。
2. 原资源面板选择 `comic-motion.vfx.json`，可调发射率、速度、散角、单发射器上限、尺寸/颜色/透明度曲线JSON和原尺寸/颜色/时长/朝向。Apply/Undo/Redo与资产独立Save/Reload；坏曲线提示错误，CAS保留草稿，显式Reload才丢弃草稿采用磁盘内容。资源duration仍只控制装饰粒子/周期，不改伤害范围与危险时长。
3. 预览选择当前效果、seed，可「预览启动暂停」→「循环 GPU 预览」→「预览单步」或「预览暂停/继续」，「固定种子重播」从tick0重播。固定30Hz，单步15次后重播同seed/参数15次，粒子位置/速度/age/seed一致；ownership epoch可变化，不影响图形。surface预览仍需要真实场景接收面，缺失则诊断。
4. Play flame后真实鼠标瞄准、J开火，松开停止、再次按键重启；武器选择器可真实切pistol射击观察新GPU火花。charge由原NPC状态机触发，melee由真实J/chainsaw触发。暂停/单步/重开/Stop沿原控件。统计含continuous的sourceFrames、events、handles、实例、overflow/fallback及GPU draw/upload/销毁；作者独立统计在authored字段。

## 成本与预算口径

轻量路径在同一暂停真实火焰场景只关闭/开启已有Pass：24实例，3个VFX draw，上传1984bytes。每模式4次热身+20样本，CPU为RendererCore.drawFrame提交侧JS wall-time，GPU为真正timestamp-query的scene开始→post结束，**不是VFX单Pass耗时**。

| 场景/指标（均值 / p95） | 关闭 | 开启 |
| --- | --- | --- |
| 真实火焰 CPU提交 ms | 0.1300 / 0.2000 | 0.2500 / 0.4000 |
| 真实火焰 GPU scene→post ms | 1.5394 / 2.0746 | 1.7250 / 2.1975 |
| 真实火焰 总draw | 10 | 13 |
| 256实例受控压力 CPU提交 ms | 0.1250 / 0.2000 | 0.8700 / 1.5000 |
| 256实例受控压力 GPU scene→post ms | 0.9876 / 2.7197 | 1.1403 / 2.2313 |
| 256实例受控压力 总draw | 8 | 9 |

压力输入只在暂停作者场景使用：4个验证发射器×120/s、各上限128、装饰寿命2s、120个固定tick，共享池256；发出512、过期256、丢弃1408，最终active256，真实上传20544bytes/帧、一个兼容VFX draw。它验证饱和限流与成本，不是新增游戏玩法，也不认证超预算粒子的视觉完整性。另分测CPU区间如下（120样本，wall-time、不是GPU时间）：

| CPU区间 | 均值 ms | p95 ms |
| --- | --- | --- |
| pool.advance | 0.0083 | 0.1000 |
| 4个Emitter.update | 0.5675 | 0.9000 |
| 暂停现有PlayVfx planner遍历（无新模拟事实） | 0.0183 | 0.1000 |

JS计时存在量化，GPU/CPU样本会受调度和温度影响；旧开发轮出现GPU on小于off，不能推断提速/零成本。CPU planner区间只认证暂停遍历，不冒充完整模拟/繁忙事实消费成本。所有结果限于本机Lovelace和这两个有界输入，不外推手机、500NPC或任意粒子数。

## M4 逐项决策

本轮**暂缓实施下列五项**，不是永久拒绝。决定依据是本阶段正式资源/作者需求及上述接近共享预算的实际测量，不以两个sprite或“索引调用少”推断无瓶颈；后续达到对应需求/证据条件再立独立单元。

| M4项目 | 当前需求、前提与实证 | 决策与触发实施条件 |
| --- | --- | --- |
| GPU模拟 | 当前5类资源为短寿命CPU定向sprite/弧线。256实例压力的CPU发射约0.57ms/tick、提交均值约0.87ms，上传约20KiB；没有采集到当前真实场景被粒子模拟占满帧预算的证据。GPU timestamp为整个scene→post，不能将其差值当compute收益。 | 暂缓。先在明确目标设备/帧预算和实际需要超过256并发的内容中复现持续CPU发射/曲线或上传瓶颈；分别profiling后再决定compute是否比缓存曲线/合批等更合适。 |
| 复杂Ribbon | charge逐tick真实路径配重叠尘sprite，`05-charge.png`可见短尘尾；目前没有长丝带、扭带、UV沿程连续或跨多段连接的正式资产需求。现契约是独立quad，不存在可直接启用的连带拓扑。 | 暂缓。需要可见长带连续边缘、当前独立粒子间隙/转弯接缝成为具体缺陷时，另建受限路径历史/切线/UV和预算测试，而非将M3尘尾称作Ribbon。 |
| soft particles | 当前漫画纹理为墨边透明切片，已核对墙前后深度/交界画面，没有将硬切片描述成柔性交界。`RendererCore.resize`的depth24plus仅有RENDER_ATTACHMENT usage，VFX只load depthStencil；HDR/aux的TEXTURE_BINDING不等于深度可采样。 | 暂缓。若后续正式烟雾/火焰需要柔和穿地/墙交界并出现可复现硬边缺陷，先设计可采样深度、重建/比较与对应测试，再评估soft fade；当前不存在已就绪的soft-depth通道。 |
| 跨面贴花 | 当前弧线/痕迹只用明确平面，未出现需绕墙角/跨台阶投影的正式M3资源。当前surface quad+深度测试无法替代projector/DBuffer，也未存接收几何范围。 | 暂缓。出现必须跨不同法线表面、quad裁切无法满足的正式痕迹需求时，再定义接收层/体积/生命周期与遮挡、跨角测试，不自动将所有平面效果改投影。 |
| 节点编辑器 | 当前五效果可用参数/2–8点曲线JSON、Apply/Undo/Redo/独立Save/CAS和固定seed预览复现，真实UI保存路径已验证。尚无需要可组合算子拓扑、多人复用子图或超出声明式曲线的正式内容。JSON作者体验仍是最小入口，不宣称已有图编辑。 | 暂缓。若正式作者流程反复需要表达当前schema无法表达的组合，并有明确节点/类型/错误定位/编译格式需求，再独立设计图真源、版本迁移和UI；不因资源项增多直接堆通用节点系统。 |

尚未认证的边界：真实游戏路径的逐tick确定性在有界无溢出输入下测试；资源/池溢出属于显式降级，不承诺任意不同消费分组在过载时视觉完全一致。当前没有compute、Ribbon、soft depth、跨面projector或node graph实现，后续不将本轮暂缓决定当作这些能力已交付。
