## 1. 已确认目标与首期边界

用户确认采用离线预破碎资产，并要求部分碎块在游戏运行时做真实三维物理模拟。两项工作分别是：

- **离线处理几何**：把完整模型拆成稳定编号的碎块，完成切口封面、内部材质、局部变换、碰撞代理和来源记录。
- **实时模拟运动**：命中发生后，根据实际接触、冲量和环境，计算碎块的三轴平移、旋转、碰撞、翻滚、落地和休眠。飞散方向与最终位置不是固定播放的动画。

首期交付一个可击碎物体和一个 NPC 致死碎裂的产品闭环，包括正式资产、场景配置、实际武器触发、真实刚体、编辑预览、保存重载、运行预算和 Stop 恢复。目标物体及 NPC 的最终稳定资产 ID 在 WU-02 依据现有可用、获准资产确定并汇报；不能拿程序占位物冒充正式美术验收。

**真实刚体路径是首期必需能力。** 简化运动的小碎块与 GPU 烟尘用于分配成本，不能替代全部真实刚体。首期也不承诺任意位置实时切割、任意模型自动断肢、完整 ragdoll、建筑结构坍塌或碎块再次无限递归破碎。

首期 NPC 只要求配置允许的致死碎裂。普通受击、未配置 NPC、持续燃烧及资源失败时继续原行为。存活状态下断肢、部位伤害、断腿影响 AI 等属于后续玩法契约，本期不擅自加入。

## 3. 架构与复用约束

### 3.1 所有权

| Owner | 本次责任 | 不应承担 |
|---|---|---|
| scene | 破碎资产/组件、稳定引用、校验、迁移、项目登记契约 | 物理世界和游戏伤害计算 |
| runtime | 通用碎片播放、固定步长、预算、句柄、物理后端适配 | 僵尸奖励、NPC 死亡条件、编辑器 DOM |
| render | 原动态网格机制的刚体变换扩展、实例打包、实际 GPU 生命周期 | 修改玩法血量、碰撞或导航状态 |
| zombie-game 内核 | 实际物体损坏、NPC 触发策略、一次性状态转换、碰撞/导航更新 | 直接创建 GPU/DOM 对象 |
| zombie-game 表现层 | 真实破碎事实到通用播放请求；选择原死亡动画或碎裂表现 | 再维护一份 NPC HP/死亡/奖励状态 |
| editor/宿主 | 既有 Inspector/资产入口扩展、预览、历史、保存、资产加载和姿态适配 | 第二套破碎模拟或武器玩法公式 |
| tools/资产制作 | 可重建的离线预破碎、封口、碰撞代理与验收报告 | 在游戏运行时用离线工具切模型 |

跨包经公共 `@aether` 入口；依赖清单遵循 `docs/architecture/layers.md`。没有合适原责任模块的全新能力可以建立聚焦模块；已有职责必须在原模块修改或局部抽离，不能以新文件、共享外壳或复制代码冒充复用。

### 3.2 两条事实链

```text
物体：真实武器接触 → 原伤害分发接线 → 物体损坏状态转换
    → 同步碰撞/导航状态 → 一次性破碎事实 → 通用碎片播放＋原 VFX

NPC：原 applyDamage → 原 kill/defeated 快照 → 配置允许的死亡表现决策
    → 原显示姿态快照 → 通用碎片播放＋原 VFX
```

游戏状态不等待 GPU 读回决定；碎块位置和粒子计数不能反向计算伤害、掉落或通关。物理碎片默认是装饰，不阻挡 NPC、不造成二次伤害、不参与奖励。若未来残骸要挡路或伤人，必须显式成为受玩法管理的对象，不能套用视觉预算直接淘汰。

### 3.3 身份和发布顺序

- NPC 身份至少为 `runId + slot/id + generation`；场景对象使用稳定 NodeId 加运行会话身份，不用数组下标做持久引用。
- 一次性破碎请求还带稳定事件序号、simulation tick、profile GUID、确定性 seed 和触发来源。散弹多命中、贯穿、爆炸及同 tick 多次伤害不应重复破碎同一对象。
- 普通武器与持续 burn 的来源语义沿既有 `WeaponDamageFacts`/CombatEvent；DOT 不借用同帧直接命中序号。是否允许烧毁或爆炸致碎由配置/游戏策略明确决定。
- 事件必须包含激活所需的不可变位置、世界变换、接触/来向和资产身份，不能在 NPC 槽位回收后再读新代次实体的数据。
- 物体状态先完成可审计的一次性转换，再发布表现事实。碰撞、导航、可见完整模型的切换有统一运行状态，不能靠编辑器临时隐藏对象代表玩法破坏。

## 4. 资产与场景数据契约

### 4.1 独立破碎资产

建议使用版本化 `.fracture.json`，由 scene 拥有格式；这不是把 GPU 缓冲写进 JSON。至少包含以下语义，最终字段和公开类型在 WU-01 固定。

| 数据 | 必须表达的内容 |
|---|---|
| 资产头 | 独立 version、id/name、accepted/quarantined 状态；源文件 sidecar 的 GUID、kind、sourceHash 和来源 |
| 完整模型/碎块集合 | 带 GUID 的 AssetRef；碎块使用稳定 chunkId；集合内部定位使用稳定标识，不依赖导入后的数组顺序 |
| 还原关系 | 统一资产局部坐标下的 bind/local TRS、pivot/质心、体积/质量权重；完整组装时与原模型对齐 |
| 碎块几何 | 外表面和封口/内部表面材质引用、UV/法线、支持的 LOD、静态或保留 skin 权重的块 |
| 物理代理 | 有界 box/sphere/capsule 或离线凸代理；质量、摩擦、恢复系数、初始运动限制及碰撞组策略 |
| NPC 对齐 | 原 actor/rig 的稳定身份、骨骼映射或分块蒙皮信息、归一化尺度与脚底偏移契约 |
| 播放策略 | 大块/小块分类、优先级、寿命/淡出、可选原 VFX 伴随绑定；不包含伤害公式 |

组件只保存 profile AssetRef、触发策略及场景实例覆盖；可复用分块配方和碰撞代理属于资产/sidecar。运行碎块位置、GPU 句柄、物理世界句柄不落场景文件。

同一资源不能同时持久化一份源图和一份独立可编辑的派生碎块状态。未来若节点图编排破碎，只引用 profile 并发出播放请求，不能在图里另存物体 HP 或 NPC 死亡状态。首期不强制增加新的 DAG 节点种类。

### 4.2 场景与 NPC 配置

- 物体建议新增明确的可破坏组件，包含 enabled、profile、最大耐久、允许伤害/触发条件、碰撞与导航关联策略。耐久是初始配置，当前耐久属于 Play runtime 副本。
- NPC 碎裂策略落现有角色定义/可复用 actor profile 的合适真源；场景特有覆盖落场景。普通 NPC 无配置时继续现有死亡行为。
- 若新增 scene 字段需要升版，则由当前 v23 连续增加迁移与 owner 测试，并扫描所有精确断言迁移链的旧测试。不要只升级常量，也不要重排已发布迁移。
- 场景里的模型/profile 引用必须同时保存 GUID/path。devfs 的读取、保存、移动/改名、sourceHash 更新和跨文件校验都要认识新资源及内部 typed refs。
- 文件版本过高、断引用、重复 chunkId、空/坏凸代理、NaN/负质量、非法尺度和超预算必须明确 diagnostic，禁止静默丢块后当作资产成功。

### 4.3 资源准入和失败恢复

沿现有资源加载/sidecar 准入责任扩展。每次 Preview/Play 激活核对源与 sidecar 的 GUID/kind/status，受影响的路径共用规则；编辑草稿的编译内容与磁盘准入身份分别处理。

隔离资产或错 GUID 必须在 GPU/物理对象分配前拒绝，保留作者草稿。已经打开面板后修改 sidecar 状态，下一次播放仍须重新检查；恢复 accepted 后可以恢复预览。异步 source/meta/模型/WASM 完成后必须核对 session generation，Stop 或换场景后的迟到结果不能分配资源或覆盖新预览。

## 5. 离线预破碎技术与美术验收

1. 先核对正式完整资产、许可证/来源、LFS 实体和 sidecar，再制作对应碎块，不自动下载未知来源资产或恢复归档工具。
2. 首个物体采用易审计的木箱/罐体等结构，选择与外观一致的预切分；允许手工创作或可复建工具生成，不要求首期实现通用 Voronoi 编辑器。
3. NPC 必须选已有正式 rigged actor。离线确定分块边界，保留需要的权重/骨骼映射并封口；不能只按三角形任意删除而留下开壳。
4. 每块检查封闭性、非退化三角形、有限值、法线、外部 UV、封口材质、正确 pivot、凸代理和原始装配关系。焊接边界时保留 UV/法线接缝，不能按位置粗暴合并所有渲染顶点。
5. 左右手系、up 轴、单位、嵌套 TRS、负尺度及 actor 身高归一化只按一条已核对的转换链执行。不能同时在离线导出和 runtime 再缩放一遍。
6. 组合还原图、拆分图和实际 GPU 近景均需保留。NPC 测试至少包含一个非 bind pose 的运动姿态；T-pose 对齐不能证明运行时姿态衔接正确。
7. 不能可靠处理的非流形/坏权重/不可逆变换应拒绝并给出资产级错误，不偷偷换成胶囊碎块计为正式验收。

模型/纹理二进制遵循 Git LFS；离线脚本、输入版本、参数、输出摘要和 sidecar 一并交付。运行场景只引用资产，不内联几何。

## 6. 真实三维物理与简化碎片

### 6.1 真实刚体后端

首选评估 Rapier 3D JavaScript/WASM 官方包，通过 runtime 的通用物理适配接口接入。开发时核对可用版本和许可证，使用 pnpm 精确锁定版本并提交 pnpm-lock.yaml；不在文档中假定某版本已安装或已验证。

物理世界只负责被授权的碎片范围，原角色移动、武器射线和导航继续原系统。静态碰撞输入从同一场景/当前 runtime collider 真源生成镜像，不能在后端另造地面、墙体或门的第二份配置。

真实路径必须具有：

- 动态刚体的三轴位置、四元数姿态、线速度和角速度；质量、摩擦、恢复系数实际进入求解。
- 可观察的冲量响应、静态环境接触、大块之间的碰撞、翻滚和落地休眠。不能仅给粒子添加自转便声称刚体完成。
- 简单碰撞形体或离线凸代理；动态碎块不默认使用任意凹三角网格。碰撞代理与显示 mesh 可以不同，但近景穿透误差必须验证。
- 碰撞分组限制：首期与静态环境及选定大块相互作用，不自动撞飞玩家/NPC。CCD 仅对确有穿透风险的快速小刚体启用，不能全量无差别打开。
- 固定 simulation step，支持暂停、单步和有界多 tick 追赶；渲染插值可选，不能反向推进物理时钟。

源 collider 的 transform 转换要核对实际世界矩阵和缩放。非均匀变换的球/胶囊不允许未经说明近似成等比例 collider；可选预生成凸代理或明确拒绝不支持的组合。动态门/破坏物体的镜像必须跟随原 runtime 状态更新，Stop 清理后不留下幽灵 collider。

WASM 模块初始化可以共享代码加载结果，World/body/collider 生命周期仍按 Preview/Play session 隔离。Stop 要移除/释放实际物理资源。WASM allocator 的预留内存不回落不自动等于泄漏；应核活动 world/body/collider、租约和多轮高水位趋势。

### 6.2 冲量与确定性

初始运动由真实来向/爆心、命中点、物体自身速度、碎块质心和 seed 共同生成。大块可按距离/质量分配冲量，命中点偏离质心时允许产生角运动；速度/角速度上限有界。数值系数属于可编辑 profile，不写死在 main.ts。

相同 seed 的随机分配在同输入下可复现。固定 step 不等于承诺不同 CPU、浏览器、物理库版本逐 bit 相同；物理对照明确容差、平台、库版本和比较区间。不要让刚体落点参与当前奖励/AI 随机序列。

### 6.3 简化小块与预算

小块可以使用位置/速度/四元数/角速度的简化积分，复用现有碰撞查询或由后端提供有界环境接触；禁用大规模块间求解。它们仍是有材质、深度遮挡的三维 mesh，不是伪装成 mesh 的平面 sprite。

预算限制运行时活动工作量，不限制资产库离线一共可制作多少块。至少分别统计：真实刚体数、简化块数、事件队列、几何三角形/材质批次、上传字节、CPU update/physics 时间、GPU draw 时间、存活资源与淘汰次数。

可从“每次约 8–16 块、全场 32 个活动真实刚体、256 个简化块、2–4 秒寿命”开始调参。**这些只是待测初值，不是已测性能、验收硬指标或永久上限。** WU-04 提交明确默认值和压力理由，再由实测调整。

满额时按优先级保留近处/新发生/大块，可提前回收低优先级装饰、减少新小块或用原烟尘反馈；必须显式计数和诊断。不能清除仍承担玩法阻挡/伤害的对象来满足视觉预算。至少有足够容量和资产时必须进入真实刚体路径；预算失败不能使所有正常案例永久走简化兼容而仍报功能完成。

碎片 wrapper/私有向量可复用 Core ObjectPool，公开事件快照不可池化后改写。必须先归还本 session 活动租约，再按所属规则释放后端和 GPU；不能把 ObjectPool.dispose() 当成自动回收全部活动对象的替代。

## 7. 动态绘制与 NPC 姿态衔接

### 7.1 在原动态网格机制扩展刚体变换

- 碎块不逐个走静态 addObject/transformBuf，不占 64 个静态场景槽。
- 以现有 CoreDynamicBatch/动态 shader 为责任入口，增加清晰的 rigid transform 数据/模式。当前 20-float 行中的 palette、transition、impactPulse 和 burnClock 均为有效功能，不能占用它们存碎块四元数。
- 可选追加的刚体变换缓冲或有版本的扩展行布局；选型须说明旧角色分支如何原样保留。不能复制一套简化材质/动态渲染器，丢失原光照、纹理、深度、描边或燃烧后宣称升级成功。
- 三维旋转须同步位置与法线变换；同几何/材质复用网格和纹理并合批。不同碎块几何不强行宣称一个 draw，实际提交数与三角形量分别记录。
- 共享资产资源和每次播放资源分开记 owner。Play 期间新增 GPU 分配登记到 PlaySession，Preview 有独立 owner；借用原 Editor core 资源不由碎片 Stop 销毁，也不能因此漏记自身新缓存。

### 7.2 NPC 的关键问题是“从当前姿态拆开”

实体 defeated 快照只有游戏视图，不等于最终蒙皮顶点/矩阵快照。碎块激活必须关联最后可见的同一 run/id/generation 和 tick，并使用原 palette、过渡矩阵、角色局部/世界变换、身高归一化与脚底偏移。

两种资产方案可在 WU-02 明确选一种：分块仍保留原 skin 权重并在触发时冻结同一姿态；或在触发时将这些分块一次性烘焙为当前姿态静态 mesh，再交给刚体。首期推荐优先选择能复用现有 palette 数据且可验证衔接的方案。

一次性 CPU 烘焙必须对照现有蒙皮/pose transition 数学；需要共享求值时先从原责任模块局部抽离，不能维护第二套动画播放器。不能每帧为全部 NPC 读回 GPU 或重建所有三角形。

预览先展示完整姿态，再触发碎裂；激活帧碎块组装位置应在声明容差内覆盖原表面，不能从 T-pose、原点或下一代 NPC 的姿态飞出。成功接管后仅隐藏该身份的完整死亡显示；资产/后端/容量失败时保留原 death 尾部，死亡判定和奖励不回滚、不重复。

## 8. 物体破坏、碰撞与导航

物体状态建议为 intact → broken，一次转换后不再消费同一次致碎为第二次破坏。HP/耐久由游戏 runtime 拥有；NPC 仍使用原 applyDamage，不建通用碎裂 HP 替代它。

射线命中原本可提供 NodeId，新增损坏接线应在原武器策略/WeaponWorld 宿主端完成。散弹、贯穿、投射物和爆炸分别按现有事实处理，不能只接手枪。首期正式案例至少验证直接击中与一次爆炸范围破坏；范围破坏复用实际爆心、距离和遮挡查询，不按屏幕距离或 VFX 粒子重叠计算伤害。

破坏发生后：

1. 原完整物体不再作为可命中的完整 collider；后续射线可穿过已打开空间。
2. 若原物体阻挡导航，复用现有动态阻挡/导航门控机制移除对应阻挡。可破坏障碍不应被永久焊进无法撤销的基础阻挡；不能只删物理镜像而留路径封锁。
3. 独立地面/台阶 collider 保留，不能为移除木箱连带删除地面或相邻墙。
4. 场景作者状态仍 intact；Stop 回滚后完整模型、碰撞和导航恢复。运行破坏状态不写回场景资产。
5. 碎裂播放失败仍给明确 diagnostic，并使用可读保底表现；不能留下不可见完整碰撞体，也不能把失败当作未受到伤害。

## 9. 作者预览、保存与正式例子

沿原组件/资产 Inspector 的责任扩展破碎配置与预览，独立复杂表单可用聚焦模块。新增入口必须可达；不另建一个只有开发探针能调用的“破碎编辑器”。

作者能选择 profile、设置触发和运动/预算参数、Apply、Undo/Redo、保存资产与场景、整页重载。复用原 CAS、sidecar hash 和文件事务。非法输入保留原配置及当前未应用草稿，不静默钳制后覆盖作者输入。

Preview 使用场景中真实被选对象/actor 的锚点、姿态和原静态碰撞输入，支持触发、暂停、单步、重播和 Stop。预览不减真实游戏 HP，不改关卡状态；Play 消费实际游戏伤害。物理求解和 mesh 绘制共用同一正式实现，不为 Preview 复制一个更简单的运动系统。

新增正式场景登记进 aether.project.json，能够从场景选择器打开。首期至少提供：可破坏物体/墙角与地面、配置 NPC、可真实触发的武器、未配置对照对象；保留现有 M1–M4 和 Act1 入口。

## 11. 验收矩阵与测量口径

### 11.1 数据及失败路径

覆盖合法正式资产、旧版本迁移、未来版本拒绝、重复 chunkId/断 GUID/坏凸代理/非法数值、资产隔离及恢复、CAS 外改、作者草稿保留。验证 typed refs 的移动/改名和 sidecar sourceHash 同事务更新；只改 JSON、UI 看似成功不足以通过。

### 11.2 真实物理与画面

证明大块实际使用真实后端的 body/collider，动量/姿态变化对应物理 step，有地面/墙/块间接触和休眠。使用两个不同入射方向/冲量观察不同轨迹，并记录后端状态与同帧真实画面。不能以任意曲线动画冒充物理。

headed 真实 GPU 核对切面、材质、全三轴旋转、深度遮挡、描边和 NPC 姿态衔接。正常玩法原生输入与受控碰撞/压力输入分开记录；不要用注入 kill 或搬运实体的探针替代正式真实武器路径。

### 11.3 生命周期与玩法

Pause 不推进；Step 恰推进固定 tick；多 tick 消费不重复爆碎；重开/Stop/显式切场景无旧代复活。覆盖异步模型、meta 和 WASM 初始化在 Stop 后完成的情况。

多轮激活/回收/Stop 检查实际 body/collider/world 数、池 active、GPU buffer/texture destroy 及所属 session 的 ledger；不只检查前端计数。确认 NPC 死亡、奖励、原 burn/命中、物体碰撞/导航和作者回滚没有变化或重复执行。

### 11.4 成本

同场景同输入分别记录关闭、简化碎块、真实刚体三种模式。CPU 分开记录事实规划/一次性姿态烘焙、物理 step、简化积分和 render 提交；GPU 使用明确 timestamp 区间并记录样本数/暖机，不能把 scene→post 当碎片单 pass。

增加并发破坏直至配置预算，报告真实/简化数量、三角形/材质批次/draw、上传量、回收与溢出次数，以及卡顿峰值。休眠后资源占用和 Stop 后存活数分别测量；本机 NVIDIA 结果不外推手机或其他硬件，不预先承诺“GPU 一定更快”。

### 11.5 原能力回归与去重

按实际影响保留七武器、NPC 原 hit/death/transition/burn、M4 compute/Ribbon/soft/贴花/图编辑和 Act1 的已有用户路径。可复用未受影响同版本证据，但必须说明提交/路径；共享加载器、shader 或实例布局变化时相应原功能必须实际回归。

交付前列出本次新增的模拟、渲染、资产加载、预览入口，证明每项正式职责只有一个实现；清除本次产生的平行简化实现，保留原能力和历史证据。不要以新增“高级模式”隐藏旧功能丢失。
