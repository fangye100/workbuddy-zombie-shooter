# VFX 系统开发 Proposal

归档日期：2026-10-19（Asia/Singapore）。以下完整保留主 chat 中的 proposal 正文；现状、验证范围和“本轮”等表述均对应原 proposal 的分析快照，不代表后续实现或验收完成。文件链接改为仓库相对链接，便于在仓库中阅读。

---

建议把 VFX 建成**数据驱动的通用运行与渲染能力**，首期交付“枪口闪光 → 弹道 → 命中”的完整闭环，再接入酸液、爆炸和持续粒子。

本 proposal 基于当前主检出目录、分支 `codex/architecture-boundaries-20261009`、提交 `6b486f0` 及现有工作区源码；本轮未修改业务文件，也未执行运行验收。

**当前基础与缺口**

| 方面 | 当前状态 | 对 VFX 开发的影响 |
|---|---|---|
| 战斗表现 | 枪火、弹道、命中和敌人攻击主要通过 [CombatOverlay](../../packages/zombie-game/src/presentation/combat-overlay.ts) 绘制 Canvas | 已有事件接入基础，但缺少场景深度遮挡 |
| 渲染器 | 自定义 WebGPU/WGSL，RendererCore 直接组织 Pass | 新增专门的 VFX 绘制阶段；当前不以 FrameGraph 改造为前置 |
| 武器配置 | 已有 `muzzle/trail/impact/resource` [字段](../../packages/scene/src/weapons.ts) | 可沿用已有入口，补全资源解析与播放契约 |
| 命中信息 | [WeaponHit](../../packages/runtime/src/weapon-combat.ts) 目前只有目标、位置和距离 | 墙面弹孔、定向火花还需要表面法线、接收者身份及明确命中类型 |
| 特效资源 | `VFX-ATLAS-01` [仍处于隔离状态](../../assets/art/textures/VFX-ATLAS-01/VFX-ATLAS-01.png.meta.json)，记录有残底、裁切和序列质量问题 | 资源验收必须单独推进，不能把图集存在视为可用 |
| 场景契约 | schema v15，尚无正式 VFXEmitter、Decal 组件闭环 | 作者配置、保存重载与迁移属于系统交付的一部分 |

**建议的职责划分**

| 位置 | 建议承担的职责 |
|---|---|
| `packages/scene` | 特效资产格式、引用与校验；作者发射器/贴花组件及迁移 |
| `packages/runtime` | 通用播放实例、发射计时、有界对象池、种子随机、暂停与回收 |
| `packages/render` | Billboard、定向 Quad、弹道条带、平面贴花的实例化绘制及 GPU 资源 |
| `packages/zombie-game` 表现层 | 将开火、命中、酸池等游戏事实转换成特效播放请求 |
| `apps/editor` | 资产选择、参数编辑、预览、保存和诊断；装配游戏表现与渲染接口 |
| `assets/vfx`（拟新增） | 可复用特效定义和已验收的纹理资源 |

数据流为：

`游戏事实 → VFX 表现规划 → 通用播放实例 → GPU 绘制`

伤害、弹丸轨迹、酸池范围与生效时间仍由游戏模拟决定；VFX 只消费这些事实。

**数据与播放契约**

建议采用三层数据：

- **特效资产**：独立、版本化的 `.vfx.json`，描述纹理/帧序列、尺寸、颜色、透明度、朝向、混合方式、持续时间和发射参数。源资产与 sidecar 保留 GUID、导入设置及验收状态。
- **场景配置**：保存带 GUID 的 AssetRef、效果绑定和作者摆放的发射器；新增组件同步补 schema 迁移、校验与编辑历史。
- **运行实例**：保存播放句柄、种子、出生 tick、锚点和生命周期，仅存在于当前运行会话。

事件接入需要先补两个关键点：

1. **稳定身份与完整消费。** 一次性效果使用 `runId + sequence` 等稳定标识去重；持续效果使用稳定 handle 更新/停止。处理同帧多个模拟 tick，避免漏播、重播，以及一次散弹开火生成多个枪口闪光。
2. **命中快照。** 区分实体命中、场景命中和未命中；记录实际接触点，场景命中补接收者 NodeId、法线。击杀后的表现读取快照，防止槽位复用后跳到其他 NPC。

枪口位置也要核对角色装配、武器 marker 与实际显示结果，确保闪光贴住可见枪口；不以新增固定偏移掩盖坐标差异。

**渲染方案**

首期建议采用 **CPU 管理播放与少量粒子状态，GPU 实例化绘制**。这样容易验证确定性、暂停和回收；后续根据测量决定是否增加 compute 模拟。

在当前场景绘制结束后、后处理之前增加 VFX 阶段，复用场景深度：

- 开启深度测试、关闭深度写入，让墙体和角色正确遮挡特效。
- 支持面向相机、轴向约束、表面对齐三种朝向。
- Alpha 效果按相机深度排序，再对连续兼容实例合批；Additive 使用独立管线。
- 明确纹理色彩空间、alpha 约定及描边 mask 合成，验证黑边、串格和透明矩形。
- 通过独立动态实例缓冲承载效果，不占用 64 个静态物件槽位。

首期平面贴花只覆盖明确的平面接收面。跨墙角投影、屏幕空间贴花和 soft particles 后置；当前深度纹理尚未提供采样用途，不能直接假定这些能力可接入。

**分阶段交付**

| 阶段 | 范围 | 可验收结果 |
|---|---|---|
| **M1：基础闭环** | 特效资产契约、枪口闪光、弹道、命中；池化；最小预览与绑定编辑 | 手枪实际 Play 可见，正确遮挡；配置保存重载；暂停/单步/Stop 正确 |
| **M2：敌人与地面效果** | 酸液飞行→落地→酸池；自爆；突扑冲击；平面痕迹 | 表现跟随真实攻击阶段、位置、半径与结束时间 |
| **M3：持续发射与丰富表现** | 火焰、烟尘、火花、冲锋拖尾、近战弧线；尺寸/颜色曲线 | 持续启停稳定，多效果并发可控，编辑器可调参与复现 |
| **M4：按测量扩展** | GPU 模拟、复杂 Ribbon、soft particles、跨面贴花、节点编辑器 | 由具体效果需求和目标设备瓶颈决定实施范围 |

M1 同时验收少量正式枪火、命中资源；开发期可以使用显式标注的程序占位效果，但占位效果不计入美术验收。

**容量、失败行为与验收**

所有阶段都应具备实例/粒子/纹理预算。满池时按优先级限流，并报告丢弃数；装饰性烟尘可优先降级，危险范围提示必须保留可读的保底表现。坏引用、非法帧索引和隔离资源产生明确诊断。

验收覆盖四条路径：

- **数据**：创建、编辑、Undo/Redo、保存、重载；旧版本迁移与坏资源诊断。
- **行为**：连射、散弹、同帧多命中、实体死亡/槽位复用、暂停、单步、重开和换场景。
- **视觉**：headed 真实 GPU 下检查遮挡、枪口对齐、透明边缘、远距离采样、排序和 HDR/描边。
- **成本与生命周期**：同场景同输入比较关闭/开启 VFX 的 CPU/GPU 帧时、draw call、实例数和上传量；反复 Play/Stop 核对实际资源释放。

跨层变更运行 `architecture:check`，资产与场景变更运行 `scene:check`，并运行对应 owner 测试。性能目标在首期基线测量后确定，桌面结果不外推到手机。

**建议首个开发单元限定为 M1：手枪三件套 + 最小资产编辑预览 + 持久化与生命周期闭环。** 这一单元能同时验证事件、资源、渲染和编辑器接入，为后续敌人效果与粒子系统提供可复用基础。
