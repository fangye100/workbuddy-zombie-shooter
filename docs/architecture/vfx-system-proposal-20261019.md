建议把 VFX 建成**数据驱动的通用运行与渲染能力**，首期交付“枪口闪光 → 弹道 → 命中”的完整闭环，再接入酸液、爆炸和持续粒子。

本 proposal 基于当前主检出目录、分支 `codex/architecture-boundaries-20261009`、提交 `6b486f0` 及现有工作区源码；本轮未修改业务文件，也未执行运行验收。

**当前基础与缺口**

| 方面 | 当前状态 | 对 VFX 开发的影响 |
|---|---|---|
| 战斗表现 | 枪火、弹道、命中和敌人攻击主要通过 [CombatOverlay](../../packages/zombie-game/src/presentation/combat-overlay.ts) 绘制 Canvas | 已有事件接入基础，但缺少场景深度遮挡 |
| 渲染器 | 自定义 WebGPU/WGSL，RendererCore 直接组织 Pass | 新增专门的 VFX 绘制阶段；当前不以 FrameGraph 改造为前置 |
| 武器配置 | 已有 `muzzle/trail/impact/resource` [字段](../../packages/scene/src/weapons.ts) | 可沿用已有入口，补全资源解析与播放契约 |
| 命中信息 | [WeaponHit](../../packages/runtime/src/weapon-combat.ts) 目前只有目标、位置和距离 | 墙面弹孔、定向火花还需要表面法线、接收者身份及明确命中类型 |
| 特效资源 | `VFX-ATLAS-01` [仍处于隔离状态](../../assets/art/textures/VFX-ATLAS-01/VFX-ATLAS-01.png.meta.json)，记录有残底、裁切和序列质量问题 | 资源验收必须单独推进，不能把图集存在视为可用 |
| 场景契约 | schema v15，尚无正式 VFXEmitter、Decal 组件闭环 | 作者配置、保存重载与迁移属于系统交付的一部分 |

**建议的职责划分**

| 位置 | 建议承担的职责 |
|---|---|
| `packages/scene` | 特效资产格式、引用与校验；作者发射器/贴花组件及迁移 |
| `packages/runtime` | 通用播放实例、发射计时、有界对象池、种子随机、暂停与回收 |
| `packages/render` | Billboard、定向 Quad、弹道条带、平面贴花的实例化绘制及 GPU 资源 |
| `packages/zombie-game` 表现层 | 将开火、命中、酸池等游戏事实转换成特效播放请求 |
| `apps/editor` | 资产选择、参数编辑、预览、保存和诊断；装配游戏表现与渲染接口 |
| `assets/vfx`（拟新增） | 可复用特效定义和已验收的纹理资源 |

数据流为：

`游戏事实 → VFX 表现规划 → 通用播放实例 → GPU 绘制`

伤害、弹丸轨迹、酸池范围与生效时间仍由游戏模拟决定；VFX 只消费这些事实。

**数据与播放契约**

建议采用三层数据：

- **特效资产**：独立、版本化的 `.vfx.json`，描述纹理/帧序列、尺寸、颜色、透明度、朝向、混合方式、持续时间和发射参数。源资产与 sidecar 保留 GUID、导入设置及验收状态。
- **场景配置**：保存带 GUID 的 AssetRef、效果绑定和作者摆放的发射器；新增组件同步补 schema 迁移、校验与编辑历史。
- **运行实例**：保存播放句柄、种子、出生 tick、锚点和生命周期，仅存在于当前运行会话。

事件接入需要先补两个关键点：

1. **稳定身份与完整消费。** 一次性效果使用 `runId + sequence` 等稳定标识去重；持续效果使用稳定 handle 更新/停止。处理同帧多个模拟 tick，避免漏播、重播，以及一次散弹开火生成多个枪口闪光。
2. **命中快照。** 区分实体命中、场景命中和未命中；记录实际接触点，场景命中补接收者 NodeId、法线。击杀后的表现读取快照，防止槽位复用后跳到其他 NPC。

枪口位置也要核对角色装配、武器 marker 与实际显示结果，确保闪光贴住可见枪口；不以新增固定偏移掩盖坐标差异。

**渲染方案**

首期建议采用 **CPU 管理播放与少量粒子状态，GPU 实例化绘制**。这样容易验证确定性、暂停和回收；后续根据测量决定是否增加 compute 模拟。

在当前场景绘制结束后、后处理之前增加 VFX 阶段，复用场景深度：

- 开启深度测试、关闭深度写入，让墙体和角色正确遮挡特效。
- 支持面向相机、轴向约束、表面对齐三种朝向。
- Alpha 效果按相机深度排序，再对连续兼容实例合批；Additive 使用独立管线。
- 明确纹理色彩空间、alpha 约定及描边 mask 合成，验证黑边、串格和透明矩形。
- 通过独立动态实例缓冲承载效果，不占用 64 个静态物件槽位。

首期平面贴花只覆盖明确的平面接收面。跨墙角投影、屏幕空间贴花和 soft particles 后置；当前深度纹理尚未提供采样用途，不能直接假定这些能力可接入。

**分阶段交付**

| 阶段 | 范围 | 可验收结果 |
|---|---|---|
| **M1：基础闭环** | 特效资产契约、枪口闪光、弹道、命中；池化；最小预览与绑定编辑 | 手枪实际 Play 可见，正确遮挡；配置保存重载；暂停/单步/Stop 正确 |
| **M2：敌人与地面效果** | 酸液飞行→落地→酸池；自爆；突扑冲击；平面痕迹 | 表现跟随真实攻击阶段、位置、半径与结束时间 |
| **M3：持续发射与丰富表现** | 火焰、烟尘、火花、冲锋拖尾、近战弧线；尺寸/颜色曲线 | 持续启停稳定，多效果并发可控，编辑器可调参与复现 |
| **M4：按测量扩展** | GPU 模拟、复杂 Ribbon、soft particles、跨面贴花、节点编辑器 | 由具体效果需求和目标设备瓶颈决定实施范围 |

M1 同时验收少量正式枪火、命中资源；开发期可以使用显式标注的程序占位效果，但占位效果不计入美术验收。

**容量、失败行为与验收**

所有阶段都应具备实例/粒子/纹理预算。满池时按优先级限流，并报告丢弃数；装饰性烟尘可优先降级，危险范围提示必须保留可读的保底表现。坏引用、非法帧索引和隔离资源产生明确诊断。

验收覆盖四条路径：

- **数据**：创建、编辑、Undo/Redo、保存、重载；旧版本迁移与坏资源诊断。
- **行为**：连射、散弹、同帧多命中、实体死亡/槽位复用、暂停、单步、重开和换场景。
- **视觉**：headed 真实 GPU 下检查遮挡、枪口对齐、透明边缘、远距离采样、排序和 HDR/描边。
- **成本与生命周期**：同场景同输入比较关闭/开启 VFX 的 CPU/GPU 帧时、draw call、实例数和上传量；反复 Play/Stop 核对实际资源释放。

跨层变更运行 `architecture:check`，资产与场景变更运行 `scene:check`，并运行对应 owner 测试。性能目标在首期基线测量后确定，桌面结果不外推到手机。

**建议首个开发单元限定为 M1：手枪三件套 + 最小资产编辑预览 + 持久化与生命周期闭环。** 这一单元能同时验证事件、资源、渲染和编辑器接入，为后续敌人效果与粒子系统提供可复用基础。

本轮先通过 CodeGraph 定位，再核对关键源码；索引仍有解析标记及未解析调用，因此上述现状结论以源码为依据。未启动浏览器、运行测试或创建提交。

## M4 全量实施补充（2026-10-19）

### 授权、执行顺序与完成边界

用户在 M1–M3 交付及 M4 暂缓原因说明后追加指令：

> M4 这五项也继续推进，恢复每小时巡检，通知原开发 session 按阶段实现和验收，直到全部完成。

因此 GPU 模拟、复杂 Ribbon、soft particles、跨面贴花、可视节点编辑器五项均进入必须实施的范围。[M3 交付指南](vfx-m3-20261019.md)中的五项暂缓理由与测量保留为历史证据；不将当时暂缓改写为已实施，也不再以“当前需求不足”“尚无瓶颈”代替本次交付。

原开发会话 `01a14fcb-c45d-79e0-982a-e4711f97c0e1` 已确认以下顺序，并沿用现有开发队列、模型配置、独立实操及终审纪律。此表定义交付目标，不表示五项已经完成；各阶段实际状态以固定提交对应的指南、原始验证和独立审查为准。

| 阶段 | 必须交付的能力 | 最小可验收结果 |
|---|---|---|
| **M4.1：GPU 模拟** | 真正的 compute 管线和 GPU 粒子状态演进；有界发射、回收、预算；设备能力诊断或兼容路径 | 真实 GPU 上可运行并可暂停、单步、重开；与 CPU 参考或既有路径核对明确种子/输入下的状态和生命周期；同负载记录 CPU/GPU/上传成本。接口占位、GPU 绘制或未证实的提速不等于 GPU 模拟完成。 |
| **M4.2：连续 Ribbon** | 连续多段拓扑、路径历史、切线与沿程 UV；断开、重启和容量管理 | 在真实运动事实及可达示例中验证直行、转弯、多段连接、断开与重启，检查连续边缘、UV、透明排序及预算；独立 sprite 尘尾不能替代条带。 |
| **M4.3：Soft particles** | 可采样场景深度、深度比较与可调交界衰减；相应资源与重建路径 | 火焰/烟尘穿地及墙体交界呈现可对照的柔和过渡；遮挡、透明排序、视角变化、尺寸/分辨率变化和资源释放正确；参数可编辑、保存并重载。 |
| **M4.4：跨面贴花** | 跨不同法线表面的投影/裁切；明确接收几何或层、投影体积、预算与生命周期 | 在墙角、台阶或其他多接收面上验证真实跨面结果，检查遮挡、范围外排除、接收过滤、坏引用诊断及回收；平面 Quad 不算跨面投影完成。 |
| **M4.5：可视节点编辑器** | 可视节点与连线编辑、类型检查、非法图/循环诊断；版本化声明式图及编译播放 | 用户能通过可达 UI 创建、连接、编辑和删除节点，编译为实际效果并预览；Undo/Redo、保存、整页重载及迁移闭环通过。仅 JSON 文本编辑或不能播放的画布不算完成。 |

每阶段完成实现、独立实操验收、完整终审、提交并推送后，继续下一阶段。常规可逆实现沿已有授权持续推进，不等待重复开工确认；如确实缺少影响产品/架构取舍的用户决定，说明具体问题并等待答复，同时继续不依赖该决定的工作。依赖分析可细分阶段内部单元，不自行删减五项范围。

### 职责、真源与失败行为

- `packages/scene` 拥有新增资产/组件/图格式、稳定引用、校验和迁移；先定义 schema 再接运行时及 UI。场景作者配置持久化，运行句柄和 GPU 状态仅属于会话。每次场景版本升级同步补迁移链及测试。
- `packages/runtime` 拥有通用发射/播放、路径与句柄生命周期及有界预算；`packages/render` 拥有 compute、Ribbon、深度采样/交界衰减、投影绘制及实际 GPU 资源。具体数据接口随阶段契约明确，避免两层重复状态。
- `packages/zombie-game` 表现层继续把真实游戏事实转换成通用请求；伤害、运动、攻击范围和时序仍由游戏模拟决定。`apps/editor` 负责作者流程、预览、诊断和宿主装配，不承担玩法公式。
- 图是声明式数据，使用稳定节点身份和带类型的连接；明确非法图、资源丢失、未来版本与编译失败的诊断及恢复方式。场景和图中不存任意可执行脚本字符串。
- 显式限定粒子、实例、路径段、贴花、纹理、图节点/连线等预算；溢出、设备能力不足和资源错误可观察，危险提示保留可读保底。新增 GPU 分配登记到所属会话，Stop、换场景、重开和异步旧代取消均不得泄漏或复活资源。

### 分阶段验收与持续巡检

五项均须提供正式示例资源、已登记场景或可达产品入口。开发期程序占位与正式视觉验收分别记录，不以接口、构建、下载或单张截图代替实际用户路径。

1. **数据与失败路径**：按阶段覆盖创建/编辑、Undo/Redo、实际保存与整页重载、版本迁移、坏引用/非法参数/非法图、保存冲突和诊断恢复。
2. **行为与生命周期**：核对真实事实与效果锚点、启停/重启、暂停/单步、多 tick 消费、死亡/槽位复用、换场景和容量降级；有状态的 GPU/路径/图执行验证重开与回收边界。
3. **可见 GPU 路径**：headed 真实硬件验证每项表中的结果，覆盖深度遮挡、交界/跨面、透明排序、HDR/描边及适用的视角/尺寸变化；真实玩法触发与受控测量输入分开记录。
4. **成本与资源**：同场景同输入比较关闭/开启和适用的参考路径，记录 CPU、GPU、draw、实例/段数、上传量与容量。区分 GPU timestamp、JS 提交耗时和测量区间，保留噪声及设备限制；多轮 Play/Stop 核对实际 GPU 销毁，不仅检查 CPU 计数。
5. **独立交付**：运行对应 owner 测试及受影响的 `architecture:check`、`scene:check`、`knowledge:check`，保留 M1–M3 与已交付 M4 项的受影响回归；独立 Audit/终审基于固定提交及原始证据。仅提交所属文件，每笔提交立即推送，保留并发修改及既有基线问题。

每小时巡检继续在监督对话中执行，唯一开发目标仍为上述原会话。发现有证据的方向偏离或代码质量问题直接反馈；当前阶段验收和推送完成后通知继续下一阶段，按阶段/提交/问题去重。**只有五项全部实际实现、独立验收与终审通过并已推送，且相关回归完成，才停止本轮巡检。** 评估完成、再次暂缓或仅完成某一阶段均不满足整体完成条件。
