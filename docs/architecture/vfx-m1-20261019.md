# M1 手枪 VFX：资源、运行与编辑

日期：2026-10-19。范围：手枪枪口闪光、弹道、实体/场景命中，以及最小资源编辑、保存、预览和 Play 生命周期。M2 敌人酸池、自爆、贴花，M3 持续发射和 M4 compute/node graph 不在本次实现中。

## 真源与职责

| Owner | 实现与契约 |
| --- | --- |
| `packages/scene/src/vfx.ts` | 独立 `.vfx.json` version 1；拒绝未来版本、坏 GUID/path、非法尺寸/时长/帧数。沿用现有武器 `presentation.vfx`，场景仍为 schema v15。 |
| `packages/runtime/src/weapon-combat.ts`、`solid-ray.ts` | 一次开火一条 fire；逐射线 trace 在伤害前复制实体/实际接触点、场景 NodeId/法线。保留旧 `nearestSolidHit` 数值接口。 |
| `packages/runtime/src/vfx.ts` | 256 实例池、优先级限流和溢出统计；以模拟 dt 推进 TTL，去重历史有界。 |
| `packages/zombie-game/src/presentation/vfx-planner.ts` | 游戏事实转换为通用播放请求；runId + sequence 去重；消费同帧多 tick，不重播已过期实例。枪口与原可见武器共用 `weaponMarkerWorld`。 |
| `packages/render/src/vfx-pass.ts` | 独立实例缓冲和 GPU Pass；场景之后、后处理之前；load HDR/aux/depth，深度测试开启、深度写入关闭。按相机深度排序，连续相容项合批。 |
| `apps/editor/src/services/play-vfx.ts` | 加载资源、PlaySession 登记真实 GPU 释放、异步代次取消与诊断；完整三件套就绪后抑制该武器旧 Canvas VFX。伤害数字和未迁移武器仍走原路径。 |
| `apps/editor/src/services/vfx-panel.ts`、`vfx-document.ts` | 资源参数和独立资产历史；场景绑定委托原作者 store；CAS 保存和重载。 |

事件队列上限 2048，超限累计 `weaponCombat.vfxDropped`；渲染上限 256 实例、16 张纹理、单纹理最大 4096px。M1 是 CPU 播放管理与 GPU 实例化，不占 64 个静态物件槽位。

原生 SVG 来自项目自行创作的 `assets/vfx/comic-{muzzle,impact,trail}.svg`。枪火/命中各为横向三帧形变，背景透明，弹道为单帧；无外部依赖。SVG 经浏览器 Image 解码、OffscreenCanvas 栅格化，再上传 sRGB 纹理；shader 在线性空间着色并输出预乘 alpha。纹理采样收紧半像素以避免串格。

VFX 覆盖处的 aux 仅写 alpha，通过 `dst * (1 - coverage)` 衰减已有描边 mask；透明 discard 保留原 mask，aux.rgb 保留，避免后处理把覆盖处强制还原为墨色。

## 产品操作

1. 打开编辑器 `https://localhost:5100/?scene=assets/scenes/sandbox/vfx-m1.scene.json`，或“文件 → 打开场景”选择 **M1 手枪 VFX · 遮挡与生命周期**。该场景已登记在 `aether.project.json`。
2. 右侧 **场景/光照 → 手枪 VFX · 资源与绑定**。从“VFX 资源”选择资源，点击“打开 VFX 资源”。也可输入安全的项目相对资源路径；正式场景绑定只接受 `assets/` 下的资源。
3. “编辑效果”选择 muzzle/trail/impact；修改宽度、高度、持续时间、颜色，点击“应用资源参数”。“撤销资源参数”“重做资源参数”只操作资产历史；“保存 VFX 资产”“重载 VFX 资产”只读写该资源文件。
4. “循环 GPU 预览”在主视口播放三件套，受场景深度遮挡；“停止 VFX 预览”释放其资源。进入 Play 自动结束编辑预览。
5. “绑定武器 → 应用 VFX 绑定”写入场景作者 store；“清除 VFX 绑定”可回退原 Canvas 表现。“撤销场景绑定”“重做场景绑定”“保存场景绑定”复用现有场景历史和保存。资产保存不会伪装成场景 dirty。
6. 点击 Play，鼠标瞄准墙体、按住 J 或左键射击；向 NPC 开火可验证实体命中。暂停保持实例 TTL，单步走一个模拟 tick；Stop 清空实例并销毁 GPU 资源。测试场景低伤害、高弹药，便于重复观察。

面板下方统计包含 pool kind/active、spawned/dropped、draws/上传字节、GPU 缓冲/纹理和释放计数。只读调试快照为 `window.__editor.vfx.snapshot()`；产品操作不依赖此接口。

资源保存通过现有 devfs 逐文件队列和共享项目锁，在同一锁内比较加载基准 `baseHash`。源定义替换后同步 sidecar 的 SHA-256，保留 GUID、userData 等字段；元数据写入异常时回滚源定义并报告失败。断电式跨两文件崩溃不具备数据库事务保证，门禁可发现 hash 不一致。编辑期间外部改动产生 CAS 冲突，保留本地草稿，不刷新基准后覆盖。

## 诊断与边界

- 引用缺失、GUID/kind 不匹配、资源 quarantined、缺少三件套或纹理解码失败：显示诊断，GPU 武器表现不启用，保留旧 Canvas 回退。资源正文未来版本与非法参数拒绝编辑/保存。
- `VFX-ATLAS-01` 保持原隔离状态，本次没有启用或修改旧图集。
- Play 与编辑预览各自拥有资源；每代 Play 的真实 Pass 被登记到 PlaySession，Stop 逐个调用 GPUBuffer/Texture.destroy，异步加载的旧代结果关闭 bitmap 后丢弃。
- `scene:check` 覆盖 VFX 定义、sidecar/hash、纹理 GUID/path 和场景武器绑定；VFX 引用影响的资产改名暂显式拒绝，避免工具静默漏改引用。先在编辑资源中调整引用。
- 只有绑定了正式三件套的射线武器迁移到 GPU。M1 默认验收手枪；弹丸、火焰、近战及敌人攻击保持现有表现。尚无 VfxEmitter/Decal 组件、soft particles 或跨面投影。
