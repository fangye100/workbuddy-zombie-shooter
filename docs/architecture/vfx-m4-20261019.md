## M4.1 数据和职责

资源拟升级到 v4，显式保存 `backend`（cpu/gpu）及通用发射加速度；旧 v1/v2/v3 读取时显式迁移，保留原始磁盘对象作为 CAS 基准，保存才升级。既有 `VfxEmitter` 组件已有资源、effectKey、seed、playing、本地方向及稳定 NodeId，优先复用，不为后端切换制造第二份场景状态。GUID、纹理引用、迁移提示及资产门禁沿用现有契约。

| owner | 责任与预期文件 |
|---|---|
| scene | `packages/scene/src/vfx.ts`、相关测试及必要公共入口：版本、校验、迁移与兼容诊断 |
| runtime | 独立 CPU 参考模块及测试：固定 tick/seed、环形槽分配、有限状态和回收；不拥有 GPU 对象 |
| render | 独立 GPU simulation/shader 模块与 `vfx-pass.ts` 装配：compute、storage buffer、直接 GPU 绘制、能力/预算及真实 destroy |
| game | 原模拟事实和表现请求不改伤害/轨迹；本阶段游戏请求如不支持 GPU 模式须显式兼容 |
| editor | `authored-vfx.ts`、聚焦资源面板与 Play 装配：真正作者节点/预览、backend 参数编辑、保存及诊断 |
| assets/tools/docs | 正式 v4 资源、登记场景、受控 headed probe、指南与目录，不使用隔离图集或未跟踪素材 |

CPU 参考与 GPU 使用相同固定 tick、seed/serial 随机算法、发射计数、寿命和半隐式运动更新。GPU 状态位置/速度/年龄/serial 留在 storage buffer；生产绘制直接读取该 buffer，不通过每帧 CPU 回读伪装 GPU 模拟。读回只在明确的测试/诊断调用中进行。暂停没有新 tick，单步恰好一个 tick；重复消费同 tick 不重复推进，重开重置 seed/clock，Stop/换场景释放全部实际分配，异步旧代不得复活资源。

首版 GPU 范围限定为 camera billboard 的 additive sprite 发射器；alpha、surface、trail 等不满足条件时给出可定位兼容原因，保留原 CPU 透明排序。不得将 alpha 无序提交到 GPU。既有纹理、premul/sRGB、深度遮挡与 aux 覆盖衰减继续复用；新 GPU 状态是独立动态预算，不占静态64物件槽。

## M4.1 预算和失败行为

设计上限：GPU 总4096粒子、16发射器、单发射器1024；单次 catchup240 tick，超限有计数；纹理仍共享16张/4096px。CPU 兼容沿用256共享实例和单发射器128、120/s限制，降级必须告知限流，不假报 GPU 成功。最终实际常量和测量将随实现核对记录。

资源未就绪、缺纹理、不支持的模式、GPU device limits 或动态预算不足均可见诊断，兼容路径有界；危险轮廓仍由真实模拟保底。设备能力的受控限制注入只能证明失败路径，不代表本机 NVIDIA 不支持。统计区分提交槽容量、实际 GPU 读回 alive、dispatch/draw/upload/dropped，不能用估计值冒充实际 alive。所有新增 buffer/texture 登记到 Play 生命周期，逐一 destroy；只清 CPU 或记账不算释放。
