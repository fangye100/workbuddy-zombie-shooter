## M4.2 实施契约（52整阶段及a8文档收尾已批准）

阶段基线 `df344d7e6c3c47bee21ced3729a0b88e69bb5078`。资源v5新增通用 `kind:ribbon` 及 `ribbon.maxPoints/minDistance/breakDistance/uvMetersPerTile`，width读size[0]、size[1]保留1；Ribbon限CPU历史/camera朝向/单帧纹理，几何仍真实GPU绘制。旧v1–v4显式迁移读取、raw CAS保留、保存才升级。scene v18新增可选 `VfxEmitter.motion`（2–32个本地点、seconds、loop），17→18只升版本不补造轨迹；正式旧场景只必要版本迁移。

`runtime/vfx-ribbon.ts`只管固定tick路径历史、生命周期与采样：默认32handle/2048总点，单条最多128；重复同tick不重复消费，位置差<1e-8计退化、不生成点，低于minDistance跳过，超breakDistance或丢点恢复后断开。停止不再加点，旧点按真实模拟时间TTL到期；重启同key清路径并换epoch、复用有界handle，run/实体generation由请求key隔离。无存活点的idle句柄可被容量回收，不存无限key历史。作者局部motion按弧长/固定模拟秒采样，游戏轨迹只能来自真实模拟事实。

渲染实现：独立Ribbon模块为每个接受点生成共享左右两个顶点，相邻段复用同一边；每个非断开段6个索引、退化/断开段0索引。切线来自同一连续段邻点，宽度/颜色/透明曲线按点龄采样；UV按分段累计弧长/uvMetersPerTile单调，不因裁剪旧点重新归零。透明段与CPU sprites按实际几何深度排序，alpha Ribbon同样阻止M4.1 additive compute跨alpha后画，显式CPU兼容。不能以M3独立尘尾quad充当本阶段结果。

游戏事实由独立 `MotionVfxFrames` 每真实fixed tick捕获player不可变位置/身份代次；charge复用既有EnemyAttackEvent的move/end与source generation，不改伤害/运动公式，不把无关轨迹塞进武器类。真实WASD直行/转向与受控拓扑/遮挡测量分开记录。正式资源/登记场景、作者motion与Ribbon参数Apply/Undo/Redo/实际Save整页Reload、断源/满池/退化/重开/Stop及CPU/GPU/upload成本均在 `.workbuddy/tmp/vfx-m4-2/` 留原始命令、exit、状态与画面；完成开发后另冻结target供独立Audit和完整Reviewer。

CPU 参考与 GPU 使用相同固定 tick、seed/serial 随机算法、发射计数、寿命和半隐式运动更新。GPU 每粒子48字节：position/age、velocity/life、uint serial/rotation/live/reserved；每workgroup64线程，单槽线程负责有界 tick 序列。覆盖旧槽计 dropped，到期计 expired。GPU 状态留在 storage buffer；生产绘制直接读取该 buffer，没有每帧 CPU 回读。`readback()` 只由测试/诊断显式调用，暂存 buffer 在 finally 销毁。

作者组件使用加载完成时的节点世界位置/本地方向变换，首个可用模拟 tick 作为局部tick0；本阶段 GPU 作者锚点固定，游戏动态事实仍显式 CPU 兼容。Preview固定1/30s、用户uint32 seed，纹理就绪前不能单步；Play读真实 runtime fixedStep。暂停无新tick，单步一个tick，重复消费不推进。GPU句柄 `playing=false` 在继续送tick时停止新生、尾部到期；同key重启清状态/计数但复用原buffer，显式release撤销状态并回收容量。产品Stop/重开/换场景走原PlaySession整体销毁，新会话重建；旧代异步加载有generation保护。

首版 GPU 范围限定为 camera billboard 的 additive sprite 发射器；alpha、surface、trail 等不满足条件时给出可定位兼容原因，保留原 CPU 透明排序。**同屏存在实际可绘制CPU alpha时，GPU发射器也退回CPU统一排序**，不固定后画GPU additive造成后方发光穿过前方alpha；该保守策略会降级未相交的同屏效果。绘制时还会阻止晚到alpha与旧GPU状态交错。兼容资源限流到120/s、128，保留加速度，CPU显示按固定step半隐式位移采样；限流改变数量，不能称与未限流GPU完全相同。游戏瞬态/持续请求的GPU声明当前也有明确CPU兼容提示。

纹理、premul/sRGB、深度less-equal/write关闭与aux覆盖衰减复用M1–M3。GPU size/color/alpha曲线在shader采样，颜色在线性空间插值，使用正式SVG三帧纹理；无跨面投影、深度软化或Ribbon接口占位。新GPU状态是独立动态预算，不占静态64物件槽。

## M4.1 预算和失败行为

实际上限：GPU总4096粒子、16发射器、单发射器1024；单次catchup240tick，时钟倒退或溢出可见拒绝/兼容；纹理仍共享16张/4096px。CPU兼容沿用256共享实例和单发射器128、120/s，降级告知限流，不假报GPU成功。GPU逐发射器绘制容量槽位，死槽退化到裁剪区；`capacity`是提交槽数，不是实际alive，后者仅诊断读回有真值。

资源未就绪、缺纹理、不支持的模式、GPU device limits 或动态预算不足均可见诊断，兼容路径有界；危险轮廓仍由真实模拟保底。设备能力的受控限制注入只能证明失败路径，不代表本机 NVIDIA 不支持。统计区分提交槽容量、实际 GPU 读回 alive、dispatch/draw/upload/dropped，不能用估计值冒充实际 alive。所有新增 buffer/texture 登记到 Play 生命周期，逐一 destroy；只清 CPU 或记账不算释放。

## 成本、检查和剩余阶段

最终样本仅代表此Windows/NVIDIA机器。轻量暂停场景每模式4warmup+20样本，CPU是`core.drawFrame` JS wall-time，GPU是scene开始→post结束timestamp（含整场景和后处理，**不是VFX单pass**）：

| 指标均值 | VFX off | VFX on |
|---|---|---|
| CPU提交ms | .150 | .150 |
| GPU scene→post ms | .365 | .159 |

几何与生命周期的验收口径明确如下：

- 一个接受点恰好两个顶点，每顶点9个float（position3/UV2/linear RGBA4）。同一连续段每相邻两点6索引，相邻两段恰共享2索引；断开、不同key/实体代次之间没有跨接索引。GPU诊断读回必须与上传CPU顶点/索引逐bit一致，生产绘制直接绑定GPU buffer，绝不每帧读回。
- 每连续片段的UV沿累计弧长单调，`u=distance/uvMetersPerTile`；每片减去共同整数周期以缩小数值，裁剪旧点保留纹理相位，不把剩余尾部重新拉伸。V为两侧0/1，U repeat。切线取同一片段邻点；平行视线/零切线有有限向量回退，miter放大最多2，颜色/宽度/alpha按点龄采样现有曲线。
- 默认32handle/2048总点、单条2–128点；单点不足以画段。重复tick不重加，距离<1e-8计退化，低于minDistance计跳过，超过breakDistance、作者loop边界、丢失事实或预算恢复均显式断开。局部容量裁掉最老点；全局点/handle满池拒绝且统计可见，不能无限增长或串线。
- Stop source只停止新点，尾部按模拟TTL自然到期；同key重新start清旧路径、换单调epoch并复用有界handle。无点idle句柄可淘汰。run/id/generation在游戏key中隔离，源销毁后不查后来同槽实体。即使源只留下一个不可见点也会停止。作者追帧上限240tick，超限诊断并断开，不伪造缺失路径。
- Preview固定1/30秒，Play读runtime.fixedStep；相同作者motion/clock/seed及相机下重播几何逐bit一致。Ribbon本身没有随机形变，seed保留统一Emitter契约。不同渲染消费分组的真实fixed-tick位置/年龄/弧长在owner测试完全一致。Pause不推进、Step只推进一个tick；产品“重跑”换run并实际释放旧buffer/texture，新历史不含旧run；Play重开清旧run与GPU资源；换场景按显式Stop→产品场景选择器执行，不声称选择场景本身会自动Stop。

## M4.3 当前实现与产品操作

深度资源由独立 [SceneDepth](../../packages/render/src/scene-depth.ts) 持有，实际创建depth24plus纹理并声明RENDER_ATTACHMENT与TEXTURE_BINDING；同尺寸复用，resize实际destroy旧纹理并换view。RendererCore只组合该资源与当前投影。独立 [vfx-soft-depth](../../packages/render/src/vfx-soft-depth.ts) 从投影矩阵取A/B/C/D，以`abs((B-depth*D)/(depth*C-A))`恢复眼空间距离，透视与正交共用；背景depth=1保留原alpha，其余`clamp((sceneEye-particleEye-bias)/fadeDistance,0,1)`。实际fragment position.xy用于物理像素textureLoad，position.z是粒子深度。不存在CPU生产读回。

独立 [sprite shader](../../packages/render/src/vfx-sprite-shader.ts) 维护普通/soft各自alpha与additive变体；fade先作用于alpha，再生成premultiplied颜色与aux覆盖衰减。VfxPass仍将普通sprite、soft sprite与Ribbon段共同按深度排序，只合并相邻兼容项。实例由80扩为96B，投影uniform仅开启soft时惰性分配16B；深度view变化重建group，Stop实际destroy该buffer。无soft的旧路径仍保持原分配数。GPU compute声明soft时明确有界CPU兼容，不丢加速度/soft参数；Ribbon soft在资源校验与UI拒绝。本阶段不认证任意透明三角形互穿的逐像素全序，也不实现Ribbon柔和交界。

## M4.4 实际实现、支持范围与操作

[投影几何模块](../../packages/render/src/vfx-decal-mesh.ts)只消费真实接收CPU顶点/索引、稳定NodeId、layer与实际世界矩阵。每个接收三角形变换到世界，再用投影器逆矩阵进入局部体积，以Sutherland–Hodgman逐一裁切±X/±Y/±Z六面；多边形扇形三角化并去掉零面积结果。UV为局部`x/width+.5`、`.5-y/height`，所以共享空间棱边保留连续投影纹理；不是复制多个平面sprite。接收法线来自真实三角面变换（含反射符号），仅接受与投影器+Z夹角不超过maxAngle的面，沿实际面法线偏移normalOffset以避免z-fighting；不使用固定屏幕偏移。体积内所有被选且符合朝向的接收面都参与，不额外实现投影器光线的最近接收面遮蔽。

[GPU模块](../../packages/render/src/vfx-decal.ts)持有固定顶点/索引buffer，生产直接indexed绘制；诊断readback才分配临时buffer并finally销毁。顶点stride36B（世界position3/UV2/linear RGBA4）。Pass只组合投影三角、Ribbon段、普通/soft sprites的全局远近顺序，相邻兼容索引才合批；[共同几何pipeline](../../packages/render/src/vfx-geometry-pipeline.ts)复用premultiplied颜色、sRGB纹理、less-equal深度且不写深度、aux仅覆盖衰减。不是OIT，任意互穿透明三角形的逐像素全序仍不认证。alpha贴花进入既有compute兼容门，同屏GPU additive作者显式降级有界CPU；M4.3 compute-soft兼容和Ribbon-soft拒绝保持。

两种支持范围必须分开：

- **通用算法/受控GPU输入**支持可逆affine投影器/接收矩阵，包括旋转、非均匀缩放；反射实现方向符号修正，但未单列受控GPU认证。不可逆、非法顶点/范围或坏接收表产出诊断。矩阵、运行几何不序列化。
- **产品接收适配** [vfx-decal-receivers](../../apps/editor/src/services/vfx-decal-receivers.ts)仅借用LabRenderer已有实际mesh/modelMatrix与可见子网格范围，支持静态builtin及已真实解码的非蒙皮/非动画GLB；拒绝bob、角色绑定、未解码占位及非均匀世界缩放。现视口只有统一缩放，不能用另一份SceneGraph非均匀矩阵把贴花投到实际不存在的表面。正式墙/台阶以builtin尺寸参数表达；不借受控affine结果认证产品非均匀receiver。GLB产品证据限定本仓库4三角静态asphalt示例，不外推任意复杂模型。

[runtime池](../../packages/runtime/src/vfx-decal.ts)按固定tick推进，作者默认16实例（通用池构造容量可显式选1–64），重复key不重复发射；满池等优先级拒绝、更高优先级回收最低项，epoch有界会话内递增。非loop按资源duration到期，loop持续到显式source stop；停止即撤，不用旧几何代当前成功。作者输入来自Play快照，key含run/稳定NodeId，重跑清旧run；无游戏动态actor贴花绑定，未宣称自动跟随角色或接管酸池/危险提示。runtime代际key隔离及stop由owner测试覆盖；本阶段GUI作者关闭在下次Play不创建该源，Play期间作者编辑锁定。几何预算整贴原子拒绝，diagnostics/stats可见；容量上限不是帧率承诺。
