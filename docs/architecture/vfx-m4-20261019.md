## M4.2 实施契约（开发中，未独立验收）

阶段基线 `df344d7e6c3c47bee21ced3729a0b88e69bb5078`。资源v5新增通用 `kind:ribbon` 及 `ribbon.maxPoints/minDistance/breakDistance/uvMetersPerTile`，width读size[0]、size[1]保留1；Ribbon限CPU历史/camera朝向/单帧纹理，几何仍真实GPU绘制。旧v1–v4显式迁移读取、raw CAS保留、保存才升级。scene v18新增可选 `VfxEmitter.motion`（2–32个本地点、seconds、loop），17→18只升版本不补造轨迹；正式旧场景只必要版本迁移。

`runtime/vfx-ribbon.ts`只管固定tick路径历史、生命周期与采样：默认32handle/2048总点，单条最多128；重复同tick不重复消费，位置差<1e-8计退化、不生成点，低于minDistance跳过，超breakDistance或丢点恢复后断开。停止不再加点，旧点按真实模拟时间TTL到期；重启同key清路径并换epoch、复用有界handle，run/实体generation由请求key隔离。无存活点的idle句柄可被容量回收，不存无限key历史。作者局部motion按弧长/固定模拟秒采样，游戏轨迹只能来自真实模拟事实。

渲染目标：独立Ribbon模块为每个接受点生成共享左右两个顶点，相邻段复用同一边；每个非断开段6个索引、退化/断开段0索引。切线来自同一连续段邻点，宽度/颜色/透明曲线按点龄采样；UV按分段累计弧长/uvMetersPerTile单调，不因裁剪旧点重新归零。透明段与CPU sprites按实际几何深度排序，alpha Ribbon同样阻止M4.1 additive compute跨alpha后画，显式CPU兼容。不能以M3独立尘尾quad充当本阶段结果。

游戏事实计划由独立 `MotionVfxFrames` 每真实fixed tick捕获player不可变位置/身份代次；charge复用既有EnemyAttackEvent的move/end与source generation，不改伤害/运动公式，不把无关轨迹塞进武器类。真实WASD直行/转向与受控拓扑/遮挡测量分开记录。正式资源/登记场景、作者motion与Ribbon参数Apply/Undo/Redo/实际Save整页Reload、断源/满池/退化/重开/Stop及CPU/GPU/upload成本均在 `.workbuddy/tmp/vfx-m4-2/` 留原始命令、exit、状态与画面；完成开发后另冻结target供独立Audit和完整Reviewer。

CPU 参考与 GPU 使用相同固定 tick、seed/serial 随机算法、发射计数、寿命和半隐式运动更新。GPU 每粒子48字节：position/age、velocity/life、uint serial/rotation/live/reserved；每workgroup64线程，单槽线程负责有界 tick 序列。覆盖旧槽计 dropped，到期计 expired。GPU 状态留在 storage buffer；生产绘制直接读取该 buffer，没有每帧 CPU 回读。`readback()` 只由测试/诊断显式调用，暂存 buffer 在 finally 销毁。

作者组件使用加载完成时的节点世界位置/本地方向变换，首个可用模拟 tick 作为局部tick0；本阶段 GPU 作者锚点固定，游戏动态事实仍显式 CPU 兼容。Preview固定1/30s、用户uint32 seed，纹理就绪前不能单步；Play读真实 runtime fixedStep。暂停无新tick，单步一个tick，重复消费不推进。GPU句柄 `playing=false` 在继续送tick时停止新生、尾部到期；同key重启清状态/计数但复用原buffer，显式release撤销状态并回收容量。产品Stop/重开/换场景走原PlaySession整体销毁，新会话重建；旧代异步加载有generation保护。

首版 GPU 范围限定为 camera billboard 的 additive sprite 发射器；alpha、surface、trail 等不满足条件时给出可定位兼容原因，保留原 CPU 透明排序。**同屏存在实际可绘制CPU alpha时，GPU发射器也退回CPU统一排序**，不固定后画GPU additive造成后方发光穿过前方alpha；该保守策略会降级未相交的同屏效果。绘制时还会阻止晚到alpha与旧GPU状态交错。兼容资源限流到120/s、128，保留加速度，CPU显示按固定step半隐式位移采样；限流改变数量，不能称与未限流GPU完全相同。游戏瞬态/持续请求的GPU声明当前也有明确CPU兼容提示。

纹理、premul/sRGB、深度less-equal/write关闭与aux覆盖衰减复用M1–M3。GPU size/color/alpha曲线在shader采样，颜色在线性空间插值，使用正式SVG三帧纹理；无跨面投影、深度软化或Ribbon接口占位。新GPU状态是独立动态预算，不占静态64物件槽。

## M4.1 预算和失败行为

实际上限：GPU总4096粒子、16发射器、单发射器1024；单次catchup240tick，时钟倒退或溢出可见拒绝/兼容；纹理仍共享16张/4096px。CPU兼容沿用256共享实例和单发射器128、120/s，降级告知限流，不假报GPU成功。GPU逐发射器绘制容量槽位，死槽退化到裁剪区；`capacity`是提交槽数，不是实际alive，后者仅诊断读回有真值。

资源未就绪、缺纹理、不支持的模式、GPU device limits 或动态预算不足均可见诊断，兼容路径有界；危险轮廓仍由真实模拟保底。设备能力的受控限制注入只能证明失败路径，不代表本机 NVIDIA 不支持。统计区分提交槽容量、实际 GPU 读回 alive、dispatch/draw/upload/dropped，不能用估计值冒充实际 alive。所有新增 buffer/texture 登记到 Play 生命周期，逐一 destroy；只清 CPU 或记账不算释放。

## 成本、检查和剩余阶段

最终样本仅代表此Windows/NVIDIA机器。轻量暂停场景每模式4warmup+20样本，CPU是`core.drawFrame` JS wall-time，GPU是scene开始→post结束timestamp（含整场景和后处理，**不是VFX单pass**）：

| 指标均值 | VFX off | VFX on |
|---|---|---|
| CPU提交ms | .150 | .150 |
| GPU scene→post ms | .365 | .159 |
| draw | 8 | 9 |

on小于off是小样本计时/调度噪声，不能推导提速、零成本或负成本。暂停GPU只重画，无compute推进，稳态上传80B/frame。
