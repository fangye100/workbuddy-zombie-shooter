# 22 · 编辑器可玩预览阶段（ADR-018）

> **Status**：Proposed
> **一句话**：把 Game Editor 的 Play 从「灰盒调试器」升级为「Unity 式 Play mode」——
> 点 Play 即进入可玩状态，用真实资产、真实玩法跑起来，用于在编辑器内向人展示
> 游戏在开发期的真正全貌。

---

## 1. Context

### 1.1 诉求与边界（用户 2026-10-01 确认）

- 目标是 **Unity 式 Play mode**：编辑器里点 Play → 进 Play mode → 在编辑器内真 gameplay。
- 档位选 **C 全量**：核心循环 + 游戏相机 + 玩家输入 + HUD + 音频 + 关卡流程 + 500 实体性能验收。
- 用途是**对外展示**：向人呈现「开发时可交付的真正全貌」，因此需要稳定、可复现、观感真实。
- 前提（用户原话）：**不得损害 Agent 的开发能力**。

### 1.2 需求澄清记录（避免后人重踩）

| 曾被误读的说法 | 实际含义 |
|---|---|
| 「runtime play」 | **口误**。真实含义是「在编辑器里点 Play 跑起来看」，**不是**运行时热更新 |
| 「改代码实时生效」 | **不要求**。改代码 → **下一次 runtime reload 才生效**（与 ADR-017 原约定一致） |
| 「GameDetective / Game Manager / Game Energy」 | 均为**语音输入识别错误**，实际都指 **Game Editor**。代码库中零命中 |

> 教训：听到「实时」先确认是「运行时热更」还是「点一下就能跑」，不要自行升级需求。
> 本次曾据此误判出「ADR-017 禁用热重载 vs 需求冲突」，并设计了代次隔离方案，
> 澄清后**全部作废**——ADR-017 原约定本就正确，一个字不改。

### 1.3 现状盘点（证据）

| 项 | 状态 | 证据 |
|---|---|---|
| 场景装载 / 固定步推进 / 种子复现 | ✅ 已落地 | `verify:parity-host` 37 PASS |
| 代次机制 | ✅ 已有 | `runId` 每次构造/reset 递增，三代同检（复审 #6） |
| Play 启动相机契约 | ✅ **schema 已有** | `document.ts:508` `entryCamera: NodeId \| null`；null → 取第一个启用的 Camera 组件 → 回落 EditorCamera |
| 跨场景引用（关卡流程） | ✅ schema 已有 | `document.ts:501` 场景 `id` 注释「通关后去 xx 场景」 |
| 行为目录指针 | ✅ 已声明 | `project.ts:203` `behaviorRoots: ['assets/behaviors']` |
| `ScriptComponent` schema | ✅ 已定义 | `document.ts:370` |
| `assets/behaviors/` 目录 | ❌ **不存在** | — |
| 行为执行 | ❌ **未接线** | `session.ts:97` `behavior` 仅 `0=idle / 1=chase`；Script 组件不执行且无 diagnostic |
| 真实角色资产 | ❌ 胶囊 | `runtime-bridge.ts:267` `meshId = capsule:…`；docs/20 的 `runtime-actors.ts` **文件不存在** |
| 玩法语义 | ❌ 空白 | `loader.ts:334` wave 未实现；无 damage/health/死亡回收 |
| Play 相机接线 | ❌ 未接 | `play-controller.ts:14` 当前用编辑相机自由移动 |

结论：**设计契约已具备大半，实现基本为零。本阶段是"接线 + 补缺"，不是重新设计。**

### 1.4 三条不可违背的既有约束

1. **ADR-017**：场景绝不存代码字符串；行为 = 代码资产 + **params schema 必需**；失效降级 warning 不阻塞加载。
2. **docs/17 §3.4**：人通过 GUI、Agent 通过工具调用**同一套领域操作**；GUI 不额外实现规则，Agent 不绕过校验/撤销/保存。
3. **运行时中心 > 编辑器中心**（docs/17 §3.2 判定第 2 问）：关闭编辑器仍需要的能力，不能只实现在编辑器里。

## 2. Decision

### 2.1 目标：C 档全量

| 档 | 范围 | 选择 |
|---|---|---|
| A 核心循环 | 行为执行 + 真模型 + 玩法语义 | — |
| B 完整 Play mode | A + 游戏相机 + 玩家输入 + HUD | — |
| **C 全量** ✅ | **B + 音频 + 关卡流程 + 500 实体性能验收** | **采纳** |

### 2.2 三条架构红线（保护 Agent 能力，防编辑器特供）

> 这三条是 C 档不反噬 Agent 能力的前提，任何 WU 违反即打回。

- **R1 · 三问检验**：所有新增能力必须通过 docs/17 §3.2 三问，尤其第 2 问
  「关闭编辑器，独立运行游戏还需要吗？」——**答案必须是「需要」**。
  否则就是编辑器特供，会把游戏锁死在编辑器里，Agent 写的东西也出不去。
- **R2 · 行为是内容，不是编辑器功能**：`assets/behaviors/*.ts` 属「当前游戏规则」层，
  Agent 可写任意逻辑，**不受任何 UI 控件限制**；`BehaviorDef.params` schema 把这份代码
  **反向暴露**成 GUI 控件。**schema 即 Agent 与人类之间的契约面**。
- **R3 · runtime 不 import 行为代码**：执行器由宿主**注入**（浏览器用 `import.meta.glob`
  收集；CLI 注入 mock）。保住 `packages/runtime` 纯 CPU / headless / 可 CLI 测试，
  以及 `verify:parity-host` 的 Node↔浏览器逐实体一致。

### 2.3 一次 Play = 一个封闭行为代次

| 时机 | 行为注册表状态 |
|---|---|
| Play 启动 | 装载场景 + **冻结当前行为快照**（本代不可变） |
| Play 期间 | 实体持有本代闭包；代码改动对本次运行**完全无效** |
| 改代码后 | 必须 Stop → 重跑 → 新 `runId` + 新行为快照 |
| 跨代引用 | 选中 / Inspector / 诊断**显式失效并告知**，不静默 |

行为代次与已有 `runId` 对齐——**不新建机制，复用既有代次语义**。

🔴 **跨代必须显式告知**：若代码已改但未重跑，编辑器要明确提示「当前跑的是旧一版行为」。
静默会导致「看起来在跑，其实跑的不是你刚改的」——本项目最忌讳的假象类别
（docs/19 反复强调「明确未做，不是看起来像做了」）。

### 2.4 分层与依赖方向

```
宿主层   GUI(Inspector) · CLI · MCP(Agent)     ← 三个宿主共享同一套领域操作
              ↓ 领域 API
领域层   BehaviorRegistry · BehaviorDef · 校验/撤销/保存
              ↓ 执行契约（注入）
运行时层 RuntimeSession · 实体表 · runId 代次   ← 纯 CPU，不 import 行为代码
              ↑ 注入
内容层   assets/behaviors/*.ts                  ← Agent 创作空间
```

## 3. Work Unit 队列

| WU | 内容 | 验收 |
|---|---|---|
| **P1** | `assets/behaviors/` + `defineBehavior()` + params schema + glob 注册 + 失效降级 | vitest：注册/校验/降级不阻塞加载 |
| **P2** | Inspector 按 schema 画 8 种控件 | Agent 写的脚本，人类能在 GUI 上调参 |
| **P3** | 执行接线 + 装载期冻结 + 代次对齐 `runId` | parity 不回归；跨代引用显式失效 |
| **P4** | 真实资产（docs/20 M1~M4，胶囊 → 真模型） | 浏览器见真模型而非胶囊 |
| **P5** | 玩法语义：波次 / 战斗 / 死亡回收 | 长时间跑不撑爆容量 |
| **P6** | Play 相机接线：`entryCamera` → 游戏相机 + 回退链路 | Play 后视角切到游戏相机 |
| **P7** | 玩家输入：虚拟摇杆 + 右侧动作键（mobile 布局） | 非仅调试箭头键 |
| **P8** | HUD：血条 / 弹药 / 波次。**数据归运行时，渲染归宿主**（R1） | Play 态可读，独立游戏可复用 |
| **P9** | 音频：**触发归规则层，播放归宿主**（R1） | 独立游戏可复用 |
| **P10** | 关卡流程：通关 → 下一关（复用 `SceneDocument.id` 跨场景引用） | 场景 id 契约驱动，非硬编码 |
| **P11** | 性能：500 实体验收（docs/19 已列未做） | 帧率与显存记录 |

**P1 是瓶颈且成本最低**——schema 与目录指针均已就绪，只差实现。
**P6 成本最低但体验变化最大**——切到游戏相机那一刻，它才从「调试器」变成「Play mode」。

## 4. 验收定义（对标 docs/17 §8）

必须能**复跑**证明，不接受「看起来能跑」：

1. 点 Play → 视角切到游戏相机，真实角色模型出现（非胶囊）。
2. 玩家可用虚拟摇杆移动、动作键射击；NPC 有波次推进、可被击杀、死亡后回收。
3. HUD 显示血量 / 弹药 / 波次，数据与运行时一致。
4. 通关后按场景 `id` 进入下一关。
5. 500 实体下帧率与显存达标并有记录。
6. 同种子 + 同输入序列：Node 与浏览器逐实体一致（parity 不回归）。
7. 改行为代码后未重跑 → **编辑器显式提示当前为旧代次**。

---

## 5. Consequences

### 变得更容易

- Agent 有了真正的**内容创作空间**（`behaviors/*.ts`），不受 UI 控件限制。
- 人类通过 params schema 在 GUI 上参与调参，Agent 与人类共享同一份契约。
- 对外展示有了稳定路径：场景数据 + 行为代码 + 真资产，一次 Play 跑全貌。
- 复用既有代次（`runId`）与既有 schema（`entryCamera` / 场景 `id`），不新建机制。

### 更难 / 代价

- **性能预算会反向约束 Agent**：要跑 500 实体，Agent 写的行为必须符合每 tick 成本预算。
  这是 C 档引入的**新约束**，需在 P11 明确预算并写入行为作者须知。
- HUD / 音频 / 关卡流程若不小心做进编辑器，会违反 R1，把游戏锁死在编辑器内。
  每个 WU 验收都要过三问检验。
- 工作量显著大于 A/B 档，需按 P1→P11 串行推进，P1/P6 先行以尽早见到形态变化。

### 明确不做

- **运行时热重载**（改代码立即生效）——用户明确不要求，与 ADR-017 一致。
  记录在此避免后人重新提出。
- **数据化行为**（把行为编译成节点图/字节码换热更能力）——会削弱 Agent 写代码的能力，
  与「优先最大化 Agent 能力」的顶层决策冲突，**否决**。
- 通用 App 调度框架、完整存档恢复、任意时刻倒放（docs/17 §5.1 已暂缓）。
