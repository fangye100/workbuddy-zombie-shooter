# 21-编辑器冒烟测试精简与模块化划分报告

> 2026-09-23 · 背景：UI 布局改造期间，每次改动都需跑完整 `editor:smoke --headed`（约 7 分钟），
> 其中与本次改动无关的绑定管线占了一半以上耗时。本文记录现状盘点、问题清单与精简建议，
> 作为后续测试架构调整的依据。

## 一、现状

`tools/verify/editor-smoke.mjs`（约 2700 行）单文件承载全部编辑器冒烟，共 13 个段、
约 217 条断言，任何一处 editor 改动收尾都要完整跑一遍：

| 段 | 内容 | 与 UI 改动的相关度 |
|---|---|---|
| A / B / B2 | 启动、WebGPU、帧循环、场景来自文件 | 高（地基） |
| C / D / E | Selection / Hierarchy / MaterialPanel 服务 | 高 |
| F / G / G2 / G2b / G2c | 拾取与 Gizmo 拖拽写回（含三类评审回归回归） | 高 |
| H | 动画面板 + 布局收敛 + 功能体断言 | 高 |
| I | 出帧稳定性 | 中（与 B 重叠） |
| J / J2 | AssetPreview、资产库 UI | 高 |
| K / L / L2 / L2b / L2c | **绑定管线**（T-pose 铁律 / 文件骨架导入 / 正侧视 / 像素健康度） | **低（除非改绑定）** |
| M | MCP 绑定探针 | 低 |
| N | 多语言切换 | 中 |

全程约 7 分钟，其中绑定相关段（K/L/L2x/M）约占一半以上；十来处固定 `sleep(3000~6000)`
按最慢机器取值，快机器上白白等待。

## 二、问题清单

### 2.1 结构性问题：单文件混装所有模块

绑定管线（K/L/L2x）是全项目最复杂的链路，回归价值极高——但与 UI 布局改动几乎无关。
现状导致：改一行 CSS 也要陪跑 T-pose 反解、文件骨架导入、像素健康度。"改什么跑什么"
无从谈起。

### 2.2 L2c 放错了地方

冒烟脚本自己的头注释声明了分工：**cdp-verify = 视觉验证；editor-smoke = 结构冒烟**。
而 L2c（渲染截图 + 像素统计防过曝/全黑）是纯视觉验证，按它自己声明的纪律应归
cdp-verify.mjs。

### 2.3 断言冗余

- **B 与 I 重叠**：B 断言"drawCalls > 0 管线在画"；I 再等 1.5s 断言"drawCalls 还在涨"。
  可合并为一段。
- **B2 与 D 重叠**：场景来源断言与 HierarchyService 断言用同一份物体名单逐名比对，
  做了两遍。留一份即可。

### 2.4 固定 sleep 是最大隐性成本

模型载入、面板打开、语言切换等十来处固定等待（合计 30~40 秒），全部按最慢环境取保守值。
快机器上纯属浪费；换成**条件轮询**（waitFor：条件成立即过、超时上限兜底），
快机器省 30-60% 等待，慢机器反而更稳（不会因偶发超时假失败）。

### 2.5 N 段双整页 reload

多语言验证切 en 等一次 reload（6s）、切回 zh 再点按钮等第二次 reload（5s）。
切回那一次可直接改 localStorage 收尾，省一次 reload 不减覆盖。

## 三、划分原则（已确认的方向）

**冒烟套件按模块依赖划分：改了哪个模块，就跑那个模块（+ 它依赖的地基）的冒烟。**

划分单位是「文件路径 → 套件」的映射，不靠人工判断"这次改动无关"：

| 改动范围 | 跑什么 |
|---|---|
| `services/binding/**`、retarget、import-skeleton | 核心 + 绑定套件 |
| 共享文件（ui.ts / index.html / params.ts 等），**不碰 main.ts** | 只跑核心 |
| **main.ts**（3000+ 行接线枢纽，绑定入口全在里面） | 核心必跑；绑定套件推荐跑（或看 diff 是否碰绑定接线区） |
| merge / push 前最终门禁 | **全量绿**（分层用途：模块套件求快的开发内环，全量求全的收尾门禁，两者不矛盾） |

## 四、建议方案

1. **拆文件**：K/L/L2x/M 段拆为 `tools/verify/editor-binding-smoke.mjs`（自带 boot，
   独立文件比单文件打 tag 干净）。
2. **双入口**：`package.json` 增加 `editor:smoke`（默认核心套件）与
   `editor:smoke:binding`（绑定套件）。
3. **sleep → waitFor**：统一条件轮询帮手（轮询断言条件、超时上限兜底），
   替换全部固定 sleep。
4. **去重**：B+I 合并为一段；B2 与 D 的逐名比对留一份。
5. **L2c 搬迁**：像素健康度移入 cdp-verify.mjs（视觉域）。
6. **N 段省一次 reload**：切回 zh 直接改 localStorage。

## 五、预期收益

- 日常 UI 改动的冒烟从 **~7 分钟 → ~3 分钟**（配合 waitFor 实测可能更低）；
- 绑定改动仍有专属全链路回归，覆盖不减；
- 断言清单与文件分工声明一致（结构归结构、视觉归视觉）；
- 后续新增模块（刷怪点、Play 控制器扩展）按同一模式各立套件，不再膨胀单文件。

## 六、不能删的（繁得有理）

- **G2 / G2b / G2c**：分别是 codex / Copilot 评审抓出的三类真实回归
  （世界值当局部值写入文档、拖父节点子树不跟随、旋转拖拽不落盘）。
- **H 段画布高度门槛与布局几何断言**：2026-09-23 刚抓过 chrome-profile 残留
  `zh.ui.dockH=702` 把画布挤成 622×1 导致的批量假失败。
- **B2 的真源推导**：期望值全部从 `aether.project.json` + 起始场景推导而非硬编码，
  这是防"门禁长期红灯"的关键设计。

这三类是"繁"的成本里买回来的真实保护，精简方案不触碰。
