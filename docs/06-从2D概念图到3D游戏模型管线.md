# 06 · 从 2D 概念图到 3D 游戏模型管线

> 以 `E-04 盾卫（Bulwark）` 为例，说明如何把 `assets/characters/images/<id>/` 下的三视图概念图系统转化为可导入引擎、带 HumanIK + Mixamo 动画的 3D 角色。

---

## 1. 输入资产清单（以 E-04 为例）

| 资产 | 路径 | 状态 | 用途 |
|------|------|------|------|
| 正视图 | `assets/characters/images/E-04/front/E-04_front.png` | ✅ | 主参考：比例、正面剪影、装备分布 |
| 侧视图 | `assets/characters/images/E-04/side/E-04_side.png` | ✅ | 深度、盾板厚度、背部接口位置 |
| 攻击POSE | `assets/characters/images/E-04/attack/E-04_attack.png` | ✅ | 动作意图、动态剪影、武器/盾的使用方式 |
| 角色数据 | `assets/characters/roster.json` → `E-04` | ✅ | 身高、面数预算、攻击范围、弱点、AI 提示词 |
| 风格 Token | `assets/style/tokens.json` | ✅ | 配色、描边规则、toon ramp、材质指示 |

### E-04 关键设计约束

- **身高**：2.05 m（作为 Maya/Blender 导入时的缩放基准）。
- **面数预算**：1600 tris（roster 给出）。AI 生成阶段可先高面，重拓扑后落回此预算。
- ** silhouette 关键词**：厚重金属矩形 + 单侧巨大盾板，左右强不对称。
- **弱点**：背部两个红色发光脊椎接口（需在模型上用 emissive 材质标出）。
- **正面 120° 减伤 70%**：游戏逻辑，模型无需特殊处理，但盾板要足够大以暗示此机制。
- **风格**：美漫卡通描边、高饱和撞色、硬边偏移阴影。渲染侧已在 `03-渲染管线.md` / `05-NPC角色控制系统.md` 中定义。

## 3. 阶段详解

### 3.1 概念图标准化

AI 3D 生成对输入图的一致性要求很高。E-04 当前三张图已经比较规范，但生成前建议再检查：

1. **统一姿势**：front / side 尽量是 T-pose 或 A-pose，手脚不交叉。E-04 当前 front 接近立正，可用；side 需要确认未做大幅度转体。
2. **统一比例尺**：两张图人物高度像素一致。可用 Photoshop/GIMP 把两张图叠在一起，脚底和头顶对齐。
3. **去除文字/编号**：图中胸口的 `069` 编号会被 AI 当成纹理的一部分生成到模型上。如需编号，留在贴图阶段手动加。
4. **背景纯白/透明**：减少 AI 对背景噪声的误读。
5. **补一张背视图（可选但推荐）**：E-04 背部有两个红色接口，是重要游戏性元素。若侧视图已足够表达背部轮廓，可省略；否则建议生成 `back/E-04_back.png`。

### 3.2 AI 3D 生成

可用工具：腾讯混元 3D 生成（`buddy-cloud.py 3d`）、Meshy、Tripo3D、Rodin、CSM 等。本项目已内置 `3D模型与视频特效` skill，可直接调用混元 3D。

#### 推荐参数

```bash
# 以混元 3D 为例：用多视角生成，结果更稳定
python3 <SKILL_DIR>/scripts/buddy-cloud.py 3d \
  --multi-view '[
    {"ViewType":"front","ViewImageUrl":"<front-url>"},
    {"ViewType":"side","ViewImageUrl":"<side-url>"},
    {"ViewType":"back","ViewImageUrl":"<back-url>"}
  ]' \
  --enable-pbr \
  --face-count 80000 \
  --generate-type Normal \
  --result-format FBX \
  --token-stdin
```

- `--enable-pbr`：生成固有色、粗糙度、金属度、法线贴图，减少后续手绘工作量。
- `--face-count 80000`：先生成高面模型，供重拓扑和烘焙使用。
- `--result-format FBX`：后续 Maya/Blender 通用性最好；GLB 可作为引擎快速预览。
- 若没有背视图，用 `--image-url <front-url>` 单图生成也可以，但背面细节会靠 AI 脑补。

#### 生成后检查

- 比例是否正确（导入 DCC 后量身高是否为 2.05 m）。
- 左右不对称部位（盾板、右臂）是否被正确识别。
- 是否有漂浮碎片、破洞、错误的面部/手部结构。
- 贴图风格是否与 `tokens.json` 一致（高饱和、暖黄肌肉、冷灰金属、红色发光点）。

### 3.3 DCC 清理：重拓扑 + UV

AI 生成的模型通常面数过高、拓扑混乱，不适合游戏。需要导入 Blender 或 Maya 做清理。

#### 目标规格

| 项目 | 目标值 | 说明 |
|------|--------|------|
| 面数 | ≤ 1600 tris | roster 给出 |
| 拓扑 | 四边面优先，关键关节处环线 | 便于绑定变形 |
| UV | 1 套 0-1 UV，利用率 > 75% | 移动平台优先 1k 贴图 |
| 材质 ID | 3-4 个：皮肤、金属、发光、布料 | 对应 shader 参数 |

#### 拓扑策略

1. **先减面**：
   - Blender：`Decimate Modifier`（Planar 模式保留硬边）或 `InstantMeshes`。
   - Maya：`Retopologize`（自带）或 `Quad Draw` 手动。
2. **手动修正关键区域**：
   - 肩、肘、膝、腕处必须有多条环线，保证弯曲不变形。
   - 盾板作为独立物体或子网格，拓扑可更简化。
   - 背部两个红色接口保留为独立面，便于贴图做 emissive mask。
3. **保持剪影**：重拓扑后从正/侧/背三视图对比剪影，确保 `厚重金属矩形 + 单侧盾板` 特征未丢失。

#### UV 策略

- 用 `RizomUV` 或 Blender `UV Packmaster` 自动打包。
- 金属盾板、皮肤、发光接口分在不同 UV 岛，但共享同一套 UV。
- 如果后续要做 toon 材质，UV 需要给边缘描边和半调网点留出贴图空间（可选）。

### 3.4 贴图烘焙 / 风格化绘制

AI 生成的 PBR 贴图通常可以直接用，但需要根据项目风格校正。

1. **烘焙高模到低模**：
   - 把 AI 高模作为 high poly，重拓扑后的低模作为 low poly。
   - 烘焙：法线（Normal）、环境光遮蔽（AO）、曲率（Curvature）、固有色（BaseColor）。
2. **风格化调整**：
   - 使用 `Substance Painter` 或 `Photoshop`。
   - 颜色严格对齐 `tokens.json`：
     - 皮肤： zombie `#8FD14F` 向的黄绿色调，带血污 `#E8402A`。
     - 金属盾板：冷灰 + teal `#2BC4D6` 焊缝。
     - 发光接口：blood red `#E8402A` emissive。
   - 卡通渲染不需要真实粗糙度，但金属/非金属区分要做（存 metallic map）。
3. **输出贴图**：
   - BaseColor / Albedo（sRGB）
   - Normal（OpenGL / DirectX 按引擎选）
   - Metallic / Roughness / AO（灰度或合并通道）
   - Emissive mask（背部接口）

### 3.5 HumanIK 骨架定义与绑定

这是问题的核心。HumanIK 是 Maya 内置的通用角色化骨架系统，适合把自定义骨骼映射到标准人体，再与 Mixamo 动画互通。

#### 前提：先建立或确认骨骼

你有两种路线：

**路线 A：让 Mixamo 自动绑骨架，再转 HumanIK（推荐用于快速原型）**
- 把清理好的模型导出 FBX，上传 Mixamo。
- Mixamo 返回带骨骼和 skin 的 FBX。
- 在 Maya 中把 Mixamo 骨骼映射到 HumanIK 骨架。

**路线 B：先在 Maya 里手动绑 HumanIK，再重定向 Mixamo 动画（推荐用于生产）**
- 在 Maya 中自建/导入标准 skeleton。
- 用 `Skeleton > HumanIK` 创建 HIK 骨架并做角色化（Characterization）。
- 把 Mixamo 动画作为源，重定向到 HIK 角色。

#### 路线 B 详细步骤（Maya HumanIK）

1. **创建 HumanIK 骨架**：
   - `Animation` 模块 → `Skeleton > HumanIK`。
   - 选择 `Create > Skeleton Generator`，生成一套默认 HIK 骨骼。
   - 根据 E-04 体型调整骨骼位置：肩宽、臂长、腿长、盾板不影响骨架但需注意碰撞体。

2. **蒙皮（Skin）**：
   - 选择网格，再选择根骨骼，执行 `Skin > Bind Skin > Smooth Bind`。
   - 对肘、膝处刷权重，避免极端变形。
   - 盾板可单独作为一个关节的子物体，或与手腕骨骼 parent，不参与身体蒙皮。

3. **角色化（Characterization）**：
   - 打开 HumanIK 窗口，选择根骨骼，点击 `Create > Character`。
   - 把 HIK 骨骼节点拖入对应槽位（hips、spine、chest、neck、head、arm、leg 等）。
   - 点击 `Characterize` 完成。

4. **定义控制 Rig**：
   - `Create > Control Rig`，生成 FK/IK 控制器。
   - 给盾板加一个独立控制（可选），方便动画师调整角度。

### 3.6 Mixamo 自动绑定 + 动画重定向

Mixamo 提供大量僵尸/怪物通用动画（idle、walk、run、attack、death、hit reaction），非常适合本项目。

#### 步骤

1. **上传模型到 Mixamo**（需 Adobe 账号）：
   - 上传 `E-04_clean.fbx`（已重拓扑、有 UV、无骨骼）。
   - Mixamo 自动识别关节并绑定。下载带 `T-pose` 或 `skin` 的 FBX。

2. **下载所需动画**：
   - 搜索关键词：`zombie idle`、`zombie walk`、`zombie attack`、`zombie death`、`zombie hit`。
   - 每个动画单独下载为 FBX，选择 `Without Skin`（不带模型，只带骨骼动画）。

3. **在 Maya 中重定向到 HumanIK**：
   - 导入 Mixamo 动画 FBX。
   - 对该 Mixamo 骨骼做 Characterization（同样映射到 HIK 槽位）。
   - 在 HumanIK 窗口中：
     - `Source` = Mixamo 角色
     - `Target` = E-04 HIK 角色
   - 点击 `Retarget`。
   - 烘焙动画到 E-04 控制器：`Bake > Simulation`。

4. **处理非标准部位**：
   - Mixamo 不识别盾牌。盾牌需手动 parent 到左前臂或独立控制器。
   - 右臂肌肉肥大、左右不对称：重定向后检查手臂穿插，必要时手动修正关键帧。
   - E-04 头盔焊死、脖子粗短：头部动画幅度可能需要缩放或限制。

### 3.7 导出到引擎

#### Maya 导出设置（FBX）

- `File > Export Selection` → `FBX export`。
- 关键选项：
  - Animation：✅（如果包含动画）
  - Bake Animation：✅
  - Deformed Models / Skins：✅
  - Cameras / Lights：❌
  - Up Axis：`Y-up`（Aether/WebGPU 通常用 Y-up；Unity 也是 Y-up，Unreal 默认 Z-up 可转换）
  - Units：`Meters`
  - Axis Conversion：按引擎选择
- 命名规范：`E04_Bulwark_SK_<animationName>.fbx`
  - 例如：`E04_Bulwark_SK_idle.fbx`、`E04_Bulwark_SK_attack_shieldCharge.fbx`

#### GLB 快速预览（可选）

- Blender 可直接导出 GLB。
- 包含骨架、动画、PBR 贴图。
- 适合在浏览器或 Three.js/Babylon 中快速查看。

## 5. 本项目落地的具体顺序

1. **补全背视图**：用现有 front/side 通过 ImageGen 生成 `E-04_back.png`，重点露出两个红色脊椎接口。
2. **跑图生3D**：用 `buddy-cloud.py 3d --multi-view` 生成 E-04 高模，下载 GLB/FBX/OBJ。
3. **DCC 清理**：导入 Blender，重拓扑到 1600 tris，分 UV，烘焙贴图。
4. **Maya 绑定**：建立 HumanIK，做 Characterization，加控制 Rig。
5. **Mixamo 动画**：下载 idle/walk/attack/death，重定向到 E-04。
6. **导出入引擎**：按 `packages/` / `apps/` 中定义的资源规范命名并提交。

## 6. 风险与注意事项

1. **AI 3D 生成不是一键出游戏资源**：高模需要大量清理，不能直接进引擎。
2. **左右不对称是绑定难点**：Mixamo 默认假设人体左右对称。E-04 的盾板、右臂肥大、背部接口需要在重定向后手动修正。
3. **盾牌不要参与身体蒙皮**：作为 prop 或独立关节子物体，避免动画时盾牌随胸腔呼吸变形。
4. **HumanIK 角色化失败常见原因**：
   - 骨骼命名不规范；
   - 缺少必要节点（如 spine、head、手腕）；
   - 骨架比例异常（E-04 肩宽/头小，需要耐心对齐）。
5. **Mixamo 动画可能不适用于非人形**：E-04 接近人形，可用；B-03 等非人形 Boss 需要自研动画或 Motion Capture。
6. **风格保持**：卡通渲染依赖 NdotL 分阶（见 `tokens.json`）。贴图不要画得过于写实，保留平面色块和硬边阴影暗示。
