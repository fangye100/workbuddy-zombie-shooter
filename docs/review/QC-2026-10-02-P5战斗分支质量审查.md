## 3. 缺陷清单

### 🔴 B1 · `main.ts` 全文件行尾重写混进功能提交（blame 已毁）

**证据**
```
git diff --numstat main...HEAD -- apps/editor/src/main.ts   → 3793 / 3754
git diff --ignore-all-space --numstat ...                   →   39 / 0      ← 实质改动只有 39 行
main:apps/editor/src/main.ts | tr -cd '\r' | wc -c          → 3754          ← 全文件 CRLF
HEAD:apps/editor/src/main.ts | tr -cd '\r' | wc -c          →    0          ← 全文件 LF
（对照 session.ts：main 与 HEAD 都是 0 —— 仓库其余文件本就是 LF，只有它一个是 CRLF）
```
全部发生在单个提交 `958177d`（P5 C5，21:35）里。

**影响**
- `git blame` 对 3793 行全部指向这一个 commit，历史归零；
- PR diff 7542 行，人工 review 事实上不可能（我只能用 `--ignore-all-space` 反推）；
- 未来 cherry-pick / merge / bisect 的冲突面被人为放大。

**根因未除**：`.gitattributes` 只有 LFS 规则，**没有任何 `* text=auto eol=` 声明** —— 行尾全靠各工具的本地行为（历史上一度是 Python 写文本把行尾改坏，见项目记忆铁律）。这次只是把 CRUD 修回 LF，机制上没堵住。

**建议**
1. 拆成独立 commit（如 `chore: main.ts 行尾规范化 CRLF→LF`）→ **需 rebase，属 git 历史重写，须用户明确授权，我不动手**；
2. 补 `.gitattributes`：`* text=auto eol=lf`，并对 LFS 条目保留 `-text`；
3. 若 1 不可行，至少在 PR 描述里显著标注，避免后人误判改动量。

### 🔴 B4 · 抓到了「行为脚本从未注册」的 bug，却没加任何防线（最危险）

**证据**
`e7861ac` 自己写的注释：vite 的绝对路径 glob `/assets/behaviors/**/*.ts` 按 `apps/editor` 解析 → 零命中 → 浏览器端注册表空；而同一行在 vitest（root=仓库根）下命中 → 「编辑器断、测试绿」。
```
grep -rn "behaviorRegistry|W_BEHAVIOR_UNAVAILABLE" tools/verify/*.mjs apps/editor/test/*.ts  → 0 命中
package.json 无 combat-probe 脚本；editor:smoke:all = editor-smoke + editor-binding-smoke
```

**影响**
- ADR-018 的整套行为脚本能力在编辑器里**从未生效**，此前所有「行为已验证」的结论都是空的（typecheck + vitest 全绿，两者都抓不到）；
- 这类「宿主 root 分裂」缺陷的**检测成本极高**（只有人手工开浏览器才能看见），而修完之后仍然**只有手工能发现** —— 回归只是时间问题。

**建议**
1. `editor-smoke` 增加一条硬断言：`behaviorRegistry` 非空（或 `__editor` 暴露的注册数 > 0）；
2. 把 `combat-probe.mjs` 接入 `editor:smoke:all`，让它进门禁而不是靠人记；
3. 长效：给所有 `import.meta.glob` 写相对路径并加注释（已在做），最好再补一个「glob 命中数为 0 即 fail」的构建期检查。

## 4. 做得好的地方（值得保留的模式）

- **`applyDamage` 单入口红线贯彻彻底**：减血 / 受击高亮 / 事件派发 / kill 回收 / generation 防冒名 / 终态判定全收在一个出口，注释把「绕过 = 不可审计」的理由写清了。这是本分支最有价值的资产。
- **数值零魔法数字**：四态机的 windup/range/damage/cd 全部来自 `stats.hp/attack`，手枪数值来自 `PLAYER_WEAPON`，测试反过来锁真源值（E-01 hp=60、手枪 12/0.35/18）。
- **确定性纪律有实测**：同种子双会话逐位对跑；wave2 投放 tick 精确到 `clearedTick + 60`。
- **换代清理完整**：`reset()` 一并清战斗事件、会话事件、波次状态、终态、开火输入 —— 跨代污染这个坑本项目踩过多次，这次堵住了。
- **评审整改有独立审核**：`b7c1427` 的 P2 推迟重试防线（容量不足不丢波 + `W_SPAWN_CAPACITY` 可见）配套了对照组测试，不是自证。
