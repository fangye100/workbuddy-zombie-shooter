# 07 · 灯光与材质系统

> 定义「末日尸潮」怎么被照亮、怎么被着色。
> 与 `03-渲染管线.md` 的分工：**03 定义 pass 拓扑与资源流，07 定义着色模型**。
> 材质 shader 是可替换插件，两者不冲突。

---

## 0. 三条铁律（来自 `assets/style/tokens.json`，不可违反）

1. **toon 分阶在材质着色器里按 NdotL 做**，不要用 LUT 在最终颜色亮度上分阶。
   原因：LUT 分阶会误伤固有色本来就暗的材质（深色布料、墨线），把它们也切成两半。
2. **描边 = inverted hull**，线宽存顶点色 R 通道（0–1 → 0–8mm 世界空间），必须做摄像机距离补偿。
   描边色纯 `ink #14110F`，**禁止纯黑**，禁止用阴影代替描边。
3. **半调网点只叠暗部**（`lum < 0.45`），1080p 网点 4–6px，强度 ≤ 0.25。
   引擎对齐：描边 Pass 在 Opaque 之后；半调 + LUT 在 **Tonemap 之后、Grading 之前**。

---

## 1. 设计约束（决定了一切取舍）

| 约束 | 值 | 对灯光的直接影响 |
|---|---|---|
| 视角 | god view，俯角 **55°** | 见 §2，顶光会让角色变平色 |
| 同屏敌人 | **300–800** | 每像素的指令数必须极低，禁多光源循环 |
| 目标平台 | 手机横屏 | 无 TBDR 之外的红利，带宽是主要瓶颈 |
| 观察尺寸 | 角色仅几十像素高 | **剪影优先于细节**：rim 光比 AO 重要得多 |
| 风格 | 美漫卡通 | 色块干净 > 物理正确 |
| 关卡 | 4 幕 × 3 波 | 每幕一套灯光预设，波次之间做强度/色温插值 |

## 2. god view 的陷阱：顶视角 + 顶光 = 平色

这是本项目灯光设计的**头号问题**，先讲清楚。

55° 俯角下，相机主要看到的是角色的**头顶、肩膀、上背**。如果主方向光也从高处打下来
（美术直觉上"太阳在天上"），那么可见面上的 `NdotL` 几乎处处接近 1 —— 角色变成一坨
没有明暗结构的平色，剪影靠描边勉强撑住，但体积感全丢。

**三条对策，按优先级：**

1. **主光压低仰角到 25°–35°。**
   不要用顶光。即使是"正午"，也把 key 的仰角压到 30° 左右，让角色的侧面/背面形成
   明确的暗部。这是最有效、零成本的一招。
2. **角色光与环境光分离（character light）。**
   场景光负责氛围，角色额外吃一盏专用的、角度经过调校的 key。
   代价是角色与场景的光照不完全一致；收益是**无论关卡多暗，角色永远有清晰结构**。
   在尸潮里这是正确的取舍——玩家必须能在 0.3s 内读出每个敌人的剪影（见 `05-NPC角色控制系统.md`）。
3. **rim 光给"顶边缘"。**
   顶视角下传统 rim（视线与法线夹角）主要出现在头顶轮廓，作用有限但仍然关键：
   **暗场景里没有 rim，深色敌人会直接消失在背景里**。
   所以 rim 在本项目不是"锦上添花"，是**可读性刚需**。

## 3. 灯光模型：三层 + 局部

### 3.1 不走完整 PBR

`03-渲染管线.md` §3.3 写了 Cook-Torrance + GGX。那套留给**场景道具**。
**角色走风格化三层光**，理由是：

- 卡通风格要的是**可控的色块**，不是能量守恒的精确性。GGX 的长尾高光在卡通渲染里是噪声。
- 800 个角色跑完整 BRDF 的指令开销，在手机上直接吃掉整个渲染预算。
- 分阶本身就会破坏 PBR 的连续性，硬套 PBR 是自相矛盾。

### 3.2 三层光

```text
最终色 = albedo × [ toonRamp(NdotL_key) × keyColor × keyIntensity
                  + fill(N)            × fillColor × fillIntensity
                  + rim(N,V)           × rimColor  × rimIntensity
                  + ambient(N)         × ambientColor
                  ]
        + emissive
```

**关键决策：只有 key 参与 toon 分阶，fill / rim / ambient 是直接加色，不分阶。**

这是整个着色模型里最重要的一个选择。原因是多光源各自分阶会互相打架——
两盏光分别产生一个阶跃，合成后出现**三阶、四阶甚至阶跃打架的脏边**，色块不再干净。
让主光独占分阶权，其余光做柔和加色，能得到干净的二阶色块 + 正确的方向感，
而且成本最低。

| 层 | 物理含义 | 卡通含义 | 分阶 |
|---|---|---|---|
| **Key** | 主方向光，唯一投影光源 | 决定明暗大结构 | ✅ 唯一 |
| **Fill** | 半球环境（sky / ground 两色） | 决定暗部的颜色倾向 | ❌ 加色 |
| **Rim** | 边缘逆光 | 把剪影从背景里"抠"出来 | ❌ 加色 |
| **Ambient** | 常数项 | 兜底，防止纯黑 | ❌ 加色 |

```wgsl
// 半球环境：比 SH9 便宜一个数量级，卡通风格下更可控
fn hemisphereAmbient(n: vec3f, skyColor: vec3f, groundColor: vec3f) -> vec3f {
  let t = n.y * 0.5 + 0.5;
  return mix(groundColor, skyColor, t);
}

// rim：视空间，带 Fresnel 感但不做真实 Fresnel
fn rimTerm(n: vec3f, v: vec3f, power: f32, invertZ: f32) -> f32 {
  let ndv = clamp(dot(n, v), 0.0, 1.0);
  let fresnel = pow(1.0 - ndv, power);
  // god view 下把 rim 往"顶边缘"偏一点，补偿俯视角
  let topBias = mix(1.0, n.y * 0.5 + 0.5, invertZ);
  return fresnel * topBias;
}
```

### 3.3 分阶函数（含抗锯齿）

**必须用屏幕空间导数自适应软边**，否则远处摩尔纹、近处硬锯齿：

```wgsl
fn toonStep(threshold: f32, softness: f32, x: f32) -> f32 {
  // fwidth 让软边宽度随 NdotL 的屏幕空间变化率自适应
  let w = fwidth(x) * 0.5 + softness;
  return smoothstep(threshold - w, threshold + w, x);
}
```

`softness` 对应 tokens 里的 `edgeSoftness = 0.035`。这是**下限**，
实际宽度是 `fwidth(NdotL) * 0.5 + 0.035`。

### 3.4 完整 toon 求值

```wgsl
struct ToonParams {
  shadowEnd:   f32,  // 0.30  暗部上界
  specStart:   f32,  // 0.88  高光下界
  softness:    f32,  // 0.035
  shadowMult:  f32,  // 0.55  暗部亮度倍率
  shadowMix:   f32,  // 0.30  暗部混入 night-deep 的比例
  shadowSat:   f32,  // 1.05  暗部饱和度
  litSat:      f32,  // 1.12  亮部饱和度
  specMix:     f32,  // 0.35  高光混入 bone 的比例
  _pad: f32,
  shadowTint:  vec4f, // night-deep #0E0C16
  specTint:    vec4f, // bone      #FFF6E2
};

fn applyToon(ndotl: f32, baseColor: vec3f, p: ToonParams) -> vec3f {
  let litMask = toonStep(p.shadowEnd, p.softness, ndotl);

  // 暗部：压亮度 + 色相偏移到紫蓝，而不是压成灰
  let shadowCol = saturate(baseColor * p.shadowMult, p.shadowSat);
  let shadowCol = mix(shadowCol, p.shadowTint.rgb, p.shadowMix);

  // 亮部：提饱和，保持高饱和撞色
  let litCol = saturate(baseColor, p.litSat);

  var c = mix(shadowCol, litCol, litMask);

  // 高光阶：叠加在亮部之上，仅金属 / 湿润 / 黏液启用
  let specMask = toonStep(p.specStart, p.softness, ndotl);
  c = mix(c, mix(c, p.specTint.rgb, p.specMix), specMask);

  return c;
}
```

**注意 `saturate()` 是调饱和度不是 clamp**，不要和 WGSL 内置的 `saturate`（clamp 0-1）混淆。
实现：

```wgsl
fn adjustSaturation(c: vec3f, amount: f32) -> vec3f {
  let l = dot(c, vec3f(0.2126, 0.7152, 0.0722));
  return max(vec3f(0.0), mix(vec3f(l), c, amount));
}
```

## 4. 描边（inverted hull）

### 4.1 基本做法

- 第二遍绘制同一网格，`cullMode: 'front'`，顶点沿法线外扩。
- 线宽存**顶点色 R 通道**（0–1 → 0–8mm 世界空间）。
- 描边 Pass 在 **Opaque 之后**（同属主 render pass，先画描边再画本体，depth test 处理遮挡）。
- 描边**不接光照**，输出纯 `ink` 色。

### 4.2 屏幕空间恒定线宽

世界空间外扩量固定时，远处角色的描边会细到看不见。要让**屏幕空间线宽恒定**，
世界外扩量必须正比于到相机的距离：

```wgsl
@vertex
fn vs_outline(@location(0) pos: vec3f,
              @location(2) smoothNormal: vec3f,
              @location(4) color: vec4f) -> VSOut {
  var out: VSOut;
  let worldPos = (model * vec4f(pos, 1.0)).xyz;
  let dist = distance(cameraPos, worldPos);

  // widthPx → 世界空间：正比于距离，反比于投影缩放
  let widthWorld = color.r * maxWidthMeters
                 * dist * frame.projScaleY
                 / frame.viewportHeight;

  let n = normalize((model * vec4f(smoothNormal, 0.0)).xyz);
  let expanded = worldPos + n * widthWorld;

  out.clip = frame.viewProj * vec4f(expanded, 1.0);
  return out;
}
```

`projScaleY = 1 / tan(fovY / 2)`，由 CPU 每帧算好传进来。

### 4.3 法线断裂（真坑）

硬边几何（立方体、盾板）的顶点法线在棱边处不连续，沿法线外扩会让描边**在棱角处裂开**。

**解法：额外存一份平滑法线**，专门给描边用。
在烘焙/导入阶段按位置合并顶点、平均法线、写回第二套法线属性。
成本是每顶点多 12 字节（可量化到 `snorm8x4` 省到 4 字节）。

顶点布局：

| location | 语义 | 格式 | 用途 |
|---|---|---|---|
| 0 | position | float32x3 | |
| 1 | normal | float32x3 | 着色用（可保留硬边） |
| 2 | smoothNormal | float32x3 | **描边外扩专用** |
| 3 | uv | float32x2 | |
| 4 | color | float32x4 | **R = 线宽，G = AO 强度** |

### 4.4 描边不能被后处理冲淡

纯 `ink #14110F` 经过 AgX tonemap 和 grading LUT 会被提亮、染色，描边会"发灰"。
**正解：MRT 输出一张 aux 通道，标记描边像素，后处理时只做 tonemap，跳过 grading / 半调 / vignette。**

主 Pass 输出两张 RT：

| location | 格式 | 内容 |
|---|---|---|
| 0 | `rgba16float` | HDR 场景色 |
| 1 | `rgba16float` | `rgb` = 调试数据（法线 / NdotL / albedo，按 debugMode 切换），`a` = 描边 mask（0/1） |

## 5. 半调网点

只叠暗部，屏幕空间，旋转 45°，模仿美漫印刷网点。

```wgsl
fn halftone(fragCoord: vec2f, lum: f32, p: HalftoneParams) -> f32 {
  if (!p.enabled) { return 0.0; }

  // 先算出这个像素的网点密度（暗部才有）
  let amount = (1.0 - smoothstep(p.lumThreshold - 0.12, p.lumThreshold, lum)) * p.strength;
  if (amount <= 0.001) { return 0.0; }

  // 旋转 45°，让网点不跟像素网格对齐产生摩尔纹
  let c = 0.70710678;
  let r = vec2f(c, -c);
  let rot = vec2f(fragCoord.x * r.x - fragCoord.y * r.y,
                  fragCoord.x * r.y + fragCoord.y * r.x);
  let uv = rot / p.dotSize;

  // 圆点：比 sin 网格更接近印刷网点
  let f = abs(fract(uv) - 0.5);
  var d = length(f) * 2.0;   // 0 中心 → 1 边缘

  // 抗锯齿 + 远处淡出：网点周期接近像素大小时会产生严重摩尔纹
  let lod = fwidth(uv.x) * 2.0;
  let fade = 1.0 - smoothstep(0.35, 0.9, lod);
  d = mix(d, 1.0, 1.0 - fade);   // 淡出时把网点拉满 → 不画

  return (1.0 - smoothstep(amount - 0.15, amount + 0.15, d)) * fade;
}
```

参数：

| 参数 | 值 | 说明 |
|---|---|---|
| `dotSize` | 4–6 px @1080p | 太小会摩尔纹，太大像波普艺术 |
| `strength` | ≤ **0.25** | 硬上限，超过就变成"网点风格"而不是"印刷质感" |
| `lumThreshold` | **0.45** | 只叠暗部 |
| 淡出 | `fwidth` 驱动 | 远处/小物体自动消失，必须的 |

## 6. 材质分类

对应 `roster.json` 里的角色部位，每类的 toon 参数不同。

| 材质 ID | 用途 | 分阶 | 暗部偏移 | 高光阶 | 半调 | 描边 | 备注 |
|---|---|---|---|---|---|---|---|
| `skin` | 僵尸皮肤（E-01…E-05） | 2 阶 | 强 0.30 | 弱（黏液湿润） | 强 | 4px | 主色 `zombie #8FD14F` 向黄绿，带 `blood` 血污 |
| `metal` | 盾板 / 武器（E-04） | 2 阶 | 弱 0.12 | **强** | 无 | **6px** | 冷灰 + `teal #2BC4D6` 焊缝 |
| `cloth` | 衣物 / 绷带 | 2 阶 | 中 0.22 | 无 | 中 | 4px | `edgeSoftness` 放大到 0.08，软边 |
| `emissive` | 脊椎接口 / 毒液 | **不分阶** | — | — | 无 | 4px | 直接输出 + 喂 bloom |
| `glass` | 毒液 / 培养舱 | 1 阶 | 弱 | 强 | 无 | 3px | 透明队列 |

**关键实现：材质差异全部走 uniform，不产生 shader 变体。**
分阶开关用 `shadowEnd >= 1.0` 表示"不分阶"，高光用 `specMix == 0` 关闭。
这样 5 类材质共用同一份 shader，没有 permutation 爆炸。

- 每幕的 fog 颜色必须与 fill sky 同色系，否则远处物体会"跳出"雾。

## 8. 光源预算（手机端）

| 类型 | 数量 | 说明 |
|---|---|---|
| 方向光 | **1**（唯一投影） | CSM 4 级 |
| 半球环境 | 2 色 | 比 SH9 便宜，更可控 |
| 动态点光 | **≤ 32** | clustered，仅给爆炸、枪口近距等"需要照亮周围"的 |
| 聚光 | ≤ 4 | 仓库顶灯、手电 |

### 最大的省钱点：发光 ≠ 光源

僵尸的红色脊椎接口、毒液、弹道拖尾、远处的爆炸——**这些全部用 emissive + bloom 伪造，
不占光源名额**。

只有真正需要**照亮周围几何**的才配真点光：

| 效果 | 真光源？ | 理由 |
|---|---|---|
| 角色脊椎接口 | ❌ emissive + bloom | 只自己亮，不照亮别人 |
| 毒液地面 | ❌ emissive + decal | 同上 |
| 枪口火焰 | ✅ 点光（1 帧） | 需要照亮射手和附近墙面 |
| 爆炸 | ✅ 点光（衰减 0.3s） | 需要照亮整个区域 |
| 隧道应急灯 | ✅ 聚光 | 需要照亮通道 |
| 子弹拖尾 | ❌ emissive | 纯自发光 |

这条规则能把动态光源数从"几百"压到"个位数"，是移动端能跑 800 敌人的前提之一。

## 9. LOD 与着色降级

`05-NPC角色控制系统.md` 定义了三级表现 LOD。着色侧对应降级：

| LOD | 表现 | 着色 |
|---|---|---|
| L0 Full | 骨骼动画，< 20m | 完整三层光 + 2 阶分阶 + 半调 |
| L1 VAT | 顶点动画纹理，20–50m | **1 阶**（只分亮/暗），关半调，保留 rim |
| L2 Proxy | 面片/impostor，> 50m | **不分阶**，预烘焙平均色 + 描边，只吃 ambient |

**L1 是成本大头**（几百只 VAT 实例）。1 阶分阶省掉一次 `mix` 和半调的全部开销，
实测能省 30–40% 的 fragment 指令。40m 外的角色只有几十像素，2 阶和 1 阶肉眼无差。

## 11. 坑列表

1. **顶视角 + 顶光 = 平色**（§2）。最隐蔽也最常见，美术会本能地把光放头顶。
2. **多光源各自分阶 → 阶跃打架**。只允许 key 分阶（§3.2）。
3. **别忘了 `fwidth` 抗锯齿**。分阶和半调都要，否则远处摩尔纹、近处硬锯齿。
4. **描边法线断裂**。硬边几何必须另存一份平滑法线（§4.3）。
5. **描边被 tonemap / grading 冲淡**。用 MRT 的 aux alpha 做豁免（§4.4）。
6. **半调点满整个屏幕**。必须只叠暗部 + `fwidth` LOD 淡出，强度硬上限 0.25。
7. **发光全用真点光**。光源数瞬间爆炸，见 §8 的判据表。
8. **fog 颜色与 fill sky 不同色系** → 远处物体"跳出"雾。
9. **`saturate` 命名冲突**：WGSL 内置 `saturate` 是 clamp(0,1)，调饱和度要自己写函数（§3.4）。
10. **uniform 里用 `vec3f` 会被 pad 成 16 字节**。要么全写 `vec4f`，要么严格对齐，
    否则会出现"改了参数没反应"的玄学 bug。
11. **描边的 depth bias**。外扩后与本体 z-fighting，需要 `depthBias` 或稍微多推一点。
12. **MSAA 与 MRT 同时开**：两张 RT 都要 `sampleCount: 4`，resolve 目标也要匹配，容易漏配。
