# WebGPU 游戏引擎 — 架构总览与主循环

> 代号建议：**Aether**（`aether-core`）。后文统一称 Engine。
> 目标：纯浏览器原生、零插件、以 WebGPU 为一等公民的模块化游戏引擎 + 编辑器工具链。

---

## 1. 设计目标与非目标

### 1.1 目标

| 目标 | 说明 |
|---|---|
| GPU 现代特性优先 | Compute / Indirect Draw / RenderBundle / Timestamp Query 全面使用，不为 WebGL 妥协 |
| 数据驱动 | ECS + SoA 布局，热路径零对象分配、零 GC 抖动 |
| 显式但不过度 | 资源生命周期由 FrameGraph 自动推导，但仍可手动 escape hatch |
| 可伸缩 | 从 2D 小游戏到中量级 3D（50 万三角面 / 2000 draw call 级别）同一套代码 |
| 热迭代 | Shader / 脚本 / 资产 热重载，编辑器内实时预览 |
| 可诊断 | 内建 CPU/GPU 时间线、内存账本、渲染调试视图（overdraw / light count / HiZ） |

### 1.2 非目标

- 不追求 AAA 级画质（不做完整光追管线，不做影视级毛发/流体）
- 不内置 WebGL2 后备渲染（提供 `NullBackend` 用于服务端/测试，WebGL2 留给社区插件）
- 不做主机/移动端原生导出（但通过 Deno + wgpu 可跑本地工具链）

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────────────┐
│ L6  Tooling & Editor      编辑器 / 资源烘焙 CLI / 性能剖析器        │
├──────────────────────────────────────────────────────────────────┤
│ L5  Gameplay & Subsystems ECS 系统集 / 脚本 / 物理 / 动画 / UI /    │
│                           音频 / VFX / 网络 / AI / 存档            │
├──────────────────────────────────────────────────────────────────┤
│ L4  Scene & Asset         World / Transform / Prefab / LOD /       │
│                           流式加载 / AssetDB / 序列化               │
├──────────────────────────────────────────────────────────────────┤
│ L3  Renderer              Clustered Forward+ / 阴影 / GI / 后处理   │
│                           Material & Shader 变体 / Debug View      │
├──────────────────────────────────────────────────────────────────┤
│ L2  FrameGraph            声明式 Pass DAG / 虚拟资源 / 生命周期推导  │
│                           自动 MSAA resolve / 内存别名 / Pass 合并  │
├──────────────────────────────────────────────────────────────────┤
│ L1  GPU Abstraction       Device / Queue / BindGroupCache /         │
│                           PipelineCache / RingAllocator / ShaderDB │
├──────────────────────────────────────────────────────────────────┤
│ L0  Platform              Canvas / Input / Clock / VFS / Worker /   │
│                           AudioContext / 存储                      │
└──────────────────────────────────────────────────────────────────┘
```

**依赖规则（强制）**：只允许向下依赖。L5 各子系统之间禁止直接引用，一律通过 L0/L4 的
`EventBus`、`ResourceHandle<T>`、`World` 查询来通信。L3 不认识 ECS——它只消费
`RenderWorld`（一帧的渲染快照），这是保证渲染可并行、可回放的关键。

### 2.1 包划分（pnpm monorepo）

```
aether/
├─ packages/
│  ├─ core/          # 无依赖：math / ECS / scheduler / time / event / reflect / serialize
│  ├─ platform/      # Canvas, Input, Clock, VFS(IndexedDB/HTTP/内存), WorkerPool, Storage
│  ├─ gfx/           # WebGPU 设备与资源层（L1）
│  ├─ framegraph/    # 声明式 Pass 图（L2）
│  ├─ render/        # 渲染特性与管线（L3）
│  ├─ scene/         # World / Transform / Camera / LOD / Streaming（L4）
│  ├─ assets/        # glTF / KTX2 / .pak / 烘焙管线接口（L4）
│  ├─ animation/     # 骨骼 / 动画图 / 状态机 / IK / Morph
│  ├─ physics/       # Rapier(WASM) 适配层 + 物理组件同步
│  ├─ vfx/           # GPU 粒子 / 拖尾 / 贴花 / 图化特效
│  ├─ ui/            # 保留模式 UI / Flex 布局 / SDF 文字 / 输入焦点
│  ├─ audio/         # WebAudio 图 / 3D 空间化 / 总线与快照
│  ├─ input/         # 设备抽象 + Action Mapping + 重绑定
│  ├─ script/        # TS 运行时 + HMR + (可选) WASM/QuickJS 沙箱
│  ├─ net/           # WebTransport/WebSocket, 预测回滚, 状态同步
│  └─ editor/        # Inspector / Gizmo / 资源浏览器 / Profiler UI
├─ tools/
│  ├─ baker/         # Node CLI：资产烘焙 glTF→.mesh/.pak，KTX2 转码，图集打包
│  ├─ shaderlab/     # WGSL 预处理、变体展开、校验（调用 naga/tint）
│  └─ trace/         # 抓取 .trace 回放与对比
├─ apps/
│  ├─ playground/    # 示例场景集合
│  └─ samples/       # 最小可运行样例（01-triangle ... 20-clustered）
└─ docs/
```

**依赖方向**：`core` ← `platform` ← `gfx` ← `framegraph` ← `render` ← `scene`；
`animation / physics / vfx / ui / audio` 只依赖 `core + platform + scene(+render 只读接口)`；
`editor` 依赖全部，**但没有任何包依赖 editor**。

## 3. 运行时主循环

### 3.1 时钟模型

- **固定步长逻辑**：`FIXED_DT = 1/60`（可配），累加器最多追 5 步（防死亡螺旋）。
- **可变步长渲染**：跟随 `requestAnimationFrame`，用 `alpha = acc / FIXED_DT` 在
  `prev/curr` 双缓冲变换之间插值 → 视觉平滑，逻辑确定性。
- **可确定性**：固定步长内禁用 `Math.random`（用 seeded PRNG）、禁用 `Date.now()`。

### 3.2 一帧时序

```
requestAnimationFrame(now)
 │
 ├─ 0. FrameBegin   ── clock.tick(now) / gpu.beginFrame() / profiler.frame()
 │
 ├─ 1. Input        ── input.poll() → InputState + ActionFrame（边沿检测、消费队列）
 │
 ├─ 2. FixedUpdate  ── while (acc >= FIXED_DT) {
 │                        net.rollbackOrAdvance()      // 网络：回滚/重模拟
 │                        script.fixedUpdate()
 │                        physics.step(FIXED_DT)       // 内部子步
 │                        animation.advance(FIXED_DT)  // 采样 → pose buffer
 │                        gameplay.fixedUpdate()
 │                        world.applyCommands()        // ECS 结构变更同步点
 │                      }
 │
 ├─ 3. Variable     ── script.update(dt) / camera / UI layout / VFX spawn / AI LOD
 │
 ├─ 4. Interpolate  ── transform.interpolate(alpha) → 写入 RenderTransform SoA
 │
 ├─ 5. Extract      ── 从 World 抽取 RenderWorld 快照（并行 Job，零拷贝视图）
 │
 ├─ 6. Culling      ── compute: frustum + HiZ 遮挡 + meshlet 剔除 → indirect args
 │
 ├─ 7. RenderGraph  ── build() → compile()（资源生命周期/别名/合并）→ execute()
 │
 ├─ 8. Submit       ── queue.submit([...])；timestamp query resolve
 │
 ├─ 9. Present      ── profiler.endFrame() / 统计滑窗 / 自动降档（Adaptive Quality）
 │
 └─ 10. HotReload   ── 帧尾安全点：替换 shader / 脚本 / 资产（不入 in-flight 帧）
```

**关键约束**：第 5 步 Extract 之后，逻辑 World 允许被下一帧修改；RenderWorld 是
in-flight 帧的只读快照，被回收进 ring pool（3 帧轮转，防止 GPU 还在读时复用）。

### 3.3 任务调度（Job System）

- 主线程 + `WorkerPool`（`SharedArrayBuffer` + `Atomics`，需 COOP/COEP 头；不支持时
  降级为主线程 `scheduler.yield()` 协作式调度）。
- ECS System 声明读写集（`reads: [Transform], writes: [Velocity]`），调度器做冲突检测
  后生成 DAG，拓扑排序 + 并行执行。
- 任务粒度目标 0.1–1ms；避免跨 worker 传递结构化对象，只传 `ArrayBuffer` + 元数据。

### 3.4 调度阶段（SystemSet）

```
enum Stage {
  First, PreUpdate, FixedUpdate(并行于物理流水线), Update,
  PostUpdate, Extract, Prepare, Render, Last,
}
```
自定义系统通过 `app.addSystem(Stage.Update, mySystem).after(other).before(x)` 注册，
同一 Stage 内无依赖者自动并行。

## 4. 核心抽象与接口风格

| 抽象 | 形态 | 说明 |
|---|---|---|
| `ResourceHandle<T>` | 数字 id（index + generation） | 所有 GPU/资产资源只传句柄，杜绝生命周期悬挂 |
| `Arena<T>` | SoA TypedArray + freelist | 组件存储；generation 检测 use-after-free |
| `RingBuffer` | 3 帧 in-flight 轮转 | Uniform / Staging / RenderWorld 快照 |
| `CommandBuffer` | 延迟指令队列 | ECS 结构变更、资源创建/销毁，在同步点批量应用 |
| `Feature<T>` | 可插拔渲染特性 | `setup / execute(graph, view) / shutdown` |
| `Plugin` | 应用级扩展单元 | `build(app: App)`，所有子系统以 Plugin 形式挂载 |

**代码示例（目标风格）**：

```ts
const app = new App()
  .addPlugin(PlatformPlugin({ canvas, workerCount: 4 }))
  .addPlugin(GfxPlugin({ requiredFeatures: ['timestamp-query'], tier: 'tier1' }))
  .addPlugin(ScenePlugin)
  .addPlugin(RenderPlugin({ pipeline: 'clustered-forward-plus', shadows: 'csm-4' }))
  .addPlugin(PhysicsPlugin({ backend: 'rapier-wasm', fixedHz: 60 }))
  .addPlugin(AnimationPlugin({ skinning: 'compute' }))
  .addPlugin(UIPlugin).addPlugin(AudioPlugin).addPlugin(VFXPlugin)
  .addPlugin(ScriptPlugin({ hmr: true }))
  .run();
```

## 5. 语言与构建

- **主语言 TypeScript 5.x**（`strict`、 `noUncheckedIndexedAccess`），目标 ES2022。
- 热路径数学库自己写，**全部用 `Float32Array` 承载**，对外暴露不可变式 API（写回式：
  `Mat4.mul(out, a, b)`），避免对象分配。
- 物理/资产解码等重计算走 **Rust→WASM**（Rapier、gltf 解析、KTX2 转码、meshopt）。
- 构建：Vite（app）+ tsup（packages）。WGSL 以 `?raw` 导入，构建期做 `#include` 展开
  与变体预编译，运行时只做 permutation key 命中缓存。

## 6. 技术选型决策表

| 议题 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 渲染路径 | **Clustered Forward+** | Deferred / Visibility Buffer | 透明与 MSAA 友好，材质灵活；WebGPU 带宽受限下 deferred 的 GBuffer 代价高 |
| 抗锯齿 | **TAA + 自研 TAAU 上采样** | MSAA / SMAA | 与动态分辨率配合，成本可控；MSAA 作为静态场景可选项 |
| GI | **Light Probe(SH) + SSR + DDGI(可选)** | 全烘焙光照贴图 | 动态场景友好，烘焙管线成本高 |
| 物理 | **Rapier(WASM)** | 自研 | 自研成本极高；Rapier 确定性较好，且 SIMD WASM 性能足够 |
| 剔除 | **GPU-driven（compute + indirect）** | CPU 剔除 | CPU 省略数千次 JS 调用，是 WebGPU 相对 WebGL 的最大红利 |
| 脚本 | **TypeScript 原生 + HMR** | Lua/WASM 沙箱 | 零跨语言成本，HMR 体验最好；沙箱留给 UGC/Mod 场景 |
| 资源管理 | **FrameGraph 自动推导** | 手工管理 | WebGPU 显式同步下手工管理极易出 bug |

## 8. 编码规范（要点）

- 文件命名 `kebab-case.ts`，类型 `PascalCase`，常量 `SCREAMING_SNAKE`。
- 热路径禁止：闭包分配、`for...of` 于 TypedArray 之上（用索引循环）、`try/catch`、
  `Object.keys`、模板字符串拼接（日志走编译期开关）。
- 所有 GPU 对象创建走 `GfxDevice` 工厂，禁止业务代码直接持有 `GPUDevice`。
- 所有跨线程数据必须是 `Transferable` 或 `SharedArrayBuffer`。
- 每个子系统必须有 `stats()` 返回统一结构的性能账本，供 Profiler 聚合。
