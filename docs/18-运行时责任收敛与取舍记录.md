# 18 · 运行时责任收敛与取舍记录（WU-0）

对应 `docs/17` 的第 6 节 WU-0。本文记录「新写的 World vs 仓库已有实现」的取舍结论，
以及本轮验收场景的冻结定义。后续 WU 以此为准，不再重复论证。

核对基线：分支 `feature/headless-runtime`，HEAD `3ac11ba`。

---

## 1. 取舍结论

判据用 `docs/17 §3.2` 的三个问题：
① 换一个游戏仍有意义吗？② 关掉编辑器独立运行还需要吗？③ 换 CLI 执行规则应该相同吗？

### 1.1 实体状态表：废弃 `runtime/World`，改用 `CharacterTable`（`@aether/gameplay`）

| | 新写的 `runtime/World` | 已有的 `CharacterTable` |
|---|---|---|
| 身份 | 数组下标，无 generation | **generation 单调递增**，槽位复用后旧身份必然失效 |
| 分离 | O(n²) 全对全 | 供 `CrowdSolver` 用的 `SpatialHash` 邻域查询 |
| 破对称 | 无（正面僵持会锁死） | `dodgeBias` ±1，两只 NPC 总往同侧错身 |
| 目标/状态 | 无 | `targetEntity` / `behavior` / `alertLevel` / `speedScale` |
| 池化 | 无 | `CharacterPool` + freelist |

**决策：废弃自研 World。**

理由：
- `docs/17 §3.5` 明令「每类运行状态只能有一个权威 owner，禁止长期同时维护两张
  可独立修改的角色状态表」。当前正是两张（World + CharacterTable）。
- `docs/17 §5.1` 要求「引入槽位复用时必须防止旧身份命中新实体，可评估复用已有
  generation 机制」—— `CharacterTable` 已有现成 generation，自研版本要重造一遍。
- 自研 World 只活了一天，没有历史包袱，正是替换成本最低的时刻。
- `CharacterTable` 是纯 CPU、零 DOM/GPU 依赖，符合 headless 约束
  （`docs/17 §3.5`：headless 只要求与 DOM/GPU/真实时间解耦，**不要求**禁止复用 `@aether/*`）。

**适配点**：`CharacterTable` 用数字 `defId`，场景 `SpawnPoint.characterId` 是字符串
（`'E-01'`）。需要一条 `characterId → defId` 的持久化映射 —— 见 §2。

### 1.2 移动与避障：改用 `FlowField` + `CrowdSolver` + `SpatialHash`（`@aether/ai`）

`packages/ai/src/navigation.ts` 已完整实现：Dial 桶环 Dijkstra 流场积分（可跨帧恢复）、
chamfer 距离变换烘焙离墙间隙、贴墙推力、邻域分离、僵持检测。全是纯 CPU。

**决策：直接用。** 自研等于造第三个轮子，且 `docs/17 §8` 第 3 条明确要求
「本轮场景的障碍真实参与移动约束」—— 只有流场 + 代价场能满足，直线追击做不到。

障碍来源：场景里 `Collider` 且 `isTrigger === false` 的节点（floor-1 已有 6 个掩体）。
作用域：场景里唯一的 `NavZone`（floor-1 的 `nd_f1_nav`，66×16，cellSize 0.5）。

### 1.3 世界变换：改用 `SceneGraph.updateWorldTransforms()`（`@aether/scene`）

`sim-level.mjs` 里手写的 `worldPosition()` 只累加父节点 `position`，忽略旋转与缩放。
`SceneGraph` 已有正确实现（TRS 组合 + depth 升序传播），且已实现 ADR-014 的
`snapshot()` / `restore()` —— 正好是 WU-4「Stop 恢复作者状态」所需要的。

**决策：删掉手写版本，走 `SceneGraph.fromDocument()`。**

### 1.4 角色参数：新增 `assets/characters/stats.json` 作为真源

现状问题：`sim-level.mjs` 的 `statsOf()` 用 `parseFloat('1.4 m/s')` 从 roster 抠数字，
再用 `Boss ? 0.6 : 0.35` 硬编码半径。`docs/17 §5.3` 点名禁止：「不以 parseFloat 加默认
常数掩盖缺失配置」。

根因：roster.json 是**美术/设计资料库**（`height: "1.75 m"`、`speed: "1.4 m/s"`、
`attack.range: "扇形 90° / 2.2 m"`），承担不了 `CharacterDef` 需要的
胶囊半径 / 质量 / 转向速率 / 视野 / 听觉 / 攻击距离等运行时数值。

**决策：新增独立的角色参数真源，两份文件分工明确。**

| 文件 | 责任 | 消费方 |
|---|---|---|
| `assets/characters/roster.json` | 外观、叙事、威胁等级、AI 提示词（美术/设计） | 画布施工、资产生成 |
| `assets/characters/stats.json`（新） | 运行时物理与 AI 数值（程序） | `CharacterDef` 生成 |

**防漂移**：`content:check` 交叉校验 —— 解析 roster 的 `speed`/`height` 首个数值，
与 stats.json 比对，不一致报 error。两份真源不会静默各改各的。

### 1.5 唯一状态 owner 总表

| 状态 | 唯一 owner | 说明 |
|---|---|---|
| 作者场景数据 | `SceneDocument`（`.scene.json`） | 唯一持久化真源 |
| 运行时场景结构 | `SceneGraph` | 派生量（world/depth）不落盘 |
| 实体状态 | `CharacterTable` | 含 generation，唯一权威 |
| 角色定义 | `CharacterDef`（由 stats.json 生成） | 只读 |
| 导航/避障 | `FlowField` + `CrowdSolver` | 每会话一份，来自装载产物 |
| 会话推进与查询 | `RuntimeSession`（`packages/runtime`） | 固定步、输入、种子 |
| 快照场景 | 显式导出的 `.scene.json` | **派生产物**，不回写作者场景 |

## 2. 验收场景定义（从 floor-1 冻结）

`docs/17` WU-0 要求：一个可进入战斗房间、一个尚未进入的刷怪区域、一个障碍物、
明确玩家起点，实体规模 ≤ 24。

`assets/scenes/act1/floor-1.scene.json` **已经满足前三条**，只需补玩家起点：

| 需求 | 落点 | 现状 |
|---|---|---|
| 可进入战斗房间 | `nd_f1r0` 房间 1 · 战斗（20×16，中心 10,0） | ✅ 已有，含 3 个刷怪点 |
| 尚未进入的刷怪区域 | `nd_f1r2` 房间 3 · 战斗（20×16，中心 56,0） | ✅ 已有，含 3 个刷怪点 |
| 障碍物 | `nd_f1r0_cv0/cv1/cv2` 掩体 1–3 | ✅ 已有，均带 `Collider{isTrigger:false}` |
| 导航作用域 | `nd_f1_nav`（66×16，cellSize 0.5） | ✅ 已有 |
| **玩家起点** | — | ❌ **缺失，本轮补 schema 字段 `playerStart`** |

实体规模：房间 1 = 5+4+3 = 12 只（E-01×9、E-02×3）；
房间 3 = 4+4+4 = 12 只（E-01×8、E-02×4）。合计 24，符合上限。

**临时模拟假设（不是产品行为，不得当作冻结基准）：**

1. 玩家在切片阶段**不移动**（无输入驱动）。WU-2 起由输入序列驱动。
2. 「进入房间」判定用**矩形 bounds 包含**玩家中心点，不用 Collider 触发器事件。
   真触发器系统属 Phase 2。
3. 刷怪后敌人**不再消失**（无战斗、无死亡）。
4. `CharacterDef` 的 `skeleton` / `bodyParts` / `animSet` / `animGraph` 本轮**全填 0**
   （尚未接入渲染资产），`bodyParts` 为空数组。这是显式的能力缺口，不是完成项。
5. `hurtboxes` 本轮为空 —— 无战斗系统。

**已知的旧结果失效**：`assets/scenes/sim/floor1-t{0,1,3,5}.scene.json` 是「所有房间
立即全部刷怪」时期生成的静态快照。改成房间进入触发后，这些快照不再代表当前规则，
属过期派生产物，保留作历史对照但**不作为本轮验收基准**。

## 5. WU-3 落地记录（动态实例渲染）

### 5.1 关键约束（调研阶段确认）

动态实体**不能**进入静态 `SceneGraph` 与 `MAX_OBJECTS`（64）槽位 —— 24 只僵尸就占掉
三分之一，500 只根本不可能。`MAX_OBJECTS` 的根因是 `renderer-core.ts` 里
`transformBuf` 的 buffer 大小（64 × 256B）；shader 侧 `scene.wgsl` 的
`transform` 是**单个** uniform 不是数组。所以动态实例**不碰 transformBuf**，
另开 storage buffer 就绕开了。

调研同时确认：全仓 instancing **完全不存在**（8 处 `drawIndexed` 的 instanceCount 全是 1，
无 `drawIndexedIndirect`，VAT 只有枚举没有任何渲染器读它）。WU-3 是全仓第一条 instancing 路径。

### 5.2 实现落点

| 层 | 文件 | 内容 |
|---|---|---|
| 引擎 | `packages/render/src/shaders/dynamic.wgsl.ts` | 新 WGSL：`vs_main` / `vs_outline` / `fs_main` / `fs_outline`；实例走 `@binding(3) var<storage, read> inst: array<DInst>`，用 `@builtin(instance_index)` 取行 |
| 引擎 | `packages/render/src/renderer-core.ts` | `CoreDynamicBatch` + `DYNAMIC_INSTANCE_FLOATS=12`；`dynamicLayout` / `dynamicPipeline` / `dynamicOutlinePipeline`；`drawDynamicBatches()` 插在 pass 1 的 `pass.end()` **之前** |
| 编辑器 | `apps/editor/src/services/runtime-bridge.ts` | `RuntimeBridge`：`start/stop/setPaused/stepOnce/reset/advance/batches/select/pickRay` |
| 编辑器 | `apps/editor/src/renderer.ts` | `setDynamicBatches()` 注入口 + `getDocument()` + 两个 debug 断言口 |
| 编辑器 | `apps/editor/src/main.ts` | 场景加载完成即 `bridge.start(doc)`；渲染循环 `bridge.advance(dt)` → `setDynamicBatches()`；HUD 运行时行；`screenRay()` + 运行时实体优先拾取 |

### 5.3 三个设计决定

1. **复用 pass 1 的 MRT + depth，不另起 pass**。动态实体因此自动参与 toon 分阶、雾、
   inverted-hull 描边、bloom / tonemap / 半调等全部后处理，与静态关卡是同一束光。
2. **按体型分组成多个 batch**（`meshId = capsule:r0.340:h1.750`）。网格按 (radius, height)
   生成并缓存，改体型即换 key。代价是「体型种类数」个 draw call（≤9），远好于 500。
   `GraphicsBuffer` 缓存归 core（ADR-001），调用方每帧传全量也不会重复上传。
3. **不引入第二套高亮管线**：选中 = 实例色 ×1.9。淡而无害，且不会误伤静态关卡的
   选中/悬停两层描边。

### 5.4 踩坑：WGSL 编译错误只有实机能抓

第一版把 `toon` 的 bind group visibility 写成只给 `FRAGMENT`，而 `vs_outline` 要读
`toon.outline` 算描边宽度 → 运行时 `CreateRenderPipeline` 直接抛
`Entry point's stage (ShaderStage::Vertex) is not in the binding visibility`，
编辑器进 fatal 页。

**`tsc --noEmit` 全绿、`vite build` 全绿、500 条单元测试全绿** —— 一条都拦不住。
只有 headed Chrome + 真实 GPU 打开页面才暴露。修法：toon 的 visibility 改成
`VERTEX | FRAGMENT`。

→ 与记忆里「WebGPU 编码期陷阱」完全一致：**每次新增 pipeline，必须实机跑一次**。
