# tools/mcp-binding — 绑定领域 MCP server（WU-2 起）

把 `BindingSession`（绑定编辑的唯一领域状态 owner）暴露成 MCP 工具，
让 Agent 能**看见**自己的绑定操作结果（视觉反馈闭环），并把调好的绑定
**导出成干净 T-pose 的 rigged GLB**（WU-3 起，与编辑器 exportBound 同管线）。

> ## 🚦 新 Agent 从这里开始（5 分钟上手）
>
> **一句话流程**：`load_model` → 出带网格的正/侧视图 → 看图定关节 → **用户确认**
> → 镜像 → **用户确认** → wrapper 半径 → 出图给用户 → `save` → `export_glb` → 门禁。
>
> **四条最容易踩的坑（先记住再动手）**：
> 1. 出图**必须带量化网格**（`render` 传 `grid:true`）—— 否则你只能看出「不对」，
>    说不出「差多少」，用户会反复来回描述。见 [铁律 0](#-铁律-02026-09-24-立优先级最高出图必须带量化坐标网格)。
> 2. `render` 的 `width/height` **静默钳制到 64..1024**；要更细看就**裁切放大**，
>    不是加分辨率。
> 3. `cylinders autoFit` **会跳过 `manual:true` 的圆柱并成功返回**（`changed:0`）——
>    静默空操作。全手动表上必须先 `unpin`。
> 4. **「在不在肉里」的判据判不了「在对的位置」** —— 定位必须靠解剖标志 + 骨段比
>    + 用户判读。见 [判据效力排序](#判据效力排序从强到弱)。
>
> **两条硬纪律**：joint 阶段 `showCylinders:false`（圆柱会污染判读）；
> 每个阶段交付前**必须出图给用户核对**，确认后才进下一阶段。
>
> 🔴 **用本 server 摆骨骼 joint 前必读**：
> [骨骼节点视觉修正流程](#-骨骼节点视觉修正流程强制纪律2026-09-23-e-01-事故沉淀) ——
> 必须可视化（截图看图）修正，每轮核对必须过独立审核员子代理直到 PASS，
> joint 经用户确认后才许进 wrapper 阶段。禁止盲调坐标。
>
> 🔴 **手臂/腿近直（自然下垂）时不要硬算关节位置** —— 没有几何拐点，
> 各信号必然矛盾。走
> [近直肢体（手臂链）收敛方法](#近直肢体手臂链收敛方法--2026-09-24-e-01-复盘)：
> 出候选高度对照图 + 明确推荐值/副作用表 + `AskUserQuestion` 单选，一轮收敛。
>
> 🔴 **进行骨骼对齐时，先关掉圆柱体的 Skin Wrapper**（MCP 路径：`render` 传
> `showCylinders:false`；编辑器路径：`__editor.binding.wrappers.set(false)`），
> 等骨骼验证通过以后，再显示出这个 Skin Wrapper——半透明 proxy 圆柱会污染
> 截图，干扰 joint 与模型关节的对位判读。

```
Agent ──MCP(stdio)──▶ server.mjs ──▶ dist/domain.mjs ──▶ BindingSession
                        │                （同一套领域操作，GUI 与 Agent 共享）
                        └── node:fs / zlib（PNG 编码）
```

## 分层（改动前先读）

| 文件 | 职责 | 约束 |
|---|---|---|
| `src/render.ts` | 正交投影光栅器：点云/骨线/关节/wrapper 轮廓/热力 → RGBA | 纯 TS，**禁 import node:*** |
| `src/tools.ts` | 工具表 + 参数校验 + `BindingDomain`（持有 session，fs 走注入的 `FsPort`） | 纯 TS，**禁 import node:*** |
| `src/domain-entry.ts` | esbuild 打包入口 → `dist/domain.mjs` | 纯 TS |
| `server.mjs` | NDJSON stdio 帧 / node:fs / PNG 编码 / 版本协商 | 零依赖 .mjs，不进 typecheck |
| `probe.mjs` | 自检：构建 → spawn → 全链路断言 | 零依赖 .mjs |

纯 TS 层被 `tsconfig.check.json` 覆盖（include `tools/mcp-binding/src/**`）。
仓库未装 `@types/node`，所以**任何 node API 只能出现在 .mjs shell 里**——
这是分层存在的理由，不要把 node import 写进 src/。

两条工具层语义（与 GUI 对齐，独立审核收口）：

- **历史粒度 = 一次工具调用一步**：MCP 没有 GUI 的手势边界（pointerup），
  每次写工具成功后立即 `sealHistory()` 封口 800ms 合并窗——Agent 脚本化连调
  不会被并步，undo 粒度与工具调用一一对应。
- **错误通道**：参数非法 / 前置条件不满足 → JSON-RPC `-32602`（带中文原因）；
  实现 bug → `-32603`。骨名一律过 HUMANIK_ORDER 白名单（不用活引用键查，
  防原型链键污染）。

## 工具表（16 个）

| 工具 | 语义 |
|---|---|
| `load_model` | 载入仓内 .glb（parseGlb 默认 2.05m 标尺 = 编辑器同尺）；sidecar 有 bindingEditor 自动回填 |
| `get_state` / `get_joints` | 会话总览 / 27 关节坐标 + 合法骨名表 |
| `set_joint` / `mirror` / `reset_pose` | 摆关节（自带历史）/ 左右镜像 / 回模板 T-pose。`mirror` 参数 `dir` = `'L2R'` \| `'R2L'`：**`R2L` = 以角色右侧为准镜像到左侧，右侧一字不动**（圆柱一起复制）。🔴 **方向必须先跟用户确认** —— 用户说「镜像到另外一边」时，若他先前对某一侧做过专门修正，那一侧就是标杆；搞反会覆盖掉他的决定 |
| `undo` / `redo` | 撤销重做（与 GUI 同一历史栈纪律） |
| `cylinders` | wrapper 表操作：get / autoFit / setRadius / setOffset / clearOffset / mirror / mirrorAll / unpin。⚠️ `autoFit` **跳过 `manual:true` 的圆柱**且成功返回（`changed` 可为 0）——全手动表上等于空操作，要先 `unpin` |
| `set_options` | 权重导出选项（weightMode / smooth* / mirrorWeights；越界按面板同款钳制） |
| `compute_skin` | 算权重只回统计（未包裹顶点数等），不回权重数组（token 纪律） |
| `render` | **视觉反馈核心**：正/侧视 PNG 图像块，可选 heatBone 热力图、selectedJoint 高亮；`style:'toon'` = 实心填充 + 深度台阶/掠射法线翻转边的实体轮廓线（2D 卡通效果，重叠在躯干上的四肢清晰可见，无线框噪音）；`azimuthDeg`（±60°）= 视差观察角，投影前绕 Y 旋转，错开重叠肢体判读；<br>🔴 `grid:true` = **量化坐标参考线**（工程图风格网格 + 刻度数值，单位米）。**给用户看的图必须开**。配套 `gridStep`（默认 0.05）/ `gridMajor`（默认 5 → 0.25m 标数值）。网格线画在模型下层、数值在最上层带白描边；回包给 `grid.stepM` / `grid.majorEveryM`，不用猜间距。⚠️ `azimuthDeg≠0` 时网格不再对齐世界轴，别叠用。<br>⚠️ `width/height` **静默钳制到 64..1024** —— 要 1400×1900 会拿到 1024×1024，不要以为出图失败；要更细看就**裁切放大** |
| `get_editor_data` / `save` / `hydrate` | 编辑态读 / 写 sidecar（validateAssetMeta 守门）/ 从 sidecar 重灌 |
| `export_glb` | 导出干净 T-pose 的 rigged GLB（编辑器 exportBound 同管线 `rigToTPoseWithImage`）。只回统计不回字节；已有 sidecar 外科式刷新 sourceHash/updatedAt，没有则提示跑 `scene:gen`。目标已存在需显式 `overwrite:true`（覆盖源模型恒拒） |

两条导出边界（WU-3 定）：

- **动画烘焙不走 MCP**：`BindAnimationInput`（BVH 重定向轨道）是 retarget 的领域，
  编辑器面板独占；`export_glb` 产物只含静态 T-pose 绑定。

是编辑器面板的徽标语义（不进持久化），MCP 导出后它们不变是预期行为。

## 🚦 完整实操流程（2026-09-24 E-01 全流程验证版）

> 这一节是**可照抄的操作序列**。E-01 从「模板骨架」走到「导出」的实际路径，
> 每一步对应的工具/脚本与判据。**括号里是用户确认门 —— 没有用户确认不许往下走。**

### 阶段划分与确认门

```
【准备】load_model → 出正/侧图（grid:true，showCylinders:false）
          ↓
【Joint 阶段】逐部位定关节（中轴 → 右半身）
          └─ 每改一处：出图 + 骨段长度对比表 → 交给用户判读
          └─ 🚧 门 1：用户确认「这一侧关节 OK」→ 才允许镜像
          ↓
【镜像】mirror(R2L 或 L2R —— 方向必须用户确认)
          └─ 🚧 门 2：用户确认「骨架位置 OK」→ 才允许进 wrapper
          ↓
【Wrapper 阶段】offset 清零 → 半径（密度峰值）→ 权属检查 → 出图
          └─ 🚧 门 3：用户确认「圆柱贴合 OK」→ 才允许导出
          ↓
【导出】save → export_glb → scene:check
```

### 每步的具体做法

| # | 步骤 | 工具/命令 | 判据与注意 |
|---|---|---|---|
| 1 | 载入 | `load_model`（sidecar 有 `bindingEditor` 自动回填） | 回填 = 续上次编辑，不是重置 |
| 2 | 出基准图 | `render` × {front, side}，`grid:true, showCylinders:false, style:'toon'` | 必须带网格；必须关圆柱 |
| 3 | 定中轴 | `set_joint` × N（Hips/Spine*/Neck/Head） | 按**背深比例**（脊柱靠背 ~27% 深度）；骨段别悬殊 |
| 4 | 定右半身 | `set_joint` × N（右锁骨/臂/肘/腕/指尖、右髋/膝/踝/趾） | 按**真裆 + 髋在裆上 2–4cm**、膝/踝判据；x/z 取实测截面，y 靠解剖标志 |
| 5 | **改完必须算骨段** | 脚本读 `session.positions` 算 `d(a,b)` | 输出「改前 → 改后」表：上臂:前臂、大腿:小腿、各段长。**副作用必须主动上报** |
| 6 | 独立审核 | 起**全新子代理**（独立上下文）看图 + 给 PASS/FAIL | 判据 = 解剖位置 + **沿肢体方向的落点**（铁律 7）；不许自证 |
| 7 | 🚧 门 1 | 出图（带网格）+ 骨段表 → 问用户 | 用户确认后才动作镜像 |
| 8 | 镜像 | `mirror`，`dir` 已确认 | `R2L` = 右为标杆、右不动。镜像后**逐对校验 Δ=0** |
| 9 | 🚧 门 2 | 出镜像后的正/侧图 | 用户确认骨架后才进 wrapper |
| 10 | wrapper offset | `cylinders setOffset [0,0,0]` × 全部 | **先做这步再谈半径**（E-01：清零 offset 就把未包裹 51%→28%） |
| 11 | wrapper 半径 | `cylinders setRadius`（各骨 bottom/medium/top） | 用**密度峰值**，不用分位数（分位数在包破布） |
| 12 | 权属检查 | 脚本按 `skin-proxy.ts` 语义算 top 归属 | 查跨部位抢权重（胸腔压颈 / 手咬膝 / 髋吞大腿根） |
| 13 | 🚧 门 3 | 出正/侧全貌图（`showCylinders:true, grid:true`） | ⚠️ 投影须含圆柱，见「出图投影必须含圆柱」 |
| 14 | 落盘 | `save` | 写 sidecar `bindingEditor`，`validateAssetMeta` 守门 |
| 15 | 导出 | `export_glb` | 产物 = 干净 T-pose；已有 sidecar 会外科式刷新 sourceHash |
| 16 | 门禁 | `pnpm run scene:check` | 105 资产同步 / 12 tests |

### 出图必须自带的东西（缺一个用户就会来回问）

| 元素 | 为什么 |
|---|---|
| **世界坐标网格 + 刻度数值** | 铁律 0。没有它用户无法量化距离 |
| **视角名**（`FRONT`/`SIDE`/`TOP`） | 正侧视与 az=±45 视差图长得像，曾被问「你给的这是侧45度」 |
| **关节名缩写**（`LUL`/`RFA`/`LFT`…） | 纯色十字用户要猜哪个点是什么 |
| **新旧对照**（灰=旧 / 红=新） | 用户要判断「改动对不对」，不给对照他就得记上一张图 |
| **结论的数字** | 「脚踝后移 6cm」胜过「脚踝往后来一点」 |

### 收尾纪律（每次改 sidecar 后固定四步）

```
① 闭环：run 归属（高模！）+ 射线奇偶 + 骨段比表
② 门禁：pnpm run scene:check
③ 出定稿图（带网格）→ 在**最终回复里写明完整绝对路径**（用户要拿去别的窗口引用）
④ commit + push（逐笔，中文 message）
```

## 🔴 骨骼节点视觉修正流程（强制纪律，2026-09-23 E-01 事故沉淀）

### 铁律 0（2026-09-24 立，优先级最高）：出图必须带量化坐标网格

**任何给用户看的绑定截图都必须带世界坐标网格 + 刻度数值**（用户令：「你要给出坐标参考线
我才能量化距离……以后截图默认就能有」）。没有网格的图只能看出「不对」，说不出
「差多少、往哪改」，用户只能反复来回描述。

| 路径 | 开关 |
|---|---|
| MCP `render` | `grid: true` + `gridStep`（默认 0.05）/ `gridMajor`（默认 5）= **脚本出图必须显式传** |
| 编辑器绑定面板 | `gridOn = true`（**默认开**）· `gridStepM = 0.05` · `gridMajorEvery = 5` |

**为什么这条能省掉整个像素↔世界标定环节**：网格与投影函数**严格对称**地反算可见世界
范围，所以网格线一定落在「世界坐标 = step 整数倍」上 —— 读数 = **数格子 × step**。
以往每次换窗口/DPR/裁剪/clip 比例都要重推标定，还因混用两种 clip 比例把脚趾坐标读错过。

🔴 **画布尺寸不是固定的**：`apps/editor/index.html` 的 `.bd-stage .bd-canvas` 是
`flex:1 1 auto; width:100%; height:100%` —— 尺寸随窗口变（见过 370×704 与 370×760 两种）。
所以 README 旧版那套常数（`px = 185 + 305.4·u` / `py = 699.2 − 305.4·y`）**只在某个
窗口尺寸下成立，不要当固定值用**。要标定就按 `computeViewFit()` 现算：
`scale = min(w·0.86/spanH, h·0.86/spanY)`、`originX = w/2`、`originY = h·0.92`，
并用渲染图里的 joint marker 圆点反验（误差 <1px 才算数）。**能用网格就别标定。**

**交付前自检网格精度**（1 分钟）：预测 `k×step` 应出现的行，去画布像素里查 ——
命中率应 ~100%、偏差 ≤1px。E-01 实测 44/44、最大 1px。

### 铁律（违反任何一条 = 返工）

1. **必须可视化修正**：joint 摆放只能以「自己截的图」为依据，把 joint 点
   对到模型的**生物关节**上（肘点对肘弯、膝对膝盖、脊柱沿背部弧线、头链进颅腔）。
   **禁止**用点云/数值聚类等量化分析代替看图——不看图就不可能对准关节。
2. **截图必须自己拍**：自己控制的浏览器 + 编辑器截正/侧视图。
   **禁止**拿用户提供的标注图做坐标换算（不知道画布 rect 与裁剪比例，换算必错）；
   用户的标注图只用来理解「他指的问题是什么」。
3. **批处理，不逐点循环**：一次截图 → 把一侧身体 + 中轴的全部 joint 一次算好 →
   批量 `set_joint`（或 hook `pose`×N）→ `mirror` → 存盘 → 重截图复核。
   禁止「调一个 joint 截一次图」的逐点循环。
4. **每轮截图核对必须过独立审核员，直到 PASS 为止**：每完成一轮摆放，
   启动一个**全新上下文**的子代理 reviewer（独立模型 + 独立上下文，
   与调整者不同源），按**生物关节可视程度**逐关节审核截图；
   FAIL 就按审核员证据修正后重截重审，循环到 PASS。
   自己（调 joint 的那个 agent）审核自己 = 无效，不许自证。
   ⚠️ 审核员必须同时判**沿肢体方向的落点**（铁律 7），只核「在不在肢体上」
   会给出假 PASS——E-01 肘位偏高那次就是这么漏过去的。
5. **先 joint 后 wrapper，两阶段硬分离**：joint 阶段截图前**必须关掉 wrapper
   proxy 总开关**（半透明圆柱会迷惑对位判断）；joint 调整必须经**用户确认**后
   才允许进入 wrapper 调整阶段。
   **镜像要放在「一侧定稿」之后、wrapper 之前**，且**方向必须先问用户**：
   `mirror` 的 `R2L` = 以角色右侧为准、右侧一字不动。E-01 事故：用户说「镜像到
   另外一边」，我按 L→R 理解并把用户专门定过的 `RightArm 1.650` 当成「要被覆盖的值」
   去问，方向搞反被纠正 —— **用户此前对某一侧的专门修正 = 那一侧是标杆的信号。**
6. **破损衣物会污染轮廓判断**：布条/破袖口超出肢体真实轮廓（E-01 肘部教训：
   审核员曾按轮廓极值 PASS 了贴着肚子的肘）。判据以解剖位置为准，
   不以轮廓极值/剪影外包为准。
7. **「落在 run 内」只证明在肢体上，不证明在肢体的哪个高度**（2026-09-24 新增，
   最贵的一条）：joint 投影落在剪影 run 内是**必要非充分**判据。E-01 事故里
   肘位明显偏高，闭环却报「20/20 全绿、0 悬空」——因为它只问「在手臂上吗」，
   没问「在手臂的哪一段」。必须叠加**沿肢体方向的定位判据**：
   骨段长度比（上臂:前臂该落在 0.8–1.2）、横截面等效半径极小点（腕）、
   外缘斜率转折（肘），或直接交给用户判读。**只跑 run 归属就宣布 PASS = 自证空转。**
8. **近直肢体没有几何拐点 → 立即停止数值推断，出候选对照图让用户点**：
   手臂自然下垂（近直）时肘部不存在可测的几何拐点，各信号必然互相矛盾
   （见下节实测表）。此时任何「加权折中」都是在噪声里挑数，越算越自信。
   正确动作：把 4–5 条**候选高度横线**画在真实网格渲染图上，列清单让用户单选。
   一次收敛，且用户判读天然带创作意图（这些模型本来就是按概念图捏的）。
9. **改一个 joint 必须量化连带效应并主动上报**（不许只报「改好了」）：
   关节是链，挪肘会改上臂/前臂比，挪肩会改整条链。每次改动后**必须**输出
   骨段长度前后对比表；发现副作用（如「上臂 0.225m < 手 0.388m」）立刻点名，
   并给出候选修正点。用户对解剖比例有最终裁决权——但**他必须知道自己的选择
   破坏了什么**，否则问题会在他下次看图时才爆出来。

### 近直肢体（手臂链）收敛方法 —— 2026-09-24 E-01 复盘

> 背景：用户连续两轮驳回肘位（「那么明显的外形结构你视图看不出来么？」），
> 而我的几何测量每次都「通过」。下面是那次真正收敛的路径，**下次遇手臂/腿
> 近直姿态直接照抄**。

**第一步：先把矛盾摆出来（禁止先动手改）**

在**高模 4K 贴图渲染**上把所有可测信号各量一遍，列成对照表。E-01 实测：

| 信号 | 指向的肘高 y |
|---|---|
| 法线褶皱扫描（径向对齐度骤降 → 横向折痕） | 1.09–1.13 |
| 前视外缘斜率转折 | ~1.06 |
| 上臂/前臂等分（肩、腕两点较硬） | 1.14–1.17 |
| 概念设定图逐行量臂宽（最粗点） | ~1.15 |
| 当时 sidecar 现值 | 1.135 |

表一出来结论就明确了：**没有单一信号可信**，继续算就是自欺。到这一步必须停手。

**第二步：出候选对照图，让用户单选**

- 在**真实网格**渲染图上画 4–5 条候选横线（间距 ~0.04–0.06m），每条一个
  字母 + 该高度的骨段长度比，**不要只给一个推荐值**。
- 同时出「两条骨架链对比图」（旧 vs 候选），让用户直接看骨段怎么变。
- 用 `AskUserQuestion` 单选，并附一题多选「除了高度还有什么不对」
  （腕 / 左右不对称 / 前后 z）——E-01 那次用户就是在一题里额外勾了 z 和腕，
  一次性把三个问题都暴露了。

**第三步：用户判读 vs 解剖比例冲突时——照做 + 立刻量化副作用**

- E-01 用户选了 1.250，导致上臂只剩 0.225m、比手（0.388m）还短。
  **不要驳回、不要静默折中。** 执行 → 立刻输出骨段对比表说明「上臂比手短」→
  给出修正候选（肩该提到哪）→ 用户随即同意提肩（1.45 → 1.580）。
- 纪律：**用户对「像不像」有裁决权，你对「比例坏了」有报警义务。** 两者都要做。

**第四步：x / z 不许拍脑袋 —— 取该高度横截面的实测中点**

肘位的 y 由用户定，x/z 由几何定：

```
在目标高度 y ± 2~3cm 带内取该侧肢体的顶点
  → x = 该带 x 范围中点（或轮廓 run 中点）
```

E-01 网格本身左右不对称（手臂差 1.5–3.5cm、小腿差 8cm、脚差 4.9cm）。两种做法各有代价：

| 做法 | 好处 | 代价 |

```
③ 出纯正交正/侧视图 + 带骨段长度标注的结果图给用户
```

### Wrapper 阶段定位/半径方法 —— 2026-09-24 E-01 沉淀

> 背景：E-01 的 `bindingEditor.cylinders` 里 11 根圆柱带着**乱拖的 offset**
> （`LeftLeg [0,-0.130,0.200]` = 侧移 13cm / 前后 20cm），是上个 session 拖去「追破布」留下的。
> 圆柱根本不在肉上，`unwrappedVerts = 2160 / 4209 (51.3%)`。

**① 先把 offset 清零（通常是主要病灶，不是半径）**

```
for 每根骨: cylinders action=setOffset offset=[0,0,0]
```
E-01 实测：仅清零 offset → **2160 → 1178 (28.0%)**。先做这一步再谈半径。

**② 半径禁用分位数反推 —— 分位数在包破布**

用「未包裹顶点的 dr p90」反推半径能得到很漂亮的数字（E-01 → 127 / 3.0%），
但代价是四肢半径膨胀到可见肉身的 **1.9–2.8 倍**，并造成**跨部位抢权重**
（`Spine2.top=0.300` 让颈前表面 49% 归胸、上臂内侧面 25% 归胸；
`LeftHand.top=0.132` 咬到膝盖外表面）。**根因：p90 在包破布/腐肉/描边壳，
而这些按设计就该在圆柱外面。**

两条可用的替代口径（E-01 实测三者互相印证）：

| 口径 | 腿（下/中/上） | 臂 |
|---|---|---|
| **密度峰值**（推荐）：顶点按「最近骨段」归属 → 归属内 dr 直方图 bin 5mm → 取峰 | 0.095 / 0.158 / 0.106 | 0.147 / 0.078 |
| 解剖经验值（上个 session 手工调） | 0.10 / 0.10 / 0.10 | 0.09 |
| 独立审核员看图量「可见肉身半宽 ×1.3」 | 0.08 / 0.115 / 0.105 | 0.075 / 0.095 / 0.08 |

密度峰值的含义 = **肉的主表面半径**（破布是分布尾部，不动峰）。

⚠️ 单切面峰值噪声极大（前臂会出现 0.185→0.035 的跳变）——必须**整段聚合**再取峰。

**③ 抢权重判据（比「包没包住」更重要）**

`unwrappedVerts` 只说明「肉有没有被包到」，不说明「谁被谁包了」。必须另算
**权属分布**：按 `skin-proxy.ts` 的语义（包内 w = 1 + 8·归一化穿透；包外窄晕带
`min(r/4, 2.5cm)`）逐顶点算出 top 归属，然后查跨部位嫌疑：

- 胸腔上端是否压住颈部 / 三角肌？
- 手部末端是否咬到膝盖（手臂自然下垂时手离膝很近）？
- 髋/大腿根是否互相吞？

E-01 定稿修法：`Spine2` top 0.240→**0.200**、medium 0.240→**0.210**；
`Neck` 0.090→**0.105**（让颈前表面归 Neck 而非 Spine2）。

**④ 出图投影必须含圆柱（否则十字错位，肉眼即见）**

`render.ts` 的 auto-fit 把 **capsules 端点 ± 半径** 也纳入包围盒（`extend(au, av, r)`）。
自己写脚本出「网格 + 圆柱 + 关节十字 + 标签」叠加图时，若变换只按 mesh 顶点算，
与渲染图不是同一个包围盒 → **两层错位十几厘米**（现象：`HD` 标签浮在头顶上方）。

修法 = 复刻完整 auto-fit：`points + segments端 + capsules端±max(r) + markers 0.02`。
自检：从渲染图里的关节 marker 圆点反解变换，与你的变换对表，**rms 应 < 1px**。

🔴 **并且 auto-fit 无条件含 markers 的 ±0.02**（不看 `showMarkers`）——
自写叠加脚本必须传 `withMarkers:true` 才对齐。E-01 实测：`false` → 平均误差
**2.66px**（错位）；`true` → **0.51px**。

> 注：**关节阶段（`showCylinders:false`）的图受后者影响，不受前者影响** ——
> 那时 capsules 为空，但 markers 仍在。两处都要按上面办。

**⑤ 僵尸/破损模型的正预期**

`unwrappedVerts` 不可能归零：破布、腐肉、外露骨、背负物、外扩描边壳按设计就在
圆柱外。E-01 定稿 **1280 / 4209 (30.4%)** 即为可接受值 —— 判据是**权属是否合理**
＋**图上可见肉身是否全覆盖**，不是这个百分数。原文档「迭代到未包裹 = 0」对破损
模型是**不可达目标**，不要再以此为目标死磕。

### 下肢（髋 / 膝）定位判据 —— 2026-09-24 E-01 补充

> 背景：用户指出「大腿和 hip 的 joint 不对，太低了，膝关节和脚的位置还可以」。
> 实测确认髋被放在了 y=0.900，而该模型**真裆在 0.980** —— 髋关节压在裆下方 8cm。

**① 先量真裆：两腿内侧间隙的骤降点**

逐层（每 1cm）量两腿内缘间隙 `gap = 左腿 x_min − 右腿 x_max`：

```
E-01 实测： y=0.94 gap=+6.3cm   y=0.97 gap=+4.5cm   ← 还有缝
           y=0.98 gap=+2.1cm   y=0.99..1.06 稳定在 2.1–2.9cm  ← 已并拢进躯干
→ 真裆 = 0.980（gap 骤降的那一层）
```

**② 髋关节在裆「上方」2–4cm，不是与裆同高**

解剖：股骨头中心 ≈ 耻骨联合上缘 / 大转子尖水平，会阴（裆）在其下 2–4cm。
按模型尺寸等比放大（E-01 高 2.05m ≈ 1.75m 人的 1.17 倍）→ **2.5–4.5cm**。
E-01 定稿 **UpLeg y = 0.995**（裆 0.980 上方 1.5cm，取区间保守侧；0.990–1.010 可接受）。

🔴 **别为凑比例把关节放到症状位置。** 独立审核员原话：
「比值是**诊断指标**，不是**目标函数**。」E-01 第一版按「大腿:小腿 =1.0」算出 y=0.970，
正好落在裆线上 —— 这就是让症状决定了位置。正确顺序是：先定解剖位置（裆上方），
再用比例**检查**它是否合理。

**③ 大腿 : 小腿 比例作为交叉检查**

| | 大腿 | 小腿 | 比 |
|---|---|---|---|
| 改前（髋 0.900） | 0.393 | 0.461 | **0.85** ← 大腿比小腿还短，明显错 |
| 第一版（髋 0.970，压在裆上） | 0.472 | 0.461 | 1.02 |
| **定稿（髋 0.995）** | **0.496** | 0.461 | **1.08** |

合理区间 ≈ **1.0–1.1**；< 0.9 = 髋太低或膝太高。注意上下限：超过 ~1.12 时髋会贴到腰线。

**④ Hips（骨盆根）位置**

应在**腰最细处下方**、两髋之间偏上。E-01：腰最细 y=1.060（z 深度最小）、
Hips=1.040（腰下 2cm）、与两髋垂直间距 4.5cm、与 Spine 相距 0.156m。

**⑤ 判据效力排序（别用弱判据下强结论）**

| 判据 | 能回答 | 不能回答 |
|---|---|---|
| **射线奇偶投票**（点在封闭网格内，Möller–Trumbore 求交，交点数奇数=在内） | **在不在肉里** ✅ 真判据 | ❌ 判不了高度/位置 |
| run 归属（投影落在剪影 run 内） | 在不在肢体上 | ❌ 判不了在肢体的哪一段 |
| 12 方向射线包围 | 只能做**快速体检** | ❌ **会假 PASS**（见下） |

🔴 **12 方向包围会假 PASS**：它测的是「周围有没有几何」，不是「点在不在肉里」。
夹在两层之间的空隙（驼背与脖子之间的凹、破布与身体之间）也会得高分。
E-01 实测：Neck 改前（z 落在颈柱后 6cm 的**空隙**里）**9/12**，改后（真在颈柱**内部**）
**也 9/12** —— **区分不出来**。历史上我曾拿它当「在肉里」的依据，是错的。

🔴 **但所有「在肉里」判据都判不了「在对的位置」**。铁证：`Spine2` 改前
`(1.450,−0.260)` 与改后 `(1.600,−0.200)`，12 方向都给 12/12、射线奇偶都给 6/6。
→ **判据只用来排除明显错误**（悬空、穿出体外、跑到别的肢体上）；
**定位必须靠解剖标志 + 骨段比 + 用户判读**。

**⑥ 射线奇偶投票的用法（判「在不在肉里」）**

用**高模 OBJ 的三角面**做 Möller–Trumbore 射线求交，向 6 个轴向各投一次，
**≥3/6 判在内**。E-01 实测全部非 tip 骨 6/6 在内。

**它还能量出「合法区间」**（比单点判定有用得多）：固定 (x,y) 沿 z 每 2cm 扫一次 ——
E-01 实测 `y=1.600` 胸腔合法 z = **[−0.28, +0.04]**；`y=0.507` 左膝合法 z 只有
**[−0.15, −0.10]**，而关节在 −0.082 → **体外约 2cm**（12 方向判据说 12/12，完全没抓到）。

⚠️ **`*Tip` 骨恒在外是预期的**（`isTipBone` → 不参与蒙皮、不建 wrapper），别误判为缺陷。
⚠️ 前提是**封闭流形**；有孔洞的减模只报「该判据不适用」，别硬下结论。

**⑦ 定位要靠「解剖标志」，不是坐标猜**

E-01 沉淀的四条（详见 skill `binding-geometry-audit`）：

| 部位 | 判据 | E-01 实测 |
|---|---|---|
| 髋 | **真裆** = 两腿内缘间隙的**骤降点**（🔴 别用「中轴最低网格点」，那是破布/臀沟）；髋在裆**上方 2–4cm** | 裆 0.980 → 髋 0.995 |
| 膝 | 大腿:小腿 比应 ≈1.0–1.1（<0.9 = 髋太低） | 改前 0.85 → **1.08** |
| 脊柱 | **背深比例**：脊柱靠背，约在背面往前 **27% 深度**（🔴 别用「躯干 z 中点」，会偏前 10cm） | (y1.600, z−0.200) |
| 颈 | **颈柱** = `|x|<0.08` 的 z 连通块；🔴 **光验 y 不够，必须同时验 z 落在柱内** | 颈柱 y1.48–1.68；改前 z=+0.020 落在**柱后 6cm 空隙**里 |

🔴 **「比值是诊断指标，不是目标函数」**（独立审核员原话，用户认可）：
E-01 第一版为凑「大腿:小腿 = 1.0」反推出髋 y=0.970，而 0.970 正好压在裆线上 ——
这就是让症状决定了位置。**正确顺序：先按解剖定位置，再用比例检查它是否合理。**

### 像素 ↔ 世界坐标标定（路径 B 读图用；**能用网格就别用这个**）

🔴 **画布尺寸不是固定的** —— `.bd-stage .bd-canvas` 是 `flex:1 1 auto; width/height:100%`，
尺寸随窗口变（E-01 会话里见过 **370×704** 与 **370×760** 两种）。所以下面这类常数
**只在对应窗口尺寸下成立，不要当固定值**：

```
px = w/2 + scale · (前视 x | 侧视 z)
py = originY − scale · y
# E-01 某次实测（w=370,h=704）：scale=295.62、originX=185、originY=h*0.92=647.68
```

要标定就**按当前画布现算**（`computeViewFit()`，`binding-panel.ts`）：

```
scale   = min(w·0.86 / spanH, h·0.86 / spanY)   # spanH=max(x幅,z幅), spanY=y幅（模型 bbox）
originX = w/2
originY = h·0.92
```

**必须用渲染图里的 joint marker 圆点反验**（圆点是 2D 层画的、位置精确）：
把预测像素与检测到的圆点质心对表，**误差 <1px 才算标定成立**。
面板尺寸/fit 改过 → 常数全部失效，必须重测。

⚠️ 裁剪/缩放过的截图：先 `page = ix/clipScale + 裁剪原点` 还原页面坐标，
再减去画布页面原点。E-01 会话曾因混用两种 clip 比例把脚趾坐标读错。

> **有了内建网格（铁律 0）后，这条基本用不上了** —— 直接从图上数格子即可。
> 只在「必须读原始渲染图的像素位置」时才需要标定。

### 标准循环（每轮必须走完审核员门）

> 两条路径的**操作动词不同、纪律相同**。下面用 `[MCP]` / `[编辑器]` 标出。
> 建议照抄 [完整实操流程](#-完整实操流程2026-09-24-e-01-全流程验证版) 的 16 步表。

```
── Joint 阶段（先）───────────────────────────────────────
[MCP] load_model（sidecar 自动回填）      [编辑器] open(path)（sidecar 自动回填）
[MCP] render(showCylinders:false, grid:true)   [编辑器] wrappers.set(false)
      # 关 proxy + 开网格，出干净的「网格 + 骨架」
→ 截正视 + 侧视（可疑部位另 clip 放大）
→ 一次读图：算出**标杆侧 + 中轴**全部 joint 的目标坐标
   ✅ 用网格读数（数格子 × step），不要重推像素标定（画布尺寸会变）
   ⚠️ 例外：肢体近直（自然下垂的手臂/腿）时肘·膝没有几何拐点，
     不要硬算——转「近直肢体收敛方法」出候选对照图让用户单选
   ⚠️ 定位靠解剖标志：真裆 / 背深比例 / 颈柱 / 骨段比（见判据节）
→ [MCP] set_joint × N      [编辑器] pose × N → 面板「保存绑定」
→ 出骨段长度前后对比表（改动的连带效应必须上报，铁律 9）
→ 启动独立审核员（全新子代理）：
    输入 = PNG 文件路径 + 当前 27 关节世界坐标表 + 网格 step（或标定公式）
    判据 = 生物关节可视程度 + 沿肢体方向的落点（逐关节：是否落在解剖关节上；
           骨段长度比是否合理；布条不算轮廓）
    输出 = 逐关节证据 + PASS/FAIL 总裁定 + 修正坐标建议
→ FAIL：按证据修 → 回到「重截」
→ PASS：截图给用户 → **🚧 门 1：等用户确认标杆侧**
→ 用户确认后 `mirror`（方向已确认）→ 逐对校验 Δ=0 → 出图 → **🚧 门 2**
── Wrapper 阶段（门 2 通过后才允许）──────────────────────
⚠️ 第一步必须 unpin：圆柱只要被手动调过一次就带 manual 标记，
   autoFitCylinders() 会**跳过**它并返回 changed=0——**静默空操作，不报错**。
   E-01 实测：22 根全 manual 时 autoFit 一根不改，unwrappedVerts 仍
   2160/4209（51.3%）。以为「跑过 autoFit 了」是最容易踩的坑。
→ cylinders setOffset [0,0,0] × 全部（**先做这步再谈半径**，
   E-01 清零 offset 就把未包裹从 51.3% 砍到 28.0%）
→ 半径：用**密度峰值**（不用分位数）；或 unpin 后 autoFit 再手工修
   （公式 `r = clamp(0.35 × 骨长, 0.04, 0.22)`，`skin-proxy.ts`；
   僵尸/破损模型上常**偏小到不可用**：E-01 的 Hips 骨长 0.186 → r=0.065，
   包不住 19.8cm 半宽的骨盆）
→ 算**权属分布**查跨部位抢权重（不只是看未包裹数）
→ 出正/侧全貌图（`showCylinders:true, grid:true`；投影须含圆柱+markers）
→ **🚧 门 3：发给用户核对，确认后才继续**
→ compute_skin 直到未包裹数达到「该模型类型」的合理残留（破损模型不必为 0）
→ save → export_glb → pnpm run scene:gen && pnpm run scene:check
```

### 审核员提示词要点（可直接套）

> 你是独立视觉审核员，与调整者无关。给定：正/侧视截图文件路径、当前 27 关节
> 世界坐标表、像素↔世界标定公式。逐关节核对截图：该 joint 圆点是否落在模型
> 对应的**生物关节**上（肘点对肘弯、膝对膝关节、脊柱沿背部弧线、头链在颅腔内、
> 足链在靴内贴地）。破损布条/衣物不算肢体轮廓。每关节给图像证据（像素位置 +
> 偏差方向与量级），坐标存疑时用标定公式反算。
>
> **额外必查（否则会假 PASS）**：该 joint 是否落在肢体的**正确段**上——
> 肘有没有压在腋窝/腕的高度、腕有没有插进肘里。判据用**骨段长度比**
> （上臂:前臂应 ≈0.8–1.2；上臂比手还短 = 错）+ **沿肢体的单调顺序**
> （肩→肘→腕→指尖的高度必须严格递减，不许倒挂）。只答「在手臂上」不算通过。
>
> 最后给 PASS/FAIL 总裁定；FAIL 必须附每个不合格关节的修正坐标建议。
